# 전투 이미지 로딩 변경의 소유 범위 분리

## 상태와 범위

- 상태: Approved / 적용 후 검증 제한 있음, 2026-10-04. 요청자의 “기능은 그대로 동작해야한다. 진행.”으로 아래 분리 설계를 승인받았습니다. 초안 당시 기록은 유지하며 최신 상태는 마지막 적용 결과 절을 따릅니다.
- Workflow: `work standard`의 설계 초안. 성공 기준은 오버레이 변경의 실제 영향과 전투 의존 여부를 밝히고, 전투 폴더 중심의 후속 변경·검증 기준을 정하는 것입니다.
- 작업 폴더는 실제 경로인 `packages/pet-battle`입니다. 사용자가 지정한 외부 예외는 Client·Port와 창 크기 기본값 관련 변경입니다. 이번 이미지 문제에는 새 외부 예외가 필요하지 않습니다.
- 사용자 폴더 제한에 따라 명세를 `.harness/specs` 대신 이 폴더에 둡니다. 기존 MR 문서의 로컬 수정은 보존합니다.
- 비목표: 메인 오버레이 개선, DB·성장·선택 저장 변경, 공통 이미지 서비스 신설, UI 디자인 변경, 커밋·push.

## 확인한 원인

`origin/main...HEAD`에서 `packages/pet-overlay`의 차이는 다음 두 파일입니다.

1. `src/overlay/PetSprite.jsx`: 모션 프리로드 성공 콜백에 주석과 `if (!alive) return`을 추가했습니다.
2. `test/pet-sprite-loading.test.ts`: 이전 펫·진화 단계의 늦은 이미지 완료를 제어하는 회귀 테스트를 추가했습니다.

`PetSprite`는 effect마다 현재 pet/stage용 `imagesRef.current`를 비웁니다. 그러나 예전 effect에서 시작한 click/click2/attack 로딩은 계속 진행합니다. 예전 요청이 늦게 끝나면 같은 ref의 현재 객체에 예전 이미지를 넣을 수 있습니다. 이후 `play()`가 현재 단계의 메타와 예전 이미지를 함께 사용하면서 잘못된 펫·프레임을 그릴 수 있습니다. 추가한 조건은 cleanup된 effect의 결과 반영을 막습니다. idle 성공·실패 경로에는 원래 같은 보호가 있었습니다.

이는 모듈의 URL별 `imgCache`가 여러 기능의 데이터를 덮어쓰는 문제가 아닙니다. 오염 대상은 컴포넌트 인스턴스의 모션별 ref이며, 이미지 요청 자체를 취소하는 변경도 아닙니다.

## 실제 영향과 MR 표의 의미

실제 사용 경로는 `pet-overlay/src/App.jsx → overlay/Overlay.jsx → PetSprite.jsx`입니다. 따라서 전투를 열지 않아도 메인 오버레이에서 펫·진화 단계가 바뀔 때 이 수정이 적용됩니다. Client·Port 추가가 아니라 다른 기능의 렌더링 내부 구현 변경이므로 사용자가 허용한 외부 범위를 벗어납니다.

MR의 ‘영향 큼 ✓’는 문서 정의상 기존 다른 기능의 동작을 바꾼다는 표시입니다. 광범위한 장애나 여러 폴더의 실행 동작 변경이 확인됐다는 뜻은 아닙니다. 코드상 영향은 오버레이의 늦은 모션 로딩 처리로 한정되며, 선택 저장·XP·DB를 변경하는 경로는 없습니다. 버그 수정 자체는 타당하지만 전투 MR의 소유 범위와 검증 책임이 넓어집니다.

전투는 `PetSprite.jsx`를 import하지 않습니다. `@pet/battle`의 선언 의존성도 client/core/room이며 오버레이 렌더러 의존은 없습니다. 공통 PNG·메타 파일을 읽는 것과 오버레이 React 컴포넌트를 재사용하는 것은 다릅니다.

## 권고 설계

**오버레이 수정은 소유 기능의 별도 변경으로 분리하고, 전투는 현재 자체 이미지 경로를 유지합니다.** 전투에 오버레이 컴포넌트를 복사하거나 새 공유 로더를 추가할 필요는 없습니다.

| 전투 내부 위치                 | 현재 보호 방식                                               | 설계 기준                                          |
| ------------------------------ | ------------------------------------------------------------ | -------------------------------------------------- |
| `src/ui/battle-images.ts`      | URL별 프리로드 완료는 캐시에만 저장하고 표시 DOM을 쓰지 않음 | 늦은 준비 성공·실패가 현재 표시를 바꾸지 않음      |
| `src/ui/battle-overlay.ts`     | 현재 scene으로 표시 src를 정하고 프리로드는 별도 실행        | 현재 펫·진화 단계·모션이 표시의 원천               |
| `src/ui/pet-grounding.ts`      | 결과 반영 시 `this.source === asset` 확인                    | 이전 에셋 분석이 현재 발 위치를 바꾸지 않음        |
| `src/ui/ambient-logs.ts`       | 얼굴 노드 즉시 교체, 현재 자식일 때만 load 결과 표시         | 제거된 얼굴 이미지가 현재 말풍선에 재등장하지 않음 |
| `src/ui/mole-sprite.ts`        | 표시 이미지의 완료 여부와 `currentSrc === src` 검사          | 단계 전환 중 이전 두더지 팔을 합성하지 않음        |
| `src/adapters/file-sprites.ts` | 주입받은 경로에서 종·단계별 메타/URL 조회                    | 공통 원본을 수정하지 않고 기존 Port로 제공         |

새 Port는 필요하지 않습니다. 브라우저 이미지 요청의 수명은 전투 렌더러 책임이며 데이터 소유자의 조회 계약에 넣지 않습니다. 테스트에서 실제 누락이 재현되는 경우에만 전투 내부의 요청 세대·에셋 식별 검사를 보완합니다. URL 재사용은 동일 콘텐츠라는 현재 전제를 유지하며 에셋 hot-reload·동일 URL 내용 교체는 이번 범위에 넣지 않습니다.

## 대안과 선택 이유

- 현재 오버레이 수정을 유지: 수정량은 가장 작지만 외부 렌더러 동작과 검증 책임이 전투 MR에 남습니다.
- 공통 로더·새 Port로 통합: React ref와 전투 DOM의 서로 다른 수명을 결합하고 소비자 변경을 늘립니다. 이번 문제에 비해 범위가 큽니다.
- **소유 기능별 분리(권고)**: 전투 보호는 이미 내부에 있으며, 오버레이의 독립 버그 수정은 해당 소유자가 별도 반영할 수 있습니다.

## 후속 적용 순서와 제약

1. 이 초안에 따라 전투 내부 회귀 조건을 보강할 필요가 있는지 결정합니다. 단순 코드 복제나 이미 통과하는 테스트 복제는 하지 않습니다.
2. 오버레이 담당 변경으로 기존 한 줄 수정과 회귀 테스트의 근거를 보존합니다. 별도 반영 전 전투에서 제외하면 main의 기존 이미지 경합은 남는다는 점을 명시합니다.
3. 전투 MR에서 오버레이 두 파일의 순변경을 제외합니다. **이 단계는 외부 파일을 실제 수정해야 하므로 현재 폴더 제한 아래에서는 실행하지 않습니다.** 외부 수정 없이 전투 폴더만 고쳐서는 이미 존재하는 오버레이 diff를 없앨 수 없습니다. 담당자가 별도 정리하거나 해당 두 파일의 정리만 명시적으로 허용된 뒤 진행합니다. baseline과 로컬 변경을 재확인하고 다른 작업을 덮어쓰지 않습니다.
4. 실제 제외 후에만 MR §2를 갱신합니다. 아직 남은 변경을 문서에서 먼저 제거하지 않습니다. 다른 외부 Client·Port·창 변경은 별도 범위 감사 대상이며 이번 조사로 전부 허용됐다고 간주하지 않습니다.

## 수용 기준과 검증 계획

- AC1: 전투가 오버레이 React 구현을 import하지 않습니다. import 검색과 패키지 의존성으로 확인합니다.
- AC2: A→B 선택, stage1→stage2, 선택 해제, STOP 중 이전 준비가 늦게 성공·실패해도 현재 전투 이미지·발 위치가 바뀌지 않습니다. 기존 battle-images/pet-grounding 테스트를 활용하고 빠진 조건만 추가합니다.
- AC3: 전투 브라우저에서 실제 이미지 완료 순서를 뒤집어 본체·얼굴·두더지 팔에 이전 에셋이 다시 표시되지 않음을 확인합니다. 현재 단위 테스트만으로 이 조건을 통과 처리하지 않습니다.
- AC4: 분리 구현 후 `git diff origin/main...HEAD -- packages/pet-overlay`가 비어야 합니다. 커밋 전에는 working tree와 index 차이도 함께 확인합니다. main에 소유자 수정이 먼저 들어갔다면 해당 최신 baseline을 기준으로 비교합니다.
- AC5: 이번 구현으로 새로 바꾼 실행 코드·테스트는 전투 내부에 한정합니다. 오버레이 정리 2개 파일은 별도 승인/소유자 작업으로 구분합니다. API·DB·저장 형식 변경은 없습니다.
- 구현 후 공식 게이트: `bash .harness/scripts/verify-electron.sh` (format:check → typecheck → npm test). 전투 브라우저 회귀는 실제 실행 결과를 별도로 기록합니다.

원본 오버레이 수정은 별도 담당자가 검토한 뒤 저장소 루트에서 `git apply packages/pet-battle/docs/overlay-sprite-fix.patch`로 반영할 수 있습니다. 이는 자동 실행 지시가 아니라 인계 방법입니다. 원복된 오버레이에서는 main의 기존 경합 가능성이 남으며, 전투 브랜치에서 오버레이 버그까지 해결된 상태를 유지했다고 표현하지 않습니다.
