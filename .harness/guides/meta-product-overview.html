Three areas

세 화면이 맡는 역할

각 화면은 한 가지 질문에 답합니다. 실제 구현과 테스트는 상세 기획서의 요구사항 ID를 기준으로 합니다.

01

정보 · 지금까지 무엇을 했나?

설치 이후의 활동과 현재 펫 상태를 한눈에 확인합니다.

  • 프로필과 오늘·누적 핵심 수치
  • 최근 12주 사용량 잔디
  • 도구별 사용량과 전체 모델 보기
  • 뽑기·합성·전투·성장 실적
02

설정 · 무엇을 수집하고 보여줄까?

세 CLI 수집 상태와 데스크톱 오버레이 동작을 제어합니다.

  • 기본 경로 자동 감지와 소스별 토글
  • 앱 시작·1분 주기·수동 재스캔
  • 오버레이 표시와 펫 크기
  • 말풍선 알림과 자동 실행
03

업적 · 무엇을 함께 축하할까?

과제를 강요하지 않고 이미 달성한 행동을 사후에 발견합니다.

  • 일반·단계형·히든 업적 22개
  • 현재 진행률과 전체 완료율
  • 코인·칭호·트로피 보상
  • 업데이트 후 설치 이후 사실 소급 판정

Local data flow

로컬 기록이 펫의 반응이 되기까지

서버 계정이나 사용자 API 키 없이, 번들된 고정 버전 수집 경계와 멱등 처리를 사용합니다.

1

자동 감지

Claude Code, Codex, Gemini CLI의 기본 위치를 찾습니다.

2

기준점과 집계

첫 정상 스캔은 기준점만 저장하고 이후 증가분부터 반영합니다.

3

기록과 보상

관측 통계와 보상 대상 토큰을 분리해 각 도메인에 전달합니다.

4

판정과 말풍선

업적을 한 번만 해제하고 현재 펫이 결과를 알려줍니다.

설치 전 기록은 0첫 정상 스캔의 기존 로그는 통계·코인·업적에 들어가지 않습니다.
비활성 기간은 제외소스를 다시 켤 때 현재 값을 새 기준점으로 잡습니다.
두 토큰을 분리정보는 관측 토큰, 코인은 재화 도메인의 보상 대상 토큰을 사용합니다.
활동 분은 중복 없이같은 로컬 분에 여러 도구를 써도 활동 시간은 1분입니다.
원천 감소에도 유지로그 삭제나 재기준화가 이미 쌓인 통계와 진행률을 깎지 않습니다.
로컬에서만 동작계정·서버 저장·클라우드 동기화 없이 macOS와 Windows를 지원합니다.

Achievement system

22개의 업적, 한 번뿐인 보상

수집·성장·전투·사용량을 고르게 다루고, 두 개의 히든 업적은 달성 전까지 내용을 공개하지 않습니다.

22

전체 업적 수

수집7
성장5
전투4
사용량4
히든2

보상과 표시 원칙

코인

업적별 고정 보상을 동일한 멱등 키로 한 번만 지급합니다.

칭호

첫 칭호만 빈 장착 슬롯에 자동 장착하고 이후에는 사용자가 고릅니다.

트로피

첫 만남만 빈자리에 자동 배치하며 나머지는 보관함으로 갑니다.

알림은 운영체제 토스트가 아니라 펫의 말풍선입니다. 여러 업적을 한 번에 달성하면 “N개 업적을 달성했어!” 한 번으로 묶고, 클릭하면 업적 화면을 엽니다.

MVP boundary

이번에 만드는 것과 만들지 않는 것

작은 데스크톱 펫이라는 제품 형태를 지키며, 운영 복잡도를 키우는 기능은 MVP에서 분리합니다.

포함

  • 정보·설정·업적 패널과 트레이 진입점
  • 세 CLI의 기본 위치 자동 감지
  • 최근 12주 사용량과 전체 모델 조회
  • 업적 판정·진행률·보상·말풍선 알림
  • 설치 이후 사실을 이용한 신규 업적 소급 판정
  • macOS·Windows 동작 검증

제외

  • 계정·서버 저장·클라우드 동기화
  • 사용자 지정 수집 경로와 USD 비용 표시
  • 백업·복원·초기화와 원본 레코드 미리보기
  • 클릭 통과·집중 모드·조용한 시간대
  • 운영체제 알림 센터
  • 후원과 게임 보상의 연결

Team handoff

구현에서는 요구사항 ID로 대화합니다.

화면과 수집은 meta가 소유하고, 펫·뽑기·전투 도메인은 승인된 이벤트를 발행합니다. 구현 계획과 테스트는 INFO, SET, COLLECT, ACH, META 요구사항 ID를 참조합니다.
