기능 간 계약 규약

각자 자기 feature 패키지 안은 자유롭게 짭니다. 다른 기능의 데이터를 쓸 때, 그리고 내 데이터를 남에게 내줄 때만 이 규약을 따릅니다.

사슬 하나

사용 로직 → Port → Port 구현체 → Repository → DB 영속성 레이어

데이터를 가진 기능이 Port 를 공표합니다. 테이블을 소유한 기능이 그 테이블을 읽고 쓰는 인터페이스를 내놓고, 구현체와 Repository 까지 만듭니다. 쓰는 쪽은 인터페이스 타입을 import 하고, 앱이 넣어 주는 인스턴스를 받아 호출합니다.

소유자는 자기 테이블과 불변 조건, 무엇을 바꿔도 되는지를 압니다. 쓰는 쪽이 남의 데이터에 대한 인터페이스를 따로 선언하면 그 셋을 짐작하게 되고, 두 소비자가 다르게 짐작하는 순간 테이블 하나에 계약이 둘이 됩니다.

각 고리가 사는 곳

고리위치누가
Port 인터페이스 · 데이터 타입 packages/pet-client/ 같은 소유자의 계약 패키지 소유자
구현체 apps/desktop/src/main/clients/ — DB 에 닿는 곳은 앱뿐 소유자
Repository apps/desktop/src/main/persistence/repositories/ 소유자
조립 apps/desktop/src/main/main.ts 에서 한 번 만들어 나눠 줌 소유자
호출 쓰는 쪽 패키지 — 계약 패키지를 타입으로만 의존 쓰는 쪽

쓰는 쪽 패키지는 남의 구현체도, DB 드라이버도 import 하지 않습니다. 계약 패키지에는 타입만 있어서 import 해도 DB 연결이 생기지 않습니다.

규칙 일곱

  1. 소유 도메인 하나에 Port 하나. 그 도메인이 테이블 여러 개에 걸쳐 있어도 쓰는 쪽에게는 하나의 Port 로 내놓습니다. 펫이 pet_species 와 owned_pets 를 PetClient 하나로 내놓은 것처럼요.
  2. 쓰는 쪽은 요구사항을, 소유자는 모양을. 무엇을 읽는지, 어디에 보여주는지, 얼마나 자주인지를 소유자에게 가져갑니다. 메서드로 만드는 건 소유자입니다.
  3. 구현체에는 규칙이 없습니다. 행을 공표된 타입으로 바꾸는 일만 합니다. 데이터베이스가 없어도 성립하는 계산이라면 도메인 패키지 몫입니다.
  4. 테이블을 만들고 고치는 것은 소유한 기능만. 없는 컬럼이 필요하면 소유자에게 요청합니다. 남의 migration scope 에 끼워 넣으면 소유자의 다음 migration 과 부딪힙니다.
  5. 소유자의 Port 없이 남의 테이블을 조회하지 않습니다. 호출부에 날 쿼리를 쓰면 그 스키마가 코드 전체에 퍼지고, 소유자는 찾을 수도 없는 코드를 깨뜨리지 않고는 스키마를 못 바꿉니다.
  6. 읽기 실패는 던집니다. null · [] · 0 은 진짜 빈 결과입니다 — 고른 펫이 없음, 펫이 없음, 셀 게 없음. “읽지 못함” 대신 쓰지 않습니다. 실패에 0 을 받은 쪽은 틀린 값을 그리면서 알아챌 방법도 없습니다.
  7. 그 순간에만 존재하는 사실은 소유자가 저장해야 합니다. 현재 상태만 담은 테이블은 “역대 최고 연승이 10이었나”나 “그때 부모가 둘 다 COMMON이었나”에 답할 수 없습니다.

일곱 번째가 가장 자주 걸립니다. 예를 들어 업적 무패(10연승)와 연금술의 기적(부모 둘 다 COMMON → EPIC)은 현재 상태 조회로 판정할 수 없습니다. 쓰는 쪽이 계산으로 해결할 수 있는 문제가 아니라, 소유자에게 컬럼을 요청해야 하는 문제입니다.

저장

petto.sqlite 하나, 기능마다 migration scope 하나, repository 하나입니다. scope · version · 등록 · 수명 절차는 apps/desktop/src/main/persistence/README.md 에 있습니다. 테이블을 추가하기 전에 읽으세요.

예시 — 펫

펫 도메인이 기준입니다. 소유자가 전부 공표했고, meta 는 호출만 합니다.

1. Port — 소유자. 타입만, 드라이버 없음

// packages/pet-client/src/index.ts
export interface PetClient {
  getActivePet(): OwnedPet | null;   // null = 아직 고른 펫 없음. 실패가 아니다
  countOwnedSpecies(): number;
  // …
}

2. 구현체 — 소유자. 규칙 없이 위임만

// apps/desktop/src/main/clients/sqlite-pet-client.ts
export class SqlitePetClient implements PetClient {
  getActivePet(): OwnedPet | null {
    return this.#repository.getActivePet();
  }
}

3. 조립 — 공유 DB 위에 한 번

// apps/desktop/src/main/main.ts
const pets: PetClient = new SqlitePetClient(new PetRepository(appDatabase));

4. 호출 — 쓰는 쪽. 타입만 import

// packages/pet-meta
import type { PetClient } from '@pet/client';

const active = pets.getActivePet();

연결 절차와 메서드별 보장은 소유자의 인계 문서 docs/pet-client-handoff.md 에 있습니다.

이 문서는 사람이 읽는 버전입니다. 에이전트가 따르는 정본은 .harness/rules/feature-contracts.md 이며, 규칙이 바뀌면 그쪽을 먼저 고칩니다.
