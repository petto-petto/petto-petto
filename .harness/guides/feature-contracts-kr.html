팀 규약

기능 간 계약 규약

각자 자기 feature 패키지 안은 자유롭게 짭니다. 다른 기능의 데이터를 쓸 때만 이 규약을 따릅니다.

사슬 하나

사용 로직 → Port(테이블 단위) → Port 구현체 → DB 영속성 레이어

사용하는 사람이 이 사슬을 전부 만듭니다. 내 화면에 남의 테이블 값이 필요하면, 내가 Port를 쓰고 내가 구현체를 쓰고 내가 DB를 부릅니다.

그래서 아무도 서로를 기다리지 않습니다. 소유자는 아직 보이지도 않는 호출자를 위해 API를 설계하지 않아도 되고, 호출자는 그 API가 나오길 기다리지 않아도 됩니다.

각 고리가 사는 곳

고리위치왜 거기인가
Port 인터페이스 packages/<내 기능>/src/ports/ 테이블이 할 수 있는 전부가 아니라 내가 필요한 것을 적기 때문
구현체 apps/desktop/src/main/ DB에 닿는 곳은 앱뿐
Repository apps/desktop/src/main/persistence/repositories/ SQL을 기능마다 한 곳에

내 패키지는 다른 feature 패키지도, DB 드라이버도 import 하지 않습니다. 인터페이스만 선언하고, 그걸 만족하는 구현체는 앱이 넣어 줍니다. 덕분에 내 규칙은 데이터베이스 없이 테스트됩니다.

규칙 여섯

  1. 테이블 하나에 Port 하나. 메서드는 내가 실제로 읽고 쓰는 것만 둡니다. “온 김에” 넣은 메서드는 아무도 확인하지 않는 약속입니다.
  2. 구현체에는 규칙이 없습니다. 행을 내 호출부가 원하는 모양으로 바꾸는 일만 합니다. 데이터베이스가 없어도 성립하는 계산이라면 도메인 패키지 몫입니다.
  3. 테이블을 만들고 고치는 것은 소유한 기능만. 없는 컬럼이 필요하면 소유자에게 요청합니다. 남의 migration scope 에 끼워 넣으면 소유자의 다음 migration 과 부딪힙니다.
  4. Port 없이 남의 테이블을 조회하지 않습니다. 호출부에 날 쿼리를 쓰면 그 테이블의 스키마가 코드 전체에 퍼지고, 소유자는 자기가 찾을 수도 없는 코드를 깨뜨리지 않고는 스키마를 못 바꿉니다.
  5. Port 는 실패하면 던집니다. null 이나 0 을 돌려주지 않습니다. 0 을 받은 쪽은 “행이 없음”과 “읽지 못함”을 구분할 수 없습니다.
  6. 그 순간에만 존재하는 사실은 소유자가 저장해야 합니다. 현재 상태만 담은 테이블은 “역대 최고 연승이 10이었나”나 “그때 부모가 둘 다 COMMON이었나”에 답할 수 없습니다.

여섯 번째가 가장 자주 걸립니다. 예를 들어 업적 무패(10연승)와 연금술의 기적(부모 둘 다 COMMON → EPIC)은 현재 상태 조회로 판정할 수 없습니다. 이건 소비자가 계산으로 해결할 수 있는 문제가 아니라, 소유자에게 컬럼을 요청해야 하는 문제입니다.

저장

petto.sqlite 하나, 기능마다 migration scope 하나, repository 하나입니다. scope · version · 등록 · 수명 절차는 apps/desktop/src/main/persistence/README.md 에 있습니다. 테이블을 추가하기 전에 읽으세요.

예시 — meta 가 코인 잔액을 보여준다

잔액은 meta 것이 아닙니다. 사슬 전체를 소비자인 meta 가 만들었습니다.

1. Port — 드라이버도 SQL도 없다

// packages/pet-meta/src/ports/
export interface CurrencyPort {
  balance(): Coin;
  grantOnce(rewardKey: string, amount: Coin, reason: string): GrantOutcome;
}

2. Repository — SQL 만, 규칙 없음

// apps/desktop/src/main/persistence/repositories/
recordGrant(dedupeKey, amount, reason, at): boolean {
  const result = this.#database
    .prepare('INSERT OR IGNORE INTO currency_ledger (dedupe_key, delta, reason, occurred_at) VALUES (?, ?, ?, ?)')
    .run(dedupeKey, amount, reason, at);
  return result.changes > 0;
}

3. 구현체 — 행을 모양으로, 실패를 오류로

// apps/desktop/src/main/
export class SqliteCurrencyPort implements CurrencyPort {
  balance(): Coin {
    try {
      return this.#repository.balance();
    } catch (error) {
      throw new PortError(`잔액을 불러오지 못했어요 (${String(error)})`);
    }
  }
}

이 예시에서 장식이 아니라 계약인 것 둘이 있습니다.

잔액을 컬럼으로 저장하지 않고 SUM(delta) 로 구합니다. 반드시 일치해야 하는 두 숫자는 언젠가 어긋나고, 그 순간 어느 쪽도 믿을 수 없게 됩니다.

멱등성은 UNIQUE 키와 INSERT OR IGNORE 에 맡깁니다. 조회한 뒤 삽입하면 두 문장 사이에 끼어든 두 번째 삽입을 막지 못합니다.

이 문서는 사람이 읽는 버전입니다. 에이전트가 따르는 정본은 .harness/rules/feature-contracts.md 이며, 규칙이 바뀌면 그쪽을 먼저 고칩니다.
