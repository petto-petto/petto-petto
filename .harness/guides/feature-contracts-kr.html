팀 규약

기능 간 계약 규약

각자 자기 feature 패키지 안은 자유롭게 짭니다. 다른 도메인의 데이터를 읽거나 쓸 때만 이 규약을 따릅니다.

사슬 하나

사용 로직 → Port → Port 구현체 → Repository → DB 영속성 레이어

작업하는 쪽이 Port 를 선언합니다. 내 기능이 다른 도메인의 데이터를 써야 하면, 내가 읽고 쓸 것의 인터페이스를 선언하고 구현체와 Repository 까지 만듭니다. petto.sqlite 에 이미 선언된 테이블 위에 만듭니다. 그 도메인을 만든 사람에게 요청하고 기다리지 않습니다.

선언하기 전에 재사용합니다. 그 도메인의 Port 가 이미 있으면 타입을 import 해서 그대로 씁니다. 지금 있는 것은 packages/pet-client/ 의 PetClient 와 TokenClient 입니다. 메서드 하나만 필요하면 Pick 으로 좁히고, 없는 메서드는 거기에 더합니다. 같은 테이블 위에 인터페이스를 하나 더 만들면 테이블 하나에 계약이 둘이 되고, 한쪽이 바뀌는 순간 어긋납니다.

각 고리가 사는 곳

고리위치
Port 인터페이스 · 데이터 타입 둘 이상의 기능이 쓰면 packages/pet-client/, 아니면 쓰는 패키지의 src/ports/
구현체 apps/desktop/src/main/clients/, 한 기능이 선언한 Port 라면 main.ts 옆의 어댑터 — DB 에 닿는 곳은 앱뿐
Repository apps/desktop/src/main/persistence/repositories/
조립 apps/desktop/src/main/main.ts 에서 한 번 만들어 나눠 줌
호출 쓰는 쪽 패키지 — Port 를 타입으로만 의존

feature 패키지는 다른 feature 패키지도, DB 드라이버도 import 하지 않습니다. Port 에는 타입만 있어서 import 해도 DB 연결이 생기지 않습니다.

규칙 일곱

  1. 도메인 하나에 Port 하나. 호출하는 쪽이나 테이블이 아니라 데이터가 속한 도메인(펫 · 토큰 · 뽑기)으로 나눕니다. 그 도메인이 테이블 여러 개에 걸쳐 있어도 Port 는 하나입니다.
  2. DB 에 선언된 것을 읽습니다. Port 는 실제로 있는 테이블과 컬럼 위에 만듭니다. 한 도메인의 값을 다른 도메인의 테이블에서 추정하지 않습니다. 상관없는 원장에서 세어 낸 횟수는 그 원장의 키나 금액이 바뀌는 순간 틀립니다.
  3. 구현체에는 규칙이 없습니다. 행을 Port 의 타입으로 바꾸는 일만 합니다. 데이터베이스가 없어도 성립하는 계산이라면 도메인 패키지 몫입니다.
  4. 테이블을 만들고 고치는 것은 소유한 기능만. 남의 테이블 위에 Port 를 만들었다고 그 테이블이 내 것이 되지는 않습니다. 남의 migration scope 에 컬럼을 끼워 넣으면 그쪽의 다음 migration 과 부딪힙니다.
  5. 호출부에서 테이블을 조회하지 않습니다. Port 밖에 날 쿼리를 쓰면 그 스키마가 코드 전체에 퍼지고, 찾을 수도 없는 코드를 깨뜨리지 않고는 테이블을 못 바꿉니다.
  6. 읽기 실패는 던집니다. null · [] · 0 은 진짜 빈 결과입니다 — 고른 펫이 없음, 펫이 없음, 셀 게 없음. “읽지 못함” 대신 쓰지 않습니다. 실패에 0 을 받은 쪽은 틀린 값을 그리면서 알아챌 방법도 없습니다.
  7. 아직 테이블에 없는 것은 Mock 으로 둡니다. 그 도메인이 아직 개발 중이라 테이블이나 컬럼이 없으면, 필요한 Port 를 선언하고 Mock 구현을 넣습니다. 그 순간에만 존재하는 사실도 없는 데이터입니다 — 현재 상태만 담은 테이블은 “역대 최고 연승이 10이었나”에 답할 수 없습니다. 테이블이 생기면 Mock 을 SQLite 구현으로 바꾸고, 그때 바뀌는 곳은 조립뿐입니다. Mock 의 숫자를 진짜로 읽지 않도록 이름에 드러냅니다.

일곱 번째가 가장 자주 걸립니다. 뽑기 횟수, 전투 승수와 연승, 합성 결과는 아직 저장하는 테이블이 없습니다. 담당자에게 컬럼을 요청하고 멈추는 것이 아니라 Mock 으로 두고 계속 진행합니다.

저장

petto.sqlite 하나, 기능마다 migration scope 하나, repository 하나입니다. scope · version · 등록 · 수명 절차는 apps/desktop/src/main/persistence/README.md 에 있습니다. 테이블을 추가하기 전에 읽으세요.

예시 — meta 가 쓰는 세 도메인

meta 는 세 도메인의 데이터를 씁니다. 하나씩이 규칙의 서로 다른 갈래입니다.

1. 펫 — Port 가 이미 있으니 재사용

// packages/pet-meta
import type { PetClient } from '@pet/client';

const active = pets.getActivePet();   // null = 아직 고른 펫 없음. 실패가 아니다

2. 토큰 — Port 가 있으니 부르는 메서드만 좁혀 쓰고, 없는 메서드는 거기에 더함

// packages/pet-meta/src/ports/index.ts — 토큰 테이블 위에 인터페이스를 새로 만들지 않는다
import type { TokenClient } from '@pet/client';

export type TokenPort = Pick<TokenClient, 'recordUsage' | 'grantOnce' | 'balance' | 'earnedSince'>;
// packages/pet-client/src/token.ts — meta 가 오늘 획득량이 필요해서 여기에 더했다
export interface TokenClient {
  earnedSince(since: string): number;
  // …
}
// apps/desktop/src/main/main.ts — 뽑기 · 합성이 차감하는 것과 같은 인스턴스
const tokens: TokenClient = new SqliteTokenClient(new TokenRepository(database), currencyRepository);

3. 뽑기 — 뽑기 횟수를 담은 테이블이 아직 없으니 선언하고 Mock

// packages/pet-meta/src/ports/index.ts — 필요한 쪽이 선언한다
export interface GachaPort {
  drawCount(): number;
  // …
}
// packages/pet-meta/src/testing/fakes.ts — 뽑기가 횟수를 저장할 때까지 대신한다
export class StubGacha implements GachaPort { /* … */ }

PetClient 메서드별 보장은 docs/pet-client-handoff.md 에 있습니다.

이 문서는 사람이 읽는 버전입니다. 에이전트가 따르는 정본은 .harness/rules/feature-contracts.md 이며, 규칙이 바뀌면 그쪽을 먼저 고칩니다.
