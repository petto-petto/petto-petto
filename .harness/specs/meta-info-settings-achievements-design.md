## 1. 목표와 제품 원칙

정보는 사용자가 설치 이후 무엇을 사용하고 이루었는지 보여주는 현황판이다. 설정은 세 AI CLI의 수집 상태와 데스크톱 오버레이 동작을 제어한다. 업적은 과제를 강요하지 않고 이미 달성한 행동을 사후에 축하한다.

공통 원칙은 다음과 같다.

1. 계정, 서버, 동기화, 사용자 API 키 없이 로컬에서 동작한다.
2. 사용량은 Claude Code, Codex, Gemini CLI의 로컬 기록을 `ccusage` 경계로 집계한다.
3. 설치 전 기록은 게임 진행으로 인정하지 않는다.
4. 사용 통계와 코인 환산 입력을 분리해 사실 표시와 게임 경제를 결합하지 않는다.
5. 업적은 다른 도메인의 내부 저장소를 직접 읽지 않고 이벤트와 승인된 스냅샷으로 판정한다.
6. 작은 오버레이 제품이라는 전제를 지켜 패널은 한 번에 하나만 표시한다.
7. 사용자에게 보이는 용어는 `업적`, 코드·이벤트·데이터의 영문 식별자는 `achievement`로 통일한다.

## 4. 정보 구조와 공통 흐름

### 4.1 진입점

펫 우클릭 메뉴는 기존 게임 기능과 함께 `정보`, `업적`, `설정`을 제공한다. 세 메뉴 중 하나를 열면 이미 열려 있던 메타 패널은 닫히고 선택한 패널만 열린다.

트레이 메뉴는 다음 항목을 제공한다.

1. 오버레이 표시 또는 숨기기
2. 설정 열기
3. 앱 종료

오버레이를 숨겨도 앱과 수집기는 계속 실행된다. 숨긴 상태에서 설정을 열면 펫 위치에 의존하지 않는 독립 패널을 활성 모니터 중앙에 표시한다.

### 4.2 패널 규약

| 항목 | 규칙 |
|---|---|
| 기본 크기 | 400 × 462 논리 픽셀 |
| 동시 표시 | 한 번에 한 패널 |
| 기본 위치 | 펫이 화면 오른쪽이면 왼쪽, 왼쪽이면 오른쪽 |
| 대체 위치 | 좌우 공간이 모두 부족하면 펫 위쪽 |
| 경계 보정 | 펫이 있는 모니터의 작업 영역 안으로 이동 |
| 내부 스크롤 | 허용 |
| 펫 크기 설정 | 패널에는 적용하지 않음 |
| 항상 맨 위 | 사용자 설정 없이 고정 동작 |

정보와 설정은 패널을 다시 열 때 기본 서브탭으로 진입한다. 정보의 기본은 `요약`, 설정의 기본은 `수집`이다. 업적은 마지막 카테고리 필터를 현재 실행 중에만 기억하고 앱을 다시 시작하면 `전체`로 돌아간다.

### 4.3 최초 실행

1. 세 수집 소스의 기본 위치를 자동 감지한다.
2. 소스별 첫 정상 스캔 결과를 진행량으로 적립하지 않고 기준점으로 저장한다.
3. 하나 이상의 소스가 발견되면 오버레이를 정상 표시한다.
4. 세 소스가 모두 발견되지 않으면 설정의 `수집` 탭을 자동으로 연다.
5. 조련사 이름을 익명 한글 조합으로 한 번 생성해 저장한다.

최초 실행 자동 안내는 수집 소스가 0개일 때만 나타난다. 이미 기준점이 있는 재실행과 단순 수집 오류는 최초 실행으로 취급하지 않는다.

## 5. 정보 화면

정보 화면은 `요약`, `사용량`, `실적` 세 서브탭으로 구성한다.

### 5.1 요약

요약은 스크롤 없이 핵심 상태를 확인하는 화면이다.

| 블록 | 표시 내용 | 원천 |
|---|---|---|
| 프로필 | 현재 오버레이 펫, 조련사 이름, 장착 칭호, `이 기기` 표기 | 프로필·Pet |
| 누적 3수치 | 설치 이후 관측 토큰, 보유 펫 수, 도감 `보유/전체` | 사용량·Pet·도감 |
| 오늘 3수치 | 오늘 관측 토큰, 오늘 획득 코인, 함께한 시간 | 사용량·재화 원장 |

`오늘 획득 코인`은 로컬 날짜 기준 오늘 발생한 양수 재화 원장 항목의 합이다. 획득 원인이 토큰, 업적, 성장 중 무엇이든 포함하고 소비는 포함하지 않는다.

`함께한 시간`은 8.6의 활동 분을 누적한 값이다. 60분 미만은 분, 그 이상은 시간과 분으로 표시한다.

#### 조련사 이름

- 첫 실행에 `형용사 + 동물` 형태의 안전한 한글 조합을 무작위 생성한다.
- 예시는 `까만 코뿔소`, `졸린 수달`, `용감한 참새`다.
- OS 사용자 이름, MAC 주소, 계정 식별자는 사용하지 않는다.
- 생성 결과는 저장하며 실행할 때마다 바꾸지 않는다.
- 사용자는 이름을 자유롭게 수정하거나 `다시 만들기`로 새 조합을 받을 수 있다.
- 저장값은 공백을 제거한 1~20개의 사용자 표시 문자여야 하며 줄바꿈과 제어 문자는 허용하지 않는다.

대표 펫은 별도 설정값이 아니라 현재 데스크톱 오버레이에 표시 중인 펫이다.

### 5.2 사용량

#### 기간 필터

| 필터 | 범위 |
|---|---|
| 오늘 | 현재 로컬 날짜 00:00부터 현재까지 |
| 주 | 오늘을 포함한 최근 7개 로컬 날짜 |
| 달 | 오늘을 포함한 최근 30개 로컬 날짜 |
| 전체 | 해당 기기의 최초 수집 기준점 이후 |

필터는 도구별·모델별 집계에 적용한다. 사용량 잔디에는 적용하지 않는다.

#### 최근 12주 잔디

- 오늘이 포함된 주까지 최근 12주의 일별 관측 토큰을 표시한다.
- 0은 빈 칸, 사용량이 있는 날짜는 비어 있지 않은 날짜들의 분포를 기준으로 네 단계 농도로 표시한다.
- 마우스를 올리거나 키보드로 초점을 이동하면 날짜와 관측 토큰을 보여준다.
- 제목 옆에 `최근 12주`를 명시해 기간 필터와 혼동하지 않게 한다.

#### 도구별 분해

Claude Code, Codex, Gemini CLI별 관측 토큰과 선택 기간 내 비율을 표시한다. 비활성화된 소스도 과거에 집계한 값이 있으면 목록에 남고 `수집 중지` 상태를 함께 표시한다.

#### 모델별 분해

- 행 식별 기준은 `(도구, 원본 모델명)`이다.
- 선택 기간의 관측 토큰 내림차순으로 정렬한다.
- 기본 화면은 상위 5개를 표시한다.
- `전체 N개 모델 보기`를 누르면 해당 기간에 기록된 모든 모델을 펼친다.
- 각 행은 도구 배지, 원본 모델명, 관측 토큰, 비율을 표시한다.
- 알 수 없는 새 모델도 별도 매핑 없이 원본 이름으로 표시한다.
- 목록을 접으면 다시 상위 5개만 표시한다.

USD 비용은 어느 기간과 상세 화면에서도 표시하지 않는다.

## 6. 설정 화면

설정 화면은 `수집`, `화면`, `알림`, `기타` 네 서브탭으로 구성한다.

### 6.1 수집

Claude Code, Codex, Gemini CLI를 항상 같은 순서로 표시한다. 각 카드는 다음 정보를 가진다.

- 도구 이름과 아이콘
- 감지 상태
- 기본 로그 위치
- 마지막 정상 집계 시각
- `재스캔` 버튼
- 도구별 수집 토글
- 필요한 경우 짧은 오류 원인

#### 카드 상태

| 내부 상태 | 사용자 표시 | 동작 |
|---|---|---|
| `connected` | 수집 중 | 1분 주기 집계 대상 |
| `not_found` | 기록을 찾을 수 없음 | 기본 위치 표시, 재스캔 가능 |
| `paused` | 수집 중지 | 기존 통계 유지, 새 기록 제외 |
| `scanning` | 확인 중 | 중복 재스캔 방지 |
| `error` | 집계 오류 | 마지막 정상 데이터 유지, 재시도 가능 |

자동 감지된 도구는 기본 활성화한다. 발견되지 않은 도구가 나중에 기본 위치에서 감지되면 활성화하고 그 시점에 최초 기준점을 만든다.

도구를 끄면 현재 시각을 비활성 시작점으로 기록한다. 다시 켜면 재활성 시각을 새 기준점으로 만들며 비활성 기간의 기록을 소급하지 않는다. 이미 집계한 과거 데이터는 삭제하거나 합계에서 빼지 않는다.

사용자 지정 경로 입력은 제공하지 않는다.

### 6.2 화면

| 설정 | 초기값 | 규칙 |
|---|---|---|
| 오버레이 표시 | 켜짐 | 끄면 트레이만 유지, 재실행 후에도 숨김 유지 |
| 펫 크기 | 보통 | 작게·보통·크게 중 하나, 패널 크기에는 영향 없음 |
| 부팅 시 자동 실행 | 꺼짐 | 사용자가 켤 때만 OS 시작 항목 등록 |

클릭 통과와 집중 모드는 제공하지 않는다. 항상 맨 위는 설정 없이 고정한다.

### 6.3 알림

| 알림 | 초기값 | 클릭 결과 |
|---|---|---|
| 레벨업 | 켜짐 | 해당 펫 화면 열기 |
| 업적 달성 | 켜짐 | 업적 화면 열기 |
| 뽑기 가능 | 꺼짐 | 뽑기 화면 열기 |

알림은 현재 오버레이 펫을 가리키는 말풍선과 사건별 펫 표정·짧은 애니메이션으로 표시한다. 운영체제 알림 센터는 사용하지 않는다.

- 업적 한 개는 업적명과 핵심 보상을 표시한다.
- 업적 두 개 이상을 같은 판정 묶음에서 달성하면 `N개 업적을 달성했어!` 한 번만 표시한다.
- 레벨업은 펫 이름과 이전·현재 레벨을 표시한다.
- 뽑기 가능은 잔액이 뽑기 비용 미만에서 이상으로 바뀌는 순간 한 번만 표시한다. 잔액이 다시 비용 미만으로 내려간 뒤 재상승해야 다시 표시할 수 있다.
- 오버레이가 숨겨졌거나 해당 알림이 꺼져 있으면 말풍선을 표시하지 않는다.
- 억제된 알림은 오버레이를 다시 켜거나 알림을 활성화할 때 재생하지 않는다.
- 판정, 성장, 보상은 말풍선 표시 여부와 무관하게 처리한다.

말풍선 애니메이션 길이, 정확한 대사, 세부 간격과 픽셀 아트는 13장의 구현 조정 범위다.

#### 로컬 데이터

저장 위치를 읽기 전용으로 표시하고 OS 파일 탐색기로 여는 기능만 제공한다. 백업, 복원, 초기화 버튼은 제공하지 않는다.

### 7.3 칭호

- 정보의 프로필 카드에는 최대 한 개의 장착 칭호를 표시한다.
- 사용자가 처음 획득한 칭호는 장착 칭호가 없을 때 자동 장착한다.
- 두 번째 이후 칭호는 현재 장착값을 바꾸지 않는다.
- 업적 화면에서 보유 칭호를 장착·교체·해제한다.

### 7.4 트로피

- `첫 만남` 트로피는 룸의 첫 번째 빈자리에 자동 배치한다.
- 빈자리가 없으면 보관함에 지급한다.
- 나머지 트로피는 모두 보관함에 지급하고 사용자가 직접 배치한다.
- 자동 배치 실패가 트로피 지급 실패로 이어져서는 안 된다.

### 7.5 소급 판정과 보상

앱 업데이트로 새 업적 정의가 추가되면 설치 이후 앱이 저장한 업적 사실과 이벤트 투영값으로 즉시 판정한다. 조건을 만족하면 일반 달성과 동일하게 보상을 한 번 지급한다. 설치 전 CLI 로그는 소급 판정의 입력이 아니다.

업적 해제 상태와 보상 완료 상태를 분리한다. 코인 지급이나 트로피 지급이 실패하면 업적을 다시 해제하지 않고 미완료 보상 작업을 재시도한다. 사용자에게 지급 완료로 표시하는 시점은 모든 필수 보상이 멱등하게 기록된 뒤다.

## 8. 수집 계약

### 8.1 번들 경계

- 앱 배포물은 macOS·Windows용으로 검증한 고정 버전 `ccusage` 수집 컴포넌트를 포함한다.
- 사용자의 전역 Node.js, Bun, Nix 또는 `ccusage` 설치에 의존하지 않는다.
- 앱 실행 중 최신 버전을 인터넷에서 자동 다운로드하지 않는다.
- 수집기는 비용 필드를 제외하고 날짜·도구·모델·입력·출력·캐시 토큰을 포함한 JSON을 반환해야 한다.
- 앱은 버전이 고정된 JSON 어댑터에서만 수집기 출력을 도메인 값으로 변환한다.
- 세 CLI의 원본 세션 스키마를 앱 코드에서 각각 파싱하지 않는다.

### 8.2 최초 기준점

소스별 첫 정상 스캔에서 현재 누적값과 가장 최근 원천 위치를 기준점으로 저장한다. 이 스캔의 값은 정보, 코인, 활동 시간, 업적에 반영하지 않는다.

기준점은 다음 경우에 새로 만든다.

1. 앱 설치 후 해당 소스의 첫 정상 감지
2. 이전에 없던 소스를 나중에 처음 감지
3. 사용자가 껐던 소스를 다시 활성화

재스캔과 앱 재실행은 정상 기준점을 과거로 되돌리지 않는다.

### 8.3 실행 주기와 원자성

수집은 앱 시작, 실행 중 매 1분, 카드별 수동 재스캔에서 실행한다. 같은 소스에 대한 실행이 겹치면 나중 요청을 합치고 동시 두 번 실행하지 않는다.

한 수집 묶음은 다음 순서로 처리한다.

1. 고정 버전 수집기 실행과 JSON 검증
2. 소스별 기준점 이후 증가분 계산
3. 중복 키 검사
4. 사용량·활동 분·업적 사실 저장
5. 보상 대상 토큰을 재화 도메인에 멱등 요청
6. `usage.aggregated` 발행
7. 소스별 기준점과 마지막 성공 시각 갱신

4~7은 중간 실패 후 재실행해도 동일 증가분을 두 번 반영하지 않아야 한다.

### 8.4 비활성 기간

소스 토글을 끄면 비활성 시작 시각과 마지막 기준점을 기록한다. 다시 켜기 전 해당 소스는 자동·수동 집계를 실행하지 않는다. 다시 켤 때 현재 상태를 새 기준점으로 잡으므로 비활성 기간의 기록은 영구 제외된다. 과거에 이미 집계한 값은 유지한다.

### 8.5 토큰 정의

```text
관측 토큰 = 입력 토큰 + 출력 토큰 + 캐시 생성 토큰 + 캐시 읽기 토큰
```

정보와 사용량 업적은 관측 토큰을 사용한다. 코인은 재화 도메인이 반환하거나 승인한 `보상 대상 토큰`을 사용한다. 보상 대상 토큰은 캐시 가중치와 환산 정책을 적용할 수 있지만 정보의 관측 토큰을 바꾸지 않는다.

### 8.6 활동 시간

- 1분 집계에서 하나 이상의 소스에 새 관측 토큰이 있으면 현재 로컬 분을 활동 분으로 기록한다.
- 같은 분에 여러 소스가 증가해도 활동 분은 하나다.
- 같은 분의 재시도와 중복 집계는 활동 시간을 추가하지 않는다.
- 앱이 종료되거나 일시 중지된 동안 발생한 토큰은 다음 정상 집계에서 사용량에는 반영하지만 과거 활동 분을 추정하지 않는다.
- 앱을 다시 열어 여러 증가분을 한 번에 발견하면 해당 감지 분 하나만 활동 시간에 더한다.

### 8.7 날짜와 시간대

일별 통계는 수집 결과가 나타내는 발생 시각을 당시 시스템 로컬 날짜로 변환해 저장한다. 이미 저장한 날짜는 사용자가 시스템 시간대를 바꿔도 다시 분류하지 않는다. 오늘·최근 7일·최근 30일·최근 12주 경계는 현재 시스템 로컬 날짜를 사용한다.

### 8.8 감소·삭제·형식 오류

- 원천 로그 삭제로 수집기의 누적값이 감소해도 앱의 통계와 업적 진행률을 감소시키지 않는다.
- 누적값이 기준점보다 작아진 소스는 `source_rebased` 오류로 표시하고 현재 값을 새 기준점으로 삼아 이후 증가분부터 재개한다.
- 알 수 없는 JSON 스키마는 해당 소스 또는 전체 수집 묶음을 실패 처리하고 마지막 정상 데이터와 기준점을 유지한다.
- 한 소스의 오류는 다른 소스의 정상 증가분 반영을 막지 않는다.

## 9. 이벤트·보상 계약

### 9.1 공통 이벤트 봉투

```text
AchievementEvent {
  event_id: string
  event_type: string
  occurred_at: timestamp
  schema_version: positive integer
  payload: event-specific object
}
```

`event_id`는 발행 도메인에서 안정적으로 생성하며 재전송해도 바뀌지 않는다. `occurred_at`은 실제 도메인 상태가 영속화된 시각이다.

### 9.2 이벤트 목록

| 이벤트 | 필수 페이로드 | 발행 소유자 | 업적 사용 |
|---|---|---|---|
| `pet.acquired` | `pet_id`, `rarity`, `source` | collection 또는 gacha | 첫 만남, 행운아 |
| `fusion.completed` | `fusion_id`, `parent_rarities[2]`, `result_pet_id`, `result_rarity` | gacha | 연금술사, 연금술의 기적 |
| `pet.levelup` | `pet_id`, `previous_level`, `level`, `max_level` | overlay-growth | 첫 걸음, 오랜 친구 |
| `pet.evolved` | `pet_id`, `previous_stage`, `stage` | overlay-growth | 진화의 순간 |
| `battle.finished` | `battle_id`, `result`, `enemy_tier`, `streak` | battle | 첫 승리, 백전노장, 무패 |
| `dex.updated` | `owned_species`, `total_species` | collection | 수집가, 도감 마스터 |
| `usage.aggregated` | `aggregation_id`, `provider`, 토큰 증가분, 누적 관측 토큰, 활동 분 추가 여부 | meta | 사용량·히든 업적 |
| `currency.balance_changed` | `ledger_entry_id`, `previous_balance`, `balance`, `reason` | overlay-growth 재화 원장 | 뽑기 가능 알림 |

희귀도 값은 `COMMON`, `RARE`, `EPIC`만 사용한다. `pet.acquired.source`는 `gacha`, `fusion`, `hatch` 중 하나다. `battle.finished.result`는 `win`, `lose` 중 하나다.

### 9.3 발행·구독 규칙

1. 도메인 저장에 성공한 뒤 이벤트를 발행한다.
2. 업적 엔진은 다른 도메인의 내부 테이블을 직접 읽지 않는다.
3. 같은 `event_id`는 한 번만 사실 투영과 업적 판정에 반영한다.
4. 업적 정의별 `achievement_id`는 릴리스 사이에 바꾸지 않는다.
5. 이벤트가 재전송되거나 앱이 중간에 종료돼도 보상을 두 번 지급하지 않는다.

### 9.4 설치 이후 사실 투영

업적 엔진은 설치 이후 이벤트에서 다음 사실을 영속적으로 투영한다.

- 첫 펫·첫 에픽 획득 여부
- 현재 도감 보유·전체 수와 최고 보유 수
- 누적 합성 횟수와 커먼 2마리에서 에픽이 나온 횟수
- 펫 최고 레벨과 진화 발생 여부
- 누적 전투 승수와 최고 연승
- 누적 관측 토큰과 활동 분
- 로컬 날짜별 토큰이 발생한 도구 집합

새 업적은 이 사실 투영으로 소급 판정한다. 새로운 업적이 기존 투영으로 판정할 수 없는 사실을 요구한다면 그 업적 정의와 함께 사실 마이그레이션 또는 설치 이후 이벤트 재생 근거를 제공해야 한다.

### 9.5 외부 인터페이스

| 제공 도메인 | 필요한 인터페이스 |
|---|---|
| overlay-growth 재화 | `grant_once(reward_key, amount, reason)`, 현재 잔액, 최근 원장 20건, 누적 획득·소비 |
| collection | 현재 오버레이 펫 조회, 보유 펫 수, 도감 진행, 트로피 보관함 지급, 첫 빈자리 배치 |
| gacha | 누적 뽑기·합성 수와 관련 이벤트 발행 |
| battle | 누적 승수와 `battle.finished` 발행 |
| overlay-growth | 최고 레벨, 레벨·진화 이벤트, 말풍선과 패널 표시 |
| 공용 저장소 | meta 논리 데이터의 원자적 저장과 마이그레이션 |

업적 코인 보상의 `reward_key`는 `achievement:<achievement_id>`다. 재화 원장은 같은 키를 중복 지급하지 않는다.

## 10. 논리 데이터 모델

구체적인 저장 방식과 TypeScript 타입은 구현 계획에서 정하되 다음 논리 상태는 보존해야 한다.

| 논리 모델 | 핵심 값 | 용도 |
|---|---|---|
| `collector_source_state` | provider, enabled, status, baseline, disabled_at, last_success_at, last_error | 소스별 수집 상태와 비활성 구간 |
| `usage_daily` | local_date, provider, raw_model, input, output, cache_create, cache_read | 잔디·도구·모델 통계 |
| `activity_minute` | local_minute | 함께한 시간, 분 단위 중복 방지 |
| `processed_source_delta` | dedupe_key, provider, applied_at | 수집 멱등성 |
| `achievement_definition` | id, category, tier, condition, rewards, hidden | 버전 관리되는 업적 정의 |
| `achievement_fact` | fact_key, fact_value, updated_at | 설치 이후 소급 판정 |
| `achievement_progress` | achievement_id, progress, unlocked_at | 진행률과 해제 상태 |
| `achievement_reward` | achievement_id, reward_key, status, attempts | 보상 완료·재시도 |
| `user_profile` | display_name, equipped_title | 익명 이름과 장착 칭호 |
| `meta_settings` | overlay_visible, pet_size, autostart, notification flags | 화면·알림 설정 |

`achievement_definition`의 ID는 7.2 표를 단일 원본으로 생성하거나 동일 값을 검증해야 한다. 이름을 바꿔도 ID는 유지한다.

## 11. 오류, 복구와 영향 반경

### 11.1 오류 처리

| 상황 | 사용자 경험 | 데이터 규칙 |
|---|---|---|
| 수집기 실행 실패 | 해당 카드 `집계 오류`, 재스캔 제공 | 마지막 정상값·기준점 유지 |
| 지원하지 않는 JSON 형식 | 앱 업데이트가 필요하다는 오류 | 증가분 미반영, 기준점 유지 |
| 소스 기록 없음 | `기록을 찾을 수 없음` | 다른 소스 정상 처리 |
| 원천 로그 감소 | 해당 소스 오류 후 새 기준점 | 누적 통계·진행률 감소 금지 |
| 재화 보상 실패 | 업적 보상 처리 중 표시 | 같은 `reward_key`로 재시도 |
| 트로피 자동 배치 실패 | 보관함 지급 안내 | 트로피 소유권 보존 |
| 다른 도메인 조회 실패 | 해당 정보 블록만 오류 | 나머지 화면 유지 |

사용자에게는 원본 로그 내용과 내부 명령 출력 대신 도구 이름, 오류 종류, 마지막 정상 집계 시각, 재시도 행동만 보여준다.

### 11.2 영향 반경

가장 넓은 계약은 9.2의 이벤트 목록이다. collection, gacha, battle, overlay-growth가 각각 자기 이벤트를 발행해야 한다. meta는 이벤트 타입과 업적 소비 계약을 소유하지만 발행 도메인의 내부 구현은 소유하지 않는다.

저장 스키마는 공용 저장소 소유자와, 코인 지급·원장 조회는 재화 소유자와, 트로피 지급·배치는 collection 소유자와 합의해야 한다.

### 11.3 플랫폼 검증 범위

macOS와 Windows에서 각각 다음을 검증한다.

- 세 CLI 기본 위치 자동 감지
- 번들 수집기 실행과 JSON 호환
- 트레이 메뉴와 오버레이 표시 상태 유지
- 항상 맨 위와 다중 모니터 경계 보정
- 부팅 시 자동 실행 등록·해제
- 외부 후원·저장소 링크 열기
- 저장 위치 열기

## 12. 인수 조건

### 정보

- **INFO-001:** 정보 진입 시 `요약`이 기본이며 프로필과 여섯 핵심 수치가 스크롤 없이 보인다.
- **INFO-002:** 최초 실행에서 기기 정보를 사용하지 않은 익명 한글 이름이 한 번 생성되고 수정·재생성할 수 있다.
- **INFO-003:** 프로필 펫은 현재 오버레이 펫 변경을 반영하고 별도 대표 펫 상태를 만들지 않는다.
- **INFO-004:** 잔디는 최근 12주 고정이며 날짜별 관측 토큰과 0을 구분한다.
- **INFO-005:** 오늘·주·달·전체 필터가 5.2의 범위대로 도구·모델 집계에 적용된다.
- **INFO-006:** 모델은 상위 5개가 기본이며 전체 보기를 열면 선택 기간의 모든 `(도구, 원본 모델명)` 행이 보인다.
- **INFO-007:** 실적 타일 하나의 조회가 실패해도 다른 타일과 사용량 화면은 계속 사용할 수 있다.
- **INFO-008:** USD 비용은 정보 화면과 저장된 표시용 데이터에 존재하지 않는다.

### 설정

- **SET-001:** 최초 실행에 세 소스가 모두 없을 때만 설정의 수집 탭이 자동으로 열린다.
- **SET-002:** 각 수집 카드는 상태, 기본 위치, 마지막 정상 시각, 재스캔, 토글을 표시한다.
- **SET-003:** 소스를 껐다 켜면 과거 통계는 유지되고 비활성 기간은 소급되지 않는다.
- **SET-004:** 사용자 지정 경로, 클릭 통과, 집중 모드, 조용한 시간대가 제공되지 않는다.
- **SET-005:** 펫 크기를 바꿔도 메타 패널 크기는 바뀌지 않는다.
- **SET-006:** 자동 실행은 기본 꺼짐이며 사용자 조작 없이 OS 시작 항목에 등록되지 않는다.
- **SET-007:** 오버레이 숨김 상태가 재실행 후 유지되고 트레이에서 다시 켤 수 있다.
- **SET-008:** 후원 주소가 비어 있는 버튼은 `준비 중`이며 클릭할 수 없다.
- **SET-009:** 백업·복원·초기화·수집 데이터 미리보기 기능이 제공되지 않는다.

### 수집

- **COLLECT-001:** 깨끗한 macOS·Windows 설치에서 별도 런타임 설치와 네트워크 다운로드 없이 번들 수집기가 실행된다.
- **COLLECT-002:** 첫 정상 스캔의 기존 로그가 통계·코인·활동 시간·업적을 증가시키지 않는다.
- **COLLECT-003:** 앱 시작·1분 주기·수동 재스캔이 같은 수집 경계를 사용한다.
- **COLLECT-004:** 같은 증가분을 반복 입력해도 사용량·활동 시간·코인·업적이 한 번만 변한다.
- **COLLECT-005:** 한 소스의 실패가 다른 두 소스의 정상 집계를 막지 않는다.
- **COLLECT-006:** 관측 토큰과 보상 대상 토큰이 서로 다른 값이어도 정보와 코인이 각 계약값을 사용한다.
- **COLLECT-007:** 같은 로컬 분에 세 소스가 증가해도 활동 시간은 1분만 증가한다.
- **COLLECT-008:** 비활성 기간과 설치 전 기간의 기록은 재스캔으로 되살아나지 않는다.
- **COLLECT-009:** 누적 원천값 감소가 저장된 통계와 업적 진행률을 감소시키지 않는다.

### 업적과 알림

- **ACH-001:** 7.2의 22개 ID·조건·보상이 설정과 화면에서 일치한다.
- **ACH-002:** 일반 업적은 진행률을 표시하고 잠긴 히든 업적은 이름·조건·진행률·보상을 공개하지 않는다.
- **ACH-003:** 동일 이벤트와 동일 업적을 반복 처리해도 해제와 각 보상은 한 번뿐이다.
- **ACH-004:** 새 업적은 설치 이후 사실로 소급 판정되고 설치 전 CLI 로그를 사용하지 않는다.
- **ACH-005:** 첫 칭호만 자동 장착하며 이후 칭호를 획득해도 사용자 선택을 덮어쓰지 않는다.
- **ACH-006:** 첫 만남 트로피는 빈자리에 자동 배치되고 실패하면 보관함에 남는다. 다른 트로피는 자동 배치하지 않는다.
- **ACH-007:** 업적 한 개는 상세 말풍선, 같은 묶음의 두 개 이상은 한 개의 집계 말풍선으로 표시한다.
- **ACH-008:** 오버레이가 숨겨졌거나 알림이 꺼진 동안 억제된 말풍선은 나중에 재생되지 않지만 판정과 보상은 유지된다.
- **ACH-009:** 보상 실패는 미완료 상태로 남고 같은 멱등 키로 재시도할 수 있다.

### 공통과 플랫폼

- **META-001:** 펫 우클릭으로 세 메타 화면을 열 수 있고 동시에 둘 이상의 메타 패널이 보이지 않는다.
- **META-002:** 패널은 펫이 있는 모니터 안에서 좌·우·상단 순으로 적절한 위치를 선택한다.
- **META-003:** macOS와 Windows에서 트레이, 항상 맨 위, 자동 실행, 저장 위치 열기가 각각 검증된다.
- **META-004:** 다른 도메인의 저장 실패 전에 업적 이벤트가 발행되지 않는다.
- **META-005:** 구현 계획과 테스트는 변경 대상 요구사항 ID를 명시하고 성공·실패 증거를 연결한다.

## 13. 구현 단계의 조정 가능 범위

다음은 사용자 관찰 계약을 바꾸지 않는 범위에서 구현 중 조정할 수 있다.

- 말풍선의 정확한 표시 시간, easing, 픽셀 단위 간격
- 사건별 펫 표정과 짧은 대사
- 익명 이름 생성용 형용사·동물 단어 목록의 구체적인 구성
- 논리 모델을 구현하는 저장 방식, TypeScript 모듈과 타입 이름
- 고정 버전 수집기를 앱에 포함하는 빌드·패키징 방식
- 플랫폼별 네이티브 API를 감싸는 내부 어댑터 구조

다음은 구현 편의로 바꿀 수 없다.

- 설치 전 기록 제외
- 비활성 기간 제외
- 관측 토큰과 보상 대상 토큰 분리
- 업적 22개와 보상
- 보상·수집 멱등성
- 사용자에게 보이는 기능의 포함·제외 범위
- macOS·Windows 지원 범위

이 경계를 바꾸려면 이 기획서와 관련 인수 조건을 먼저 수정하고 사용자 승인을 다시 받아야 한다.
