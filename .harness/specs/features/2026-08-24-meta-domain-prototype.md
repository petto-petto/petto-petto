# Feature specification: meta 도메인 프로토타입

This specification owns the product what and why. The related implementation
plan owns the technical how.

## Status

Approved (요청자 승인, 2026-08-24)

## Owner

성훈 (`meta` 도메인 담당, 요청자)

## Problem and user outcome

스터디 사이드 프로젝트가 도메인별로 나뉘어 각자 임시 저장소에서 프로토타입을 만들고, 다음
주에 서로의 프로토타입 UI와 코드베이스를 놓고 **공통 베이스 패키지 구조**를 확립한다.

현재 이 저장소는 `src/main.rs` 하나짜리 hello-world이고 구조 결정이 전혀 없다. 승인된 제품
기획서 `.harness/specs/meta-info-settings-achievements-design.md`는 `meta` 도메인의 MVP
전체를 서술하지만, 한 주짜리 프로토타입이 그중 무엇을 어느 깊이로 구현할지는 정하지 않는다.

이 명세의 사용자는 **요청자 본인과 스터디 팀원들**이다. 의도한 결과는 다음 두 가지다.

1. 팀 회의에 가져갈 **근거 있는 워크스페이스 구조 제안** — 도메인 패키지가 서로를 직접
   의존하지 않고 공용 커널만 공유한다는 것을 패키지 매니페스트로 증명할 수 있는 형태.
2. `meta` 도메인의 **세 화면이 실제로 뜨고 조작되는 데스크톱 앱** — 팀원들이 UI를 눈으로
   비교할 수 있는 실행물.

## Scope

### 확정된 스택 결정

| 결정 | 확정값 | 근거 |
|---|---|---|
| UI 스택 | Tauri v2 | 요청자 선택. 펫 애니메이션·말풍선 표현과 트레이·멀티모니터 지원이 성숙 |
| 수집기 경계 | `UsageCollector` 트레이트 + 고정 JSON 픽스처 | 요청자 선택. 8장 규칙을 결정론적으로 검증하고 실제 어댑터는 나중에 교체 |
| 화면 범위 | 정보·설정·업적 3화면 전부 | 요청자 선택 |

### 구현 깊이

프로토타입은 영역마다 목표 깊이가 다르다. 이 구분이 이 명세의 핵심이다.

| 깊이 | 영역 | 의미 |
|---|---|---|
| **깊게** — 실제 규칙 + 테스트 | 수집 계약(기획서 8장), 업적 판정·보상 멱등성(7장·9장), 조련사 이름 규칙(5.1) | 기획서의 불변식을 계약 테스트로 못박는다. 나중에 저장소·수집기를 갈아끼워도 이 테스트가 살아남아야 한다 |
| **동작하는 수준** | 정보 3서브탭, 설정 4서브탭, 업적 화면, 패널 규약(4.2) | 실제로 뜨고 눌리고 값이 바뀐다. 픽셀 완성도와 애니메이션은 목표가 아니다 |
| **스텁** | 다른 도메인 포트(collection·gacha·battle·overlay-growth), 영속 저장소, 펫 오버레이 | 트레이트로 경계만 긋고 인메모리 가짜 구현으로 채운다 |

### 워크스페이스 구조 제안

팀 결정: **feature 단위 상위 패키지**를 두고 그 안을 아키텍처별로 나눈다.

```
package.json                # npm workspaces
packages/
  pet-core/                 # 공통 베이스: 이벤트 봉투, 공용 값 타입, 시간 추상화
  pet-meta/                 # ← 내가 맡은 feature의 상위 패키지
    src/domain/             #   규칙 (순수 로직, 바깥을 모른다)
    src/ports/              #   다른 도메인·인프라에 요구하는 인터페이스
    src/persistence/        #   저장 형식과 저장소 포트
    src/view/               #   화면 모델
    test/                   #   기획서 인수 조건 계약 테스트
      support/              #     다른 도메인·저장소 대역
apps/
  desktop/src/main/         # Electron 메인: 조립 · IPC · 창 · 저장 · 도메인 대역
  desktop/src/preload/      # 렌더러에 노출하는 안전한 API 표면
  desktop/renderer/         # 화면 (HTML/CSS/JS)
```

`@pet/meta`는 `@pet/core`에만 의존한다. 다른 feature 패키지가 추가돼도 서로를 직접 의존하지
않고 `@pet/core`의 이벤트와 각자가 소유한 포트로만 대화한다. 이것이 팀에 제안할 규칙이다.

### 포함하는 동작

- 정보 화면: 요약(프로필 + 누적 3수치 + 오늘 3수치), 사용량(기간 필터·최근 12주 잔디·도구별·모델별 분해), 실적(타일 6종 + 코인 원장)
- 설정 화면: 수집(소스 카드 3종·상태·재스캔·토글), 화면, 알림, 기타
- 업적 화면: 22개 목록, 카테고리 필터, 진행률, 히든 마스킹, 완료율, 칭호 장착
- 수집 파이프라인: 최초 기준점, 증가분 계산, 중복 제거, 활동 분 적립, 소스별 오류 격리
- 업적 엔진: 이벤트 소비, 사실 투영, 판정, 보상 멱등 지급, 소급 판정
- 패널 규약: 400×462, 한 번에 하나, 펫 기준 좌·우·상단 배치와 모니터 작업 영역 보정
- 자리표시 펫: 드래그 가능한 always-on-top 작은 창. 패널 배치를 시연하기 위한 최소 구현

## Non-goals

프로토타입에서 명시적으로 제외한다. 제외 이유를 함께 남긴다.

| 제외 항목 | 이유 |
|---|---|
| 실제 `ccusage` 실행·번들 (COLLECT-001) | 요청자가 픽스처 경계를 선택. 번들·버전 고정은 MVP 과제 |
| 영속 저장소(SQLite 등)와 마이그레이션 | 저장소는 팀 공통 베이스 논의 대상. 프로토타입은 인메모리로 두고 경계만 노출 |
| 실제 펫 스프라이트·애니메이션·말풍선 (ACH-007, ACH-008) | `overlay-growth` 도메인 소유. 자리표시 펫으로 대체 |
| 트로피 지급·배치 (ACH-006) | `collection` 도메인 소유. 포트 스텁으로만 표현 |
| 부팅 시 자동 실행, 오버레이 숨김 영속 (SET-006, SET-007) | OS 통합 + 영속화 의존. 토글 UI만 두고 동작은 미구현으로 표시 |
| Windows 검증 (META-003, COLLECT-001) | 요청자 머신이 macOS. 크로스 플랫폼 검증은 MVP 과제 |
| 후원 링크 실제 주소 (SET-008) | 배포 설정 주입 대상. `준비 중` 비활성 상태만 구현 |
| 다국어, 배지·공유 카드, USD 비용 | 제품 기획서 2.2가 이미 MVP에서 제외 |

## Domain rules

기획서의 규칙 중 프로토타입이 **코드와 테스트로 지켜야 하는** 것들이다. 전문은 제품 기획서를
따르며 여기서는 프로토타입이 검증할 대상을 특정한다.

### 수집 (기획서 8장)

1. 소스별 첫 정상 스캔은 기준점만 저장하고 통계·코인·활동 시간·업적을 증가시키지 않는다.
2. 같은 증가분을 반복 입력해도 사용량·활동 분·코인·업적은 한 번만 변한다 (`dedupe_key`).
3. 같은 로컬 분에 세 소스가 모두 증가해도 활동 분은 1만 증가한다.
4. 누적 원천값이 기준점보다 작아지면 `source_rebased` 오류로 표시하고 현재 값을 새 기준점으로
   삼는다. 저장된 통계와 업적 진행률은 감소시키지 않는다.
5. 한 소스의 실패가 다른 소스의 정상 증가분 반영을 막지 않는다.
6. 소스를 끈 기간의 기록은 다시 켜도 소급되지 않는다. 이미 집계한 과거 값은 유지한다.
7. 관측 토큰 = 입력 + 출력 + 캐시 생성 + 캐시 읽기. 보상 대상 토큰은 별도 값이며 관측 토큰을
   바꾸지 않는다.

### 업적 (기획서 7장·9장)

8. 22개 `achievement_id`·조건·보상은 코드 분기가 아니라 버전 관리되는 설정에서 온다.
9. 같은 `event_id`는 한 번만 사실 투영과 판정에 반영한다.
10. 해제 상태와 보상 완료 상태를 분리한다. 보상 실패는 해제를 되돌리지 않고 같은
    `reward_key`(`achievement:<achievement_id>`)로 재시도한다.
11. 진행률은 감소하지 않는다.
12. 잠긴 히든 업적은 이름·조건·진행률·보상을 노출하지 않는다.
13. 새 업적 정의는 설치 이후 사실 투영으로 소급 판정하며 설치 전 CLI 로그를 쓰지 않는다.
14. 첫 칭호만 자동 장착한다. 이후 획득은 사용자 선택을 덮어쓰지 않는다.

### 프로필·패널

15. 조련사 이름은 `형용사 + 동물` 한글 조합을 최초 1회 생성해 저장한다. OS 사용자명·MAC 주소·
    계정 식별자를 쓰지 않는다.
16. 저장값은 공백 제거 후 1~20자이며 줄바꿈과 제어 문자를 허용하지 않는다.
17. 메타 패널은 한 번에 하나만 보인다. 펫 크기 설정은 패널 크기에 영향을 주지 않는다.

## Acceptance criteria

각 항목은 제품 기획서 12장의 요구사항 ID로 추적한다. 확인 수단을 함께 적는다.

### 프로토타입 고유

- **PROTO-001:** `@pet/meta`가 `@pet/core` 외의 feature 패키지를 의존하지 않는다. — `packages/pet-meta/package.json`의 `dependencies`로 확인.
- **PROTO-002:** `bash .harness/scripts/verify-electron.sh`가 전 항목 통과한다. — 신선한 명령 출력으로 확인.
- **PROTO-003:** 앱이 실행되어 세 패널을 열고 서브탭을 전환할 수 있다. — 앱 자체 점검 로그로 확인.

### 수집 — 단위 테스트로 확인

- **COLLECT-002:** 첫 정상 스캔이 통계·코인·활동 시간·업적을 증가시키지 않는다.
- **COLLECT-004:** 같은 증가분 반복 입력이 각 값을 한 번만 바꾼다.
- **COLLECT-005:** 한 소스 실패가 다른 두 소스 집계를 막지 않는다.
- **COLLECT-006:** 관측 토큰과 보상 대상 토큰이 서로 다른 값이어도 각 계약값이 쓰인다.
- **COLLECT-007:** 같은 로컬 분에 세 소스가 증가해도 활동 시간은 1분만 증가한다.
- **COLLECT-008:** 비활성 기간 기록이 재스캔으로 되살아나지 않는다.
- **COLLECT-009:** 누적 원천값 감소가 저장된 통계와 진행률을 감소시키지 않는다.

### 업적 — 단위 테스트로 확인

- **ACH-001:** 22개 ID·조건·보상이 설정과 화면에서 일치한다.
- **ACH-002:** 잠긴 히든 업적이 이름·조건·진행률·보상을 노출하지 않는다.
- **ACH-003:** 동일 이벤트·동일 업적 반복 처리에도 해제와 보상이 한 번뿐이다.
- **ACH-004:** 새 업적이 설치 이후 사실로 소급 판정된다.
- **ACH-005:** 첫 칭호만 자동 장착되고 이후 획득이 사용자 선택을 덮어쓰지 않는다.
- **ACH-009:** 보상 실패가 미완료로 남고 같은 멱등 키로 재시도된다.

### 정보·설정 — 실행 화면으로 확인

- **INFO-001:** 정보 진입 시 `요약`이 기본이고 프로필과 여섯 핵심 수치가 스크롤 없이 보인다.
- **INFO-002:** 익명 한글 이름이 한 번 생성되고 수정·재생성할 수 있다.
- **INFO-004:** 잔디가 최근 12주 고정이며 날짜별 관측 토큰과 0을 구분한다.
- **INFO-005:** 오늘·주·달·전체 필터가 도구·모델 집계에 적용된다.
- **INFO-006:** 모델이 상위 5개 기본이며 전체 보기에서 모든 `(도구, 원본 모델명)` 행이 보인다.
- **INFO-008:** USD 비용이 화면과 저장된 표시용 데이터에 존재하지 않는다.
- **SET-001:** 세 소스가 모두 없을 때만 수집 탭이 자동으로 열린다.
- **SET-002:** 각 수집 카드가 상태·기본 위치·마지막 정상 시각·재스캔·토글을 표시한다.
- **SET-003:** 소스를 껐다 켜면 과거 통계가 유지되고 비활성 기간이 소급되지 않는다.
- **SET-004:** 사용자 지정 경로·클릭 통과·집중 모드·조용한 시간대가 제공되지 않는다.
- **SET-005:** 펫 크기를 바꿔도 메타 패널 크기가 바뀌지 않는다.
- **SET-008:** 후원 주소가 비어 있는 버튼이 `준비 중`이며 클릭할 수 없다.
- **SET-009:** 백업·복원·초기화·수집 데이터 미리보기가 제공되지 않는다.
- **META-001:** 동시에 둘 이상의 메타 패널이 보이지 않는다.
- **META-002:** 패널이 펫 기준 좌·우·상단 순으로 배치되고 모니터 작업 영역 안으로 보정된다.

## Edge and error cases

| 상황 | 프로토타입 동작 |
|---|---|
| 수집기 픽스처가 잘못된 JSON | 해당 소스만 `집계 오류`, 마지막 정상값·기준점 유지, 다른 소스 정상 처리 |
| 누적값이 기준점보다 작음 | `source_rebased` 표시 후 현재 값을 새 기준점으로. 통계·진행률 감소 없음 |
| 보상 지급 실패 | 업적은 해제 유지, 보상은 미완료로 남고 재시도 가능 |
| 다른 도메인 포트 조회 실패 | 해당 정보 블록만 오류, 나머지 화면 유지 (INFO-007) |
| 기록이 아직 없음 | `설치 이후 기록이 아직 없습니다`와 0 값 |
| 조련사 이름이 빈 문자열·21자 초과·제어 문자 포함 | 저장 거부 후 이전 값 유지 |

## API and data impact

**신규 공개 인터페이스** — 다음 주 팀 논의의 실제 안건이다.

- `@pet/core`: `DomainEvent` 봉투(`event_id`, `event_type`, `occurred_at`, `schema_version`, `payload`), 기획서 9.2의 이벤트 8종, `Rarity`/`PetId`/`Coin` 등 공용 값 타입.
- `@pet/core` 포트 트레이트: `CurrencyPort`(`grant_once`, 잔액, 최근 원장 20건, 누적 획득·소비), `CollectionPort`(현재 오버레이 펫, 보유 펫 수, 도감 진행, 트로피 지급), `EventBus`.
- `@pet/meta` 포트: `UsageCollector`(고정 JSON 스냅샷 반환), `MetaStore`(스냅샷 저장·로드).

**저장 형식** — 기획서 10장의 논리 모델 10종을 TypeScript 타입으로 표현하되 프로토타입 구현은
인메모리다. 영속 스키마와 마이그레이션은 공용 저장소 소유자와 합의할 사항으로 남긴다.

**호환성** — 프로토타입이므로 하위 호환 의무가 없다. 단 `achievement_id` 22개 값은 릴리스
사이에 바뀌지 않아야 하므로 지금부터 기획서 7.2 표를 단일 원본으로 삼는다.
