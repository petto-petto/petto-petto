# Feature specification: 동선 4단계 — 정보를 공통 틀 안으로

This specification owns the product what and why. The related implementation
plan owns the technical how.

## Status

Approved (요청자 승인, 2026-10-17)

## Owner

sh111-coder (요청자). 정보 화면 배치는 메타 담당, 창 수명은 앱 담당이 리뷰한다.

## Problem and user outcome

3단계 뒤 앱에는 창 문법이 두 가지 남았다.

- 펫룸·뽑기·합성·도감은 같은 상단 바가 있는 640 창 하나이고, 탭으로 같은 자리에서 바뀐다.
- 정보는 오버레이 펫 옆에 뜨는 400×544 세로 패널이고, 상단 바도 다른 화면으로 가는 탭도 없다.

펫룸에서 `정보 ↗`로 열 때는 보조 창이라 괜찮다. 하지만 펫 우클릭 메뉴에서 `정보`만 열면 닫기밖에 할 수 없어
다른 화면으로 갈 수 없다(2026-10-17 요청자 피드백). 패널에 바로가기를 더해도 두 세계 사이에 다리를 하나 더 놓을
뿐이라 유기적으로 느껴지지 않는다.

요청자 결정(2026-10-17): 동선 결정 3(정보는 펫 옆 세로 패널 유지)을 바꾼다. 정보를 640 공통 틀의 탭으로 넣는다.

사용자 관점의 결과: 앱은 오버레이 펫과 창 하나다. 어디서 정보를 열든 같은 상단 바가 보이고, 거기서 바로 다른
화면으로 간다.

## Scope

### 상단 바

- 탭을 `펫룸 · 뽑기 · 합성 · 도감 · 정보 · 업적 · 전투 ↗`로 바꾼다. `정보`에서 `↗`를 뗀다 — 다른 탭처럼 같은
  자리에서 화면이 바뀐다.
- `업적`도 상단 바 탭으로 뺀다(요청자 추가 결정, 2026-10-17). 정보와 같은 창이 업적 화면을 보인다. 받을 보상의
  빨간 점은 `업적` 탭으로 옮긴다.
- 상단 바의 지금 탭은 정보 창이 보이는 화면을 따른다. 설정·시연은 정보 안의 화면이라 `정보`가 지금 탭이다.

### 정보 화면

- 정보·업적·설정(과 개발용 시연 화면)을 640 창 안의 `정보` 화면으로 연다. 상단 바 아래 640×420을 쓴다.
- 화면 안의 `정보 · 업적` 탭은 지운다. 그 자리에 지금 화면 이름(정보 · 업적 · 설정)을 둔다. 설정 입구 `⚙`, 설정의
  `←`, 개발용 `⚗`는 지금처럼 화면 안에 둔다.
- 화면 안의 `✕`와 창 끌기 손잡이는 지운다. 상단 바가 닫기와 끌기를 맡는다.
- 넓어진 폭을 쓴다. 정보 요약은 왼쪽에 펫 카드와 토큰 카드, 오른쪽에 함께한 기록을 두는 두 칸이다. 업적·설정·사용량은
  가운데 한 칸(최대 폭 560px)에 그대로 둔다.
- 요약의 `자세히`는 없앤다. 세로 패널은 높이가 모자라 함께한 기록을 접어 두었지만, 두 칸이면 한 화면에 들어간다
  (구현 중 확인, 2026-10-17). 사용량의 `자세히`는 그대로 둔다.
- 화면 안 글자·카드 모양·색은 바꾸지 않는다.

### 정보를 여는 곳

정보를 여는 모든 길이 같은 640 창을 연다. 640 창이 이미 떠 있으면 그 자리에서 정보로 바뀐다(2단계 화면 여는 규칙).

| 여는 곳 | 열리는 화면 |
| --- | --- |
| 펫 우클릭 메뉴 `정보` | 정보(받을 보상이 있으면 업적) |
| 알림 말풍선 `보상 받으러 가기` | 업적 |
| 상단 바 `정보` · `업적` 탭 | 정보 · 업적 |
| 트레이 `정보 · 설정 · 업적`, 앱 메뉴 `⌘2 · ⌘3 · ⌘4` | 각 화면 |

### 지우는 것

- 펫 옆에 뜨는 세로 패널 창. 오버레이 펫 위치를 따라 패널 자리를 정하던 동작도 쓰지 않는다.
- 오버레이를 숨기면 패널도 숨기던 동작. 정보 화면은 이제 펫에 붙어 있지 않아 오버레이와 따로 산다.

## Non-goals

- 정보·업적·설정 화면의 내용, 문구, 계산.
- 개발 도구(⚗ 시연) 숨기기. 요청자 결정으로 나중에 한다.
- 메타 도메인의 패널 배치 함수(`placePanel`)와 크기 상수 삭제. 쓰는 곳이 없어지지만 메타 담당이 정리한다.
- 전투 창의 형태(결정 2 유지).

## Domain rules

1. 앱의 창은 오버레이 펫, 640 창 하나, 따로 뜨는 전투 창 셋이다. 정보는 640 창의 한 화면이다.
2. 정보 화면이 무엇을 보일지는 지금처럼 메타가 정한다(`panelScreen`, `panel:show`). 앱은 창만 연다.
3. 상단 바 탭 이동은 2·3단계와 같은 화면 여는 규칙을 쓴다. 창이 두 개가 되지 않는다.

## Acceptance criteria

| 관측 가능한 결과 | 확인 방법 |
| --- | --- |
| 상단 바 탭이 `펫룸 · 뽑기 · 합성 · 도감 · 정보 · 업적 · 전투 ↗`이고 받을 보상의 점이 `업적`에 있다 | 탭 모델 단위 테스트 |
| 정보 창에서 업적·정보·설정으로 옮기면 상단 바의 지금 탭이 업적·정보·정보로 바뀐다 | 실화면 |
| 펫 우클릭 메뉴 `정보`가 640 창을 정보 화면으로 열고, 상단 바로 펫룸·뽑기로 바로 간다 | 실화면 |
| 펫룸이 열려 있을 때 `정보` 탭을 누르면 같은 자리에서 정보로 바뀌고 창이 하나다 | 실화면, 창 목록 |
| 받을 보상이 있을 때 메뉴 `정보`, 말풍선 `보상 받으러 가기`가 업적 화면을 연다 | 실화면 |
| 트레이·앱 메뉴의 정보·설정·업적이 640 창의 각 화면을 연다 | 실화면 |
| 정보 화면에 `✕`·끌기 손잡이가 없고 상단 바의 닫기·끌기가 동작한다 | 실화면 |
| 정보 요약이 두 칸이고, 업적·설정이 640×420 안에서 잘리지 않는다 | 실화면, 패널 자체 시험 |
| 펫 옆 세로 패널 창이 더는 뜨지 않는다 | 실화면, 창 목록 |
| 기존 테스트와 `bash .harness/scripts/verify-electron.sh`가 통과한다 | 명령 실행 결과 |

## Edge and error cases

- **오버레이를 숨긴 채 정보를 엶**: 정보 화면은 오버레이와 상관없이 열린다.
- **설정 화면에서 다른 탭으로 감**: 다음에 정보 탭을 열면 메타의 기존 규칙대로 기본 화면(정보)으로 들어간다.
- **전투 창과 겹침**: 다른 640 화면과 같이, 초점이 있는 동안 전투 창 위에 보인다.

## API and data impact

- 저장 형식·테이블·마이그레이션 변경 없음.
- 메타 IPC(`panel:open` · `panel:show` · `panel:current` 등)는 그대로다. 앱의 `MetaHost.showPanel`이 패널 창 대신 640
  정보 화면을 연다.
- `@pet/shell`의 탭 모델에서 `정보`가 640 화면이 된다.
- `design.md`의 공통 상단 바 절과 정보 패널 관련 문구를 고친다.
