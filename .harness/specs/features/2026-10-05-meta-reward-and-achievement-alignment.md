# Feature specification: meta 재화 단위·토큰 적재·합성 업적·도감 칸 수 정렬

This specification owns the product what and why. The related implementation
plan owns the technical how.

## Status

Approved (요청자 승인, 2026-10-05)

## Owner

성훈 (`meta` 도메인 담당, 요청자)

## Problem and user outcome

`meta`를 다른 도메인의 실제 데이터에 연결하기 전에, `meta`의 규칙 네 가지가 지금 구현된
다른 도메인과 어긋나 있다.

- **재화 단위.** 뽑기·합성은 재화를 토큰량 그대로 쓴다(뽑기 1회 100,000, 합성 30,000 /
  100,000). 그런데 `meta`는 재화를 "코인"이라 부르며 보상 대상 토큰 10,000개를 1로 줄여
  지급한다. 같은 원장에 쌓이므로 사용량 보상으로는 뽑기를 할 수 없다. 요청자의 실제
  저장소에서 보상 대상 토큰 약 102만 개가 재화 92로 지급돼 있었다.
- **토큰 사용량 적재.** `ccusage`로 수집한 사용량이 `meta` 자신의 표에만 쌓이고 공용 토큰
  표(`token_stats` · `token_history`)는 비어 있다. 다른 기능이 `TokenClient`로 도구별
  사용량을 읽을 수 없다.
- **합성 업적.** 숨김 업적 `연금술의 기적`의 조건은 "커먼 펫 2마리 합성으로 에픽 획득"이다.
  실제 합성은 같은 등급 10마리로 한 단계 위 등급 1마리를 만들기 때문에 이 조건은 어떤
  경로로도 달성할 수 없다.
- **도감 칸 수.** `meta`는 도감을 20칸으로 고정했는데 등록된 종은 6종이다. 전부 모아도
  `6/20`으로 보이고 `도감 마스터`를 달성할 수 없다.

사용자는 AI 도구를 쓴 만큼 쌓인 재화로 실제로 뽑기·합성을 할 수 있고, 업적 화면에는
지금 게임에서 달성할 수 있는 조건이 보이기를 원한다.

## Scope

- 코인이라는 개념을 없앤다. 재화의 단위는 토큰이고, 사용량 보상은 보상 대상 토큰 1개당
  재화 1을 지급한다.
- 업적의 재화 보상을 토큰 단위로 다시 정한다. 기존 값에 10,000을 곱한다.
- 수집한 사용량 증가분을 공용 토큰 표에 적재한다.
- `meta`의 재화 포트를 없애고 공용 `TokenClient`로 합친다. 사용량 적재·재화 지급·잔액·오늘
  획득량을 뽑기·합성과 같은 `TokenClient` 하나로 읽고 쓴다.
- 숨김 업적 `연금술의 기적`의 조건을 현재 합성 규칙으로 달성할 수 있는 것으로 바꾼다.
- 도감 전체 칸 수는 등록된 펫 종 수를 따른다. 요약의 `도감 보유/전체`와 `도감 마스터`
  판정이 같은 값을 쓴다.
- 요약의 함께한 기록 첫 칸을 `사용한 토큰`(관측 토큰)에서 `누적 토큰`(지금까지 쌓은 재화)으로
  바꾼다. 요청자가 2026-10-05에 지시했다 — 사용 가능 토큰과 같은 기준이어야 하고, 사용자는
  그 숫자를 "앱에서 쌓은 토큰"으로 읽는다.
- 사용량 화면과 토큰 마일스톤 업적도 누적 토큰과 같은 기준으로 맞춘다(요청자 지시,
  2026-10-05). 사용량 화면의 `사용한 토큰`은 `쌓인 토큰`이 된다.
- 전투 업적 4개(`첫 승리`, `백전노장 Ⅰ·Ⅱ`, `무패`)는 정의를 그대로 둔다.
- 합성 횟수 업적 `연금술사 Ⅰ·Ⅱ`(5회·50회)와 `수집가 Ⅱ`(도감 15종)는 정의를 그대로 둔다.

## Non-goals

- 합성·뽑기·전투·성장·활성 펫·트로피의 **실제 데이터 연결**. 이 도메인들은 값을 담은 표가
  아직 없어 Mock(시연 이벤트 · `StubGacha` · 메모리 트로피)으로 두고, 표가 생기면 바꾼다.
  합성·전투 업적은 그때까지 시연 이벤트로만 진행된다.
- 이미 지급된 원장 항목의 소급 재계산. 과거 `사용량 보상`과 업적 보상 항목은 그대로 둔다.
- 연결 이전에 `meta` 표에 쌓인 사용량을 공용 토큰 표로 옮기는 일. 요청자가 연동 이후부터만
  쌓여도 된다고 정했다.
- 뽑기·합성 비용과 합성 규칙 자체의 변경, 펫 종 추가.

## Domain rules

1. 재화의 단위는 토큰이다. 뽑기·합성이 차감하는 원장과 같은 원장, 같은 단위다.
2. 사용량 보상 지급액 = 그 증가분의 보상 대상 토큰 수. 보상 대상 토큰은 입력 + 출력 +
   캐시 생성이며 캐시 읽기는 제외한다. 캐시 읽기는 같은 맥락을 다시 읽을 때마다 쌓여 관측
   토큰의 대부분을 차지하므로, 포함하면 새로 일한 양이 아니라 대화 길이를 보상하게 된다.
3. 보상 대상 토큰이 0인 증가분은 재화를 지급하지 않는다.
4. 같은 증가분은 한 번만 지급하고 한 번만 적재한다.
5. 증가분은 공용 토큰 표에 관측 토큰과 보상 대상 토큰을 함께 적재한다. 첫 스캔(기준점)은
   적재하지 않는다.
6. 토큰 표 적재에 실패한 증가분은 통계·재화·활동 시간에도 반영하지 않고 다음 집계에서 다시
   시도한다.
7. 업적의 재화 보상은 토큰 수다. `첫 만남`은 100,000(뽑기 1회)이고 가장 큰 보상은
   3,000,000이다.
8. `연금술의 기적`은 합성 결과로 에픽 펫을 처음 얻었을 때 달성한다. 현재 규칙에서는 레어
   10마리 합성이 유일한 경로다. 업적 id, 숨김 상태, 보상(재화·칭호)은 유지한다.
9. 도감 전체 칸 수 = 등록된 펫 종 수. 종이 추가되면 칸 수도 따라 늘어난다.
10. `도감 마스터`는 보유 종 수가 등록된 종 수 이상일 때 달성한다. 등록된 종이 0이면
    달성하지 않는다.
11. 이미 달성한 업적은 종이 추가돼도 취소되지 않는다(진행률은 감소하지 않는다).
12. 오늘 획득량 = 사용자의 로컬 날짜 자정 이후에 지급된 재화의 합. 소비는 세지 않고 자정
    정각의 지급은 포함한다. 지급 건수와 무관하게 전부 더한다.
13. 누적 토큰 = 지금까지 지급된 재화의 합(사용량 보상 + 업적 보상). 써도 줄지 않는다. 사용
    가능 토큰 = 누적 토큰 − 쓴 양이므로, 한 번도 쓰지 않은 사용자에게는 두 값이 같다.
14. 사용량 화면의 모든 숫자(기간 합계, 도구별·모델별 분해, 12주 잔디)는 재화로 쌓이는 토큰 —
    보상 대상 토큰 — 이다. 업적 보상은 도구나 날짜에 속하지 않으므로 이 화면에는 없다. 그래서
    `전체` 기간의 합계 = 누적 토큰 − 업적 보상이다.
15. 토큰 마일스톤 Ⅰ·Ⅱ·Ⅲ은 누적 토큰이 100만 · 1천만 · 1억에 닿으면 달성한다. 요약에 보이는
    숫자가 곧 진행률이다. 업적 보상도 누적 토큰에 들어가므로 다른 업적의 보상으로도 진행된다.
16. 한 판정에서 지급된 보상은 다음 판정부터 누적 토큰에 반영한다. 보상 하나가 같은 판정에서
    다음 마일스톤을 연달아 열지 않는다.
17. 수집 결과 문구는 관측 토큰이 아니라 쌓인 토큰을 말한다(`토큰 +N`).

## Acceptance criteria

- 보상 대상 토큰 1,000,000개(관측 2,000,000개)의 증가분을 집계하면 재화가 1,000,000
  늘어난다. 다시 집계해도 더 늘지 않는다. — 계약 테스트(집계 파이프라인)
- 캐시 읽기만 늘어난 증가분은 원장 항목을 만들지 않는다. — 계약 테스트
- 집계한 증가분이 `TokenClient.statsByProvider()`에 도구별 관측·보상 대상 토큰으로 보이고,
  같은 잔액으로 뽑기 1회 값을 치를 수 있다. — 실제 SQLite 통합 테스트
- 토큰 표 쓰기가 실패한 집계는 통계와 재화를 바꾸지 않고, 다음 집계가 같은 증가분을
  반영한다. — 계약 테스트, 실제 SQLite 통합 테스트
- 결과가 에픽인 합성 완료 사실로 `연금술의 기적`이 달성되고, 결과가 레어인 합성으로는
  달성되지 않는다. — 계약 테스트(업적)
- 등록된 종이 6종일 때 요약의 도감이 `보유/6`으로 보인다. — 계약 테스트(요약 화면 모델)
- 5종 보유로는 `도감 마스터`가 달성되지 않고 6종을 모두 보유하면 달성된다. — 계약 테스트
- 업적 보상 문구가 `토큰 100,000` 형식이다. — 계약 테스트
- 어제 지급 500,000, 오늘 지급 30,000과 100,000, 오늘 소비 100,000이 있을 때 오늘 획득은
  130,000이다. — 계약 테스트(요약 화면 모델), 실제 SQLite 테스트(`earnedSince`)
- `meta` 패키지와 앱에 `meta` 전용 재화 포트·어댑터가 남아 있지 않다. — 소스 검색
- 보상 대상 100,000에 캐시 읽기 5,000,000이 붙은 사용을 집계하면 사용 가능 토큰과 누적 토큰이
  둘 다 100,000이다. 업적 보상 100,000을 받고 100,000을 쓰면 누적은 250,000 그대로 늘고 사용
  가능만 줄어든다. — 계약 테스트(요약 화면 모델)
- 전투 업적 4개의 정의와 판정 결과가 변경 전과 같다. — 기존 계약 테스트 통과
- 코인 보상 기록이 든 기존 DB와 옛 저장 파일이 토큰 보상으로 열린다. — migration 테스트,
  저장 형식 계약 테스트

- 보상 대상 100,000에 캐시 읽기 5,000,000이 붙은 사용을 집계하면 사용량 화면의 기간 합계 ·
  도구별 · 모델별 · 오늘 잔디 칸이 모두 100,000이고 요약의 누적 토큰과 같다. — 계약 테스트
- 같은 사용으로는 토큰 마일스톤 Ⅰ이 열리지 않고(진행 100,000), 누적 토큰이 1,000,000에 닿는
  판정에서 열린다. `무패` 보상 1,200,000만으로도 다음 판정에서 열린다. — 계약 테스트
- 누적 토큰을 읽지 못한 판정은 마일스톤 진행을 그대로 두고 다른 업적은 계속 판정한다. — 계약
  테스트

## Edge and error cases

- 등록 종 수를 읽지 못하면 요약의 도감 칸만 오류로 표시하고 나머지는 그대로 보인다.
  판정은 그 주기에 펫 사실을 갱신하지 않는다.
- 토큰 표에는 적재됐는데 `meta` 상태를 저장하기 전에 앱이 꺼졌다면, 다시 켰을 때 같은
  증가분이 통계에는 반영되고 토큰 표는 두 배가 되지 않는다.
- 재화 지급만 실패하면 지금처럼 지급 대기로 남겨 다음 집계에서 재시도한다.
- 변경 전에 1/10,000 비율로 지급된 항목과 변경 후 1:1 항목이 같은 원장에 섞인다. 잔액은
  그 합이다.
- 변경 전에 달성한 업적은 이미 예전 금액으로 지급됐고 다시 지급하지 않는다.
- 예전 기준(관측 토큰)으로 이미 열린 토큰 마일스톤은 누적 토큰이 목표에 못 미쳐도 열린 채로
  남는다.
- 환산을 없애기 전에 쌓인 사용량은 재화로 1/10,000만 지급됐다. 그런 저장소에서는 사용량
  화면의 `전체` 합계가 누적 토큰보다 크다. 새 저장소에서는 생기지 않는다.

## API and data impact

- `@pet/core`의 `Coin` 타입을 없앤다.
- `meta`의 재화 포트(`CurrencyPort`)와 앱의 어댑터(`SqliteCurrencyPort`)를 없앤다. 환산
  비율도 함께 사라진다.
- `meta`가 공용 `TokenClient`를 주입받아 네 메서드(`recordUsage` · `grantOnce` · `balance` ·
  `earnedSince`)만 좁혀 쓴다. 새 인터페이스는 만들지 않는다.
- 공용 `TokenClient`에 `earnedSince(since)`를 더한다. 기존 메서드와 구현은 바뀌지 않는다.
- 업적 정의의 보상 필드와 보상 종류 값이 `coin`에서 `token`으로 바뀐다. 저장된 보상
  기록은 migration(`meta / 2`)과 저장 형식 v3 변환이 옮긴다. 멱등 키는 바뀌지 않는다.
- `fusion.completed` 이벤트에서 재료 등급 2개를 뺀다(이벤트 스키마 v2).
- 업적 사실 `commonFusionEpic` · `dexTotal`을 없애고 `fusionEpic`을 더한다. 저장된 옛
  사실 행은 migration이 지운다.
- 테이블 추가·변경은 없다.

## Open questions

없음. 요청자가 2026-10-05에 다음을 결정했다 — 코인 개념 제거, 업적 보상 금액과 지급 기준
토큰은 구현자가 정함(각각 10,000배, 보상 대상 토큰), `수집가 Ⅱ` 유지, 표가 없는 도메인은
Mock. 같은 날 이어서 `meta` 재화 포트의 `TokenClient` 통합을 지시했고, 연동 이전 사용량은
옮기지 않기로 했다.
