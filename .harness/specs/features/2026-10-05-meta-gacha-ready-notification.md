# Feature specification: meta 뽑기 가능 알림과 뽑은 횟수 표시

This specification owns the product what and why. The related implementation
plan owns the technical how.

## Status

Approved (요청자 승인, 2026-10-05)

## Owner

성훈 (`meta` 도메인 담당, 요청자)

## Problem and user outcome

- 정보 화면의 `뽑은 횟수`가 누구에게나 12로 보인다. 뽑기는 횟수를 저장하지 않고, `meta`가
  쓰는 대역이 12를 돌려주기 때문이다. 사용자는 지어낸 숫자를 실제 기록으로 읽는다.
- 설정의 `뽑기 가능` 알림은 켜고 끌 수 있지만 아무 일도 하지 않는다. 재화가 토큰량 그대로
  쌓이게 되어 뽑기 비용을 넘기는 순간이 실제로 생겼는데, 사용자는 그 순간을 알 수 없다.

사용자는 기록되지 않은 값을 숫자로 보지 않고, 뽑기를 할 수 있게 된 순간 펫에게서 듣는다.

## Scope

- `뽑은 횟수`는 횟수를 저장하는 곳이 없는 동안 숫자 대신 `—`로 표시한다.
- 뽑기 가능 알림을 제품 기획서 6.3의 규칙대로 낸다.
- 주기 집계에서도 펫이 할 말(업적 달성, 뽑기 가능)을 펫 창 채널로 보낸다.

## Non-goals

- 펫 창이 말풍선을 그리는 일과 말풍선을 눌러 뽑기 화면을 여는 일. 오버레이의 몫이고,
  지금 오버레이는 이 채널의 말풍선을 그리지 않는다.
- 뽑기 횟수와 뽑기 비용의 실제 연결. 뽑기에 그 값을 담은 표가 없어 대역으로 둔다.
- 레벨업 알림.
- 성장 업적(`첫 걸음`, `오랜 친구 Ⅰ·Ⅱ·Ⅲ`, `진화의 순간`)을 성장 표에 연결하는 일. 아래
  Open questions 참조.

## Domain rules

1. 뽑기 가능은 잔액이 뽑기 1회 비용 미만에서 이상으로 바뀌는 순간 한 번만 알린다. 잔액이
   정확히 비용과 같으면 가능이다.
2. 잔액이 다시 비용 미만으로 내려간 뒤 재상승해야 다시 알린다.
3. 앱을 켰을 때 이미 뽑을 수 있는 상태는 "바뀐 순간"이 아니므로 알리지 않는다.
4. 오버레이가 숨겨졌거나 뽑기 가능 알림이 꺼져 있으면 표시하지 않는다. 억제된 알림은 나중에
   재생하지 않는다.
5. 업적 달성과 뽑기 가능이 같은 집계에서 함께 일어나면 한 말풍선에 이어서 표시한다.
6. 뽑기 1회 비용은 100,000 토큰이다. 뽑기 구현이 차감하는 값과 같다.
7. `뽑은 횟수`의 `0`은 한 번도 뽑지 않았다는 실제 값이다. 기록되지 않은 값은 `0`이 아니라
   "모름"이고 `—`로 그린다. 조회 실패(`⚠ 조회 실패`)와도 구분한다.

## Acceptance criteria

- 잔액이 60,000에서 120,000이 되는 집계에서 말풍선 `뽑기를 할 수 있어!`가 한 번 나오고,
  다음 집계에서는 나오지 않는다. — 계약 테스트
- 100,000을 쓴 뒤 다시 100,000을 넘기면 다시 나온다. — 계약 테스트
- 알림이 꺼져 있거나 오버레이가 숨겨진 동안 넘긴 것은, 다시 켜도 나오지 않는다. — 계약 테스트
- `첫 만남` 보상으로 비용을 넘기면 말풍선이 `첫 만남 달성! 토큰 100,000 · 뽑기를 할 수 있어!`
  이다. — 계약 테스트
- 잔액을 읽지 못한 집계는 알리지 않고, 다음 집계가 그동안의 변화를 알린다. — 계약 테스트
- 앱이 조립한 요약의 `뽑은 횟수`는 숫자가 아니라 "모름"이다. — 계약 테스트

## Edge and error cases

- 집계 사이에 뽑기로 잔액이 비용 미만으로 내려갔다가 같은 1분 주기 안에 다시 넘기면 그
  왕복은 알리지 않는다. `meta`는 뽑기의 차감 시점을 알지 못한다.
- 직전 상태는 저장하지 않는다. 앱을 다시 켜면 처음 보는 상태에서 시작한다.

## API and data impact

- `meta`의 `GachaPort`: `drawCount()`가 "모름"을 돌려줄 수 있고, `drawCost()`가 생긴다.
- 집계 결과에 뽑기 가능 전환 여부가 실린다.
- 주기 집계의 `usage:aggregated` 방송에 말풍선 문구가 실린다(이전에는 항상 비어 있었다).
- 저장 형식과 테이블 변경은 없다.
