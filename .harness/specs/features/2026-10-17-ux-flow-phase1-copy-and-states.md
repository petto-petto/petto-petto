# Feature specification: 동선 1단계 — 문구와 버튼 상태 바로잡기

This specification owns the product what and why. The related implementation
plan owns the technical how.

## Status

Approved (요청자 승인, 2026-10-17 — 개발 모드 분리는 빼고 진행)

## Owner

sh111-coder (요청자). 화면별 변경은 해당 패키지 담당이 리뷰한다: 오버레이, 메타 패널, 뽑기, 합성.

## Problem and user outcome

팀원마다 기능을 따로 만들면서 같은 대상을 화면마다 다르게 부르고, 할 수 없는 행동이 할 수 있는 것처럼
보이며, 개발용 도구가 사용자 화면에 그대로 노출돼 있다. 2026-10-17 동선 진단에서 확인한 문제 중 각 패키지
안에서 끝나는 것만 먼저 고친다.

- 펫 우클릭 메뉴의 `펫 관리`를 누르면 `펫룸` 창이 열린다. 이름이 다르다.
- 재화를 정보 패널은 `토큰`, 뽑기는 `TOKEN`·`Token`, 합성은 `TOKEN`이라고 쓴다.
- 잔액이 255,309인데 `10회 소환(1,000,000)`이 금색으로 강조된 채 눌리고, 누르면 `Token이 부족합니다`가 나온다.
- 합성은 재료 10장과 토큰(COMMON 30,000 · RARE 100,000)이 필요한데, 화면에 선택 수와 비용이 없다.
- 합성의 선택 탭과 선택 카드에 EPIC 보라색을 쓴다. `design.md` §2는 등급 색을 등급 표시에만 쓰고 선택은 금색으로 하라고 정한다.
- 설정 수집 화면에 `(기획서 SET-004)` 같은 내부 문서 번호가 사용자에게 보인다.
- 오버레이 빈 상태 카드가 프로젝트에 없는 `Galmuri` 글꼴을 지정해 시스템 글꼴로 보인다.

사용자 관점의 결과: 같은 것은 어디서나 같은 이름으로 보이고, 지금 할 수 없는 행동은 눌리기 전에 이유와 함께
비활성으로 보인다.

## Scope

### 용어

| 위치 | 지금 | 바뀐 뒤 |
| --- | --- | --- |
| 펫 우클릭 메뉴 | 펫 관리 | 펫룸 |
| 뽑기 잔액 상자 | 보유 TOKEN · 펫 N마리 | 보유 토큰 · 펫 N마리 |
| 뽑기 버튼 보조 문구 | 100,000 Token / 1,000,000 Token · RARE 이상 보장 | 100,000 토큰 / 1,000,000 토큰 · RARE 이상 보장 |
| 뽑기 안내 문구 | 잠든 씨앗에 Token을 건네보세요 | 잠든 씨앗에 토큰을 건네보세요 |
| 합성 잔액 | TOKEN 255,309 | 보유 토큰 255,309 (뽑기와 같은 표기) |
| 뽑기·합성 오류 | Token이 부족합니다. | 토큰이 부족합니다. |
| 설정 수집 화면 | 사용자 지정 경로는 제공하지 않습니다 (기획서 SET-004) | 사용자 지정 경로는 아직 지원하지 않아요. |
| 설정 기타 화면 | 백업·복원·초기화는 제공하지 않습니다 (SET-009) | 백업·복원·초기화는 아직 지원하지 않아요. |

오버레이 관련 용어(`오버레이로 지정`, `오버레이 활성 중`, `오버레이 표시`)는 이미 통일돼 있어 그대로 둔다.

### 뽑기: 잔액에 따른 버튼 상태

- `1회 소환`과 `10회 소환`은 각각 잔액이 그 비용 이상일 때만 누를 수 있다.
- 잔액이 모자란 버튼은 회색 비활성으로 보이고, 보조 문구가 `{비용} 토큰 · {부족분} 부족`으로 바뀐다.
- 어느 버튼이든 잔액이 모자라면 조작 영역에 `AI 도구를 쓰면 토큰이 쌓여요.` 한 줄을 보인다.
- 금색 강조는 누를 수 있는 버튼에만 쓴다.

### 합성: 재료 수·비용·버튼 상태

- 활성 등급 옆에 `재료 {n} / 10 · {비용} 토큰`을 늘 보인다.
- `합성하기`는 재료가 10장이고 잔액이 비용 이상일 때만 누를 수 있다.
- 누를 수 없으면 버튼 근처에 이유 한 줄을 보인다. 재료가 모자라면 `재료가 {10-n}장 더 필요해요.`, 재료는 충분한데 잔액이 모자라면
  `토큰이 {부족분} 부족해요.`를 보인다. 둘 다 모자라면 재료 쪽을 보인다.
- 선택된 등급 탭과 선택된 재료 칸의 강조색을 금색(`#FFD166`)으로 바꾼다. 비전 합성소의 배경과 그 밖의 색은 유지한다.

### 글꼴

- 오버레이 빈 상태 카드(`아직 함께할 펫이 없어요`)의 글꼴을 이사만루체(`'Isamanru', sans-serif`)로 바꾼다.

## Non-goals

- 동선 2단계(말풍선 연결, 펫 우클릭 메뉴 항목 재구성과 배지, 결과 화면 후속 버튼, 정보 패널 카드 링크, 전투 HUD, 펫룸의 전투·정보 입구)
- 동선 3단계(공통 상단 바, 공통 디자인 토큰 CSS, 숫자 축약 통일)
- 개발 도구(정보 패널 ⚗ 시연 버튼, 오버레이 ⚙ 개발 패널, 전투 모션 메뉴) 숨기기. 요청자 결정(2026-10-17): 별도 실행 방법은
  학습 비용이 있어 지금은 그대로 두고, 나중에 걷어 낸다.
- 전투 화면의 모션 메뉴. 전투 기획서가 `모션 미리보기 유지`를 정해 두었으므로 전투 담당과 따로 정한다.
- 펫 우클릭 메뉴의 아이콘·순서·항목 수 변경. 이번에는 이름만 바꾼다.
- `아직 함께하는 펫이 없어요` 같은 보유 펫 빈 상태 문구. 오버레이 용어와 무관하다.
- 뽑기·합성의 비용, 확률, 천장, 재료 수 규칙 변경
- 정보 패널의 `K·M·B` 축약 표기와 뽑기·합성의 전체 자릿수 표기 차이

## Domain rules

1. 버튼을 누를 수 있는지는 화면에 보이는 잔액과 비용으로 판단한다. 잔액이 비용과 정확히 같으면 누를 수 있다.
2. 부족분은 `비용 - 잔액`이고 화면의 다른 금액과 같은 천 단위 구분 표기를 쓴다.
3. 버튼을 비활성으로 보이게 해도, 서버 쪽(메인 프로세스) 잔액 검사와 `토큰이 부족합니다.` 오류는 그대로 둔다. 화면과 저장소의
   잔액이 어긋나는 순간을 막는 마지막 방어선이다.
4. 등급 이름은 `design.md` 규칙대로 대문자 영어(`COMMON`·`RARE`·`EPIC`)를 유지한다.
5. 사용자에게 보이는 문구에 기획서 번호, 개발 용어, 영어 재화 이름을 쓰지 않는다.

## Edge and error cases

- **잔액을 읽지 못함**: 0으로 간주해 `부족`으로 표시하지 않는다. 버튼과 문구는 지금처럼 두고 기존 오류 안내를 보인다. 뽑기는 버튼을
  누르면 다시 읽기를 시도하므로, 비활성으로 막으면 복구 경로가 사라진다(구현 탐색 중 확인, 2026-10-17).
- **창이 열린 채 잔액이 바뀜**: 뽑기는 창에 다시 초점이 오거나 소환이 끝날 때, 합성은 데이터를 다시 읽을 때 버튼 상태를 다시 계산한다.
  사용량 집계로 잔액이 늘어난 순간 바로 반영되지 않을 수 있으나, 누르면 서버 검사가 판정하므로 잘못 차감되지 않는다.
- **연출 중**: 소환 연출, 합성 연출 중의 기존 비활성 규칙이 우선한다.
- **재료 후보 부족**: 같은 등급 보유 개체가 10장 미만이면 `재료가 N장 더 필요해요.`가 계속 보인다.

## API and data impact
