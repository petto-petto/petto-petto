# Feature specification: 펫룸 활성 선택의 읽기 전용 전투 연결

## Status

Approved — 2026-10-01 요청자의 “client 연동 … 필요하면 기능 추가해 … 내가 만든 port, adator 에”와
“전투창. 메인 오버레이는 ㄴㄴ”로 확정된 **선택 펫 표시 복구** 범위입니다.
이전 Draft의 전투 전체 보류안 대신 선택한 펫과 모션을 표시합니다.
실제 성장 데이터가 없는 개체에 XP를 부여하거나 저장소를 통합하는 승인은 포함하지 않습니다.

## Owner

전투 담당자(srkim0917). 펫룸은 선택 조회 계약, 공통 펫 담당자는 보유 개체·성장 계약을 소유합니다.

## Problem and user outcome

펫룸은 JSON 선택을 저장하지만 전투의 Adapter는 공통 DB 활성 펫만 읽어 선택한 펫이 나오지 않습니다.
사용자는 기존 펫룸에서 오버레이로 지정한 펫을 전투창에서도 즉시 보고 기존 모션을 사용할 수 있어야 합니다.
메인 오버레이의 표시·선택·성장은 변경하지 않습니다.

## Scope

- 기존 펫룸의 공개 scene 조회를 읽는 RoomSelectionClient·Adapter를 추가합니다.
- 전투는 매 요청에서 현재 선택과 명부를 읽고 개체 ID·이름·종·등급·레벨·외형을 반영합니다.
- 같은 개체 ID와 종이 검증된 공통 OwnedPet이 있으면 그 실제 성장 스냅샷으로 기존 전투 진행을 유지합니다.
- 공통 개체가 없는 JSON 펫도 외형·모션·기존 미리보기 조작은 표시합니다. 실제 XP 진행은 연결 대기임을 안내합니다.
- 앱의 전투 생성 옵션에 조회 Adapter만 주입합니다.

## Non-goals

- 메인 오버레이, 펫룸 JSON 저장·선택·IPC, 공통 활성값·DB·migration·성장 저장은 바꾸지 않습니다.
- 동일 종이라는 이유로 개체를 대응하거나 JSON 레벨에서 실제 XP를 추정하지 않습니다.
- 미연결 펫을 자동 지급·복제하지 않습니다. 다른 펫의 성장 진행을 대신 보여주지 않습니다.
- 전투 그래픽·크기·밸런스·공격 모션은 변경하지 않습니다.

## Domain rules

1. 선택 원천은 주입된 펫룸 조회입니다. 공통 활성 펫으로 fallback하지 않습니다. 조회 실패는 빈 결과가 아닙니다.
2. 공통 ID가 정확히 일치한 경우에만 저장 XP·레벨·진화 데이터를 사용합니다. ID는 같은데 종이 다르면 오류입니다.
3. 미연결 개체는 실제 XP 없음(null)으로 명시합니다. 표시용 적은 1스테이지·HP100%에서 시작하고 실제 XP 정복은 발생하지 않습니다.
   표시 모션·STOP/START·처치 등 기존 프로토타입 미리보기는 유지합니다. 이는 XP0이라는 저장 사실을 만드는 것이 아닙니다.
4. 같은 개체의 성장 연결이 확인되면 저장 진행으로 복원하되 과거 정복 연출을 재생하지 않습니다.
   연결을 잃으면 기존 XP 진행·처치 잔상을 남기지 않고 연결 대기 표시로 전환합니다.
5. 조회는 소유 데이터에 쓰지 않습니다. 같은 종의 여러 개체·선택 변경·재실행을 구분합니다.
6. 기존 공통 Client만 받는 사용자는 원래 활성 선택·XP 연동 그대로 동작합니다.

## Acceptance criteria

| 기준 | 검증 |
| --- | --- |
| 기존 펫룸 선택 후 첫 전투 열기·실행 중 교체·재열기에서 실제 선택 펫을 표시 | 실제 RoomState·임시 JSON·SQLite·Rust·격리 Electron |
| JSON 펫만 있고 공통 보유 펫이 없어도 선택 펫·실제 종/진화 에셋·모션 표시 | 빈 공통 명부의 실제 Rust/Electron 회귀 |
| 공통 활성값이 달라도 정확한 ID의 선택 개체에만 저장 XP 반영 | 같은 종 다른 개체·XP 증가·중복 알림 테스트 |
| 미연결 XP는 null, 실제 정복 없음, 연결/해제시 진행 복원·정리 | Rust 프로토콜·TypeScript 계약 |
| 다른 기능·저장 데이터 변경 없음 | 펫룸/오버레이/공통 DB diff 및 저장 전후 비교 |
| STOP·투명도·공격·모션 메뉴·닫기·재진입 유지 | 기존 전투 테스트와 실제 Electron |

## Edge and error cases

빈 명부·선택 없음·복수 활성·중복 ID·종 불일치·조회 오류·개체 삭제를 구별합니다.
오류를 다른 펫 또는 시드로 감추지 않습니다. 실제 사용자 DB를 테스트에 사용하지 않습니다.

## API and data impact

펫룸의 조회 계약을 그대로 소비하며 새 테이블·저장 형식은 없습니다.
전투 runtime 옵션에 선택 Client를 추가하며 기존 호출은 호환됩니다.
전투 내부 SYNC의 totalXp는 실제 값 또는 null입니다. 소유자의 OwnedPet/PetClient 타입은 바꾸지 않습니다.

## Open questions

공통 개체와 대응되지 않은 기존 JSON 펫의 **실제 성장 데이터 통합**은 펫/성장 소유자의 별도 작업입니다.
이 작업에서는 외형·모션을 복구하지만 성장까지 연결됐다고 보고하지 않습니다.

## Related implementation plan

`work standard` 및 `tdd-workflow`: 선택 조회 계약과 null XP 프로토콜 RED → 최소 구현 →
공식 Electron 게이트·실제 Rust·SQLite·UI 검증 → 독립 리뷰. 상세 결과는 전투 패키지 작업 기록에 남깁니다.
