# Feature specification: 전투의 펫 선택·성장 연동

## Status

Approved (2026-10-04 기준)

## Owner

전투 담당자(srkim0917). 펫룸은 선택 조회, 펫·성장 담당자는 개체와 성장 데이터 계약을 소유한다.

## Problem and user outcome

펫룸에서 선택한 펫과 전투에 표시되는 펫이 다르면 사용자가 원하는 개체의 전투를 볼 수 없다.
사용자는 선택한 펫의 외형과 모션을 전투창에서 확인하고, 해당 개체의 저장된 XP에 따라
현재 적과 전투 진행도를 이어가야 한다. 전투 실행에는 별도의 Rust 설치가 필요하지 않아야 한다.

## Scope

- 펫룸의 현재 선택과 보유 명부를 읽어 전투에 표시한다.
- 같은 개체의 성장 정보가 있으면 누적 XP·레벨·진화 단계를 반영한다.
- 성장 정보가 연결되지 않은 펫도 외형과 모션을 표시하고 연결 대기 상태를 안내한다.
- 기존 공격·피격·정복·다음 적 전환과 모션 미리보기 기능을 유지한다.
- 전투 규칙을 Electron 내부에서 실행하고 창 닫기·재진입·앱 종료를 처리한다.
- 전투 외 변경은 읽기 전용 Client·Adapter와 앱의 전투창·수명 연결에 한정한다.

## Non-goals

- 펫룸·메인 오버레이의 선택·표시·성장 저장 방식 변경.
- 공통 DB·테이블·마이그레이션 변경, 기존 펫 데이터 이관 또는 자동 생성.
- 토큰의 XP 환산, 전투 모션을 통한 XP·재화 지급.
- 뽑기·합성 결과를 펫룸에 전달하는 기능 구현.
- 전투 디자인·밸런스·공격 모션 변경.

## Domain rules

1. 펫룸 선택이 제공되면 그 개체를 표시한다. 선택이 없거나 조회가 실패했을 때 공통 활성
   펫으로 대체하지 않는다. 선택 조회를 제공하지 않는 기존 사용자는 공통 활성 펫을 따른다.
2. 개체 ID가 같은 펫만 성장 정보와 연결한다. 같은 ID의 종·이미지 식별자가 다르면 오류로
   처리하며, 같은 종류라는 이유로 다른 개체의 XP를 사용하지 않는다.
3. 전투 진행은 저장이 완료된 누적 XP로 계산한다. 중복 알림이나 공격 모션으로 XP가
   증가하지 않으며, 전투가 소유자의 선택·성장 데이터를 기록하지 않는다.
4. 성장 정보가 없으면 XP를 미연결 상태로 구분한다. 표시용 적은 1스테이지·HP 100%에서
   시작하며 실제 XP에 따른 정복은 발생하지 않는다. XP 0인 성장 정보는 정상 연결이다.
5. 성장 연결 시 저장된 진행도를 복원하되 과거 정복 연출을 재생하지 않는다. 연결이
   해제되면 이전 개체의 진행과 처치 연출을 정리하고 연결 대기 상태로 전환한다.
6. 선택·진화 단계가 바뀌면 해당 이미지를 사용한다. 이전 이미지의 늦은 응답이 현재
   전투 펫을 덮어쓰지 않아야 한다.
7. 전투창을 닫아도 다른 창은 유지하며, 재진입 시 기존 STOP·투명도 설정을 보존한다.
8. 앱·전투 데모·통합 검증은 Electron 내부 TypeScript 엔진을 사용한다. 별도 엔진
   바이너리와 빌드 준비 경로는 제공하지 않는다.

## Acceptance criteria

- 펫룸에서 선택한 개체가 첫 전투 실행·선택 변경·창 재열기 후에도 표시된다.
- 성장 정보가 없는 펫도 실제 이미지와 모션을 표시하고 성장 연결 대기를 안내한다.
- 같은 종의 여러 개체가 서로 다른 XP와 설정을 유지한다. 선택하지 않은 개체의 성장
  알림이 현재 전투에 적용되지 않는다.
- 저장 XP 증가에 따라 HP가 줄고, 해당 구간을 완료하면 처치 연출 후 다음 적으로 전환한다.
  재시작 시 저장된 XP로 진행도를 복원한다.
- 연결·해제·진화 전환 뒤에도 이전 개체의 XP·이미지·정복 연출이 남지 않는다.
- 공격·STOP/START·미리보기·카메라·크기 조절·닫기와 투명도 설정이 유지된다.
- Cargo가 없는 환경에서 실제 Electron 전투창을 열고 조작할 수 있다.
- 전투 조회·모션 조작 전후에 펫룸·성장 저장 데이터가 변하지 않는다. 전투창 이외의
  발신자와 성장 쓰기 명령은 전투 IPC에서 거부한다.

## Edge and error cases

- 빈 명부·선택 없음·삭제된 개체를 구분하며 다른 펫을 임의로 선택하지 않는다.
- 중복 개체 ID·복수 활성값·종 불일치·잘못된 XP·조회 실패를 오류로 전달한다.
- 조회 오류를 빈 결과로 바꾸지 않으며 이후 정상 조회에서 복구할 수 있어야 한다.
- 창 닫기·앱 종료 후 늦게 완료된 준비가 전투 실행을 다시 시작하지 않아야 한다.

## API and data impact

- 기존 PetClient의 조회 기능을 사용한다. RoomPetReadClient·PetClientRoomAdapter는
  조회 메서드만 제공하며 선택·성장 쓰기 기능을 노출하지 않는다.
- RoomSelectionClient·RoomSelectionAdapter로 현재 선택과 표시 명부를 읽는다.
- 앱은 성장 곡선·에셋 위치·전투창 식별 및 종료 신호를 전투에 제공한다.
- 저장 형식·테이블은 변경하지 않는다. 실제 성장 데이터 연결은 펫·성장 소유자가 제공한다.

## Open questions

전투 표시·계산 범위의 미결정 사항은 없다. 선택한 개체의 실제 XP를 공개 조회 계약으로
제공하는 작업은 펫룸·성장 담당자 범위이며, 연결 전에는 모션 미리보기를 유지한다.
