# Feature specification: 펫 도감 (Pet Dex)

This specification owns the product what and why. The related implementation
plan owns the technical how.

## Status

Approved (2026-10-05)

## Owner

박소원

## Problem and user outcome

지금은 어떤 펫이 존재하는지, 그중 무엇을 이미 만났고 무엇이 남았는지 볼 곳이 없다.
정보 화면의 `도감 보유/전체` 숫자만 있고, 도감 화면 자체는 펫룸 기획(2026-09-03)에서
범위 밖으로 미뤄 두었다.

사용자는 펫 도감에서 다음을 한눈에 본다.

- 아직 만나지 못한 COMMON·RARE·EPIC 펫은 **실루엣**으로 보여 "다음에 무엇을 뽑을지"를 기대하게 한다.
- 이미 만난 펫은 컬러 스프라이트와 **현재 보유 마릿수**를 보여 준다.
- 등급별·전체 수집 진행도를 보여 뽑기·합성의 동기를 만든다.

## Scope

### 1. 진입

- 펫룸 오른쪽 이동 버튼(`#destinations`)에 `📖 펫 도감`을 `✨ 펫 뽑기`·`🔮 펫 합성`과 나란히 추가한다.
- 뽑기·합성과 같은 방식(`room:navigate`)으로 펫룸 창이 도감 화면으로 바뀌고, 도감에서 `← 펫룸`으로 돌아온다.
- 확인하지 않은 신규 등록 종이 있으면 `📖 펫 도감` 버튼에 `NEW` 표식을 붙인다.

### 2. 화면 구성 (640×420 프레임 없는 창)

```
┌───────────────────────────────────────────────────────────────┐
│ ← 펫룸     펫 도감                    수집 4 / 6  ▓▓▓▓▓▓░░░ 66% │
│ [전체] [COMMON 2/2] [RARE 1/2] [EPIC 1/2]                      │
├──────────────────────────────────────┬────────────────────────┤
│ COMMON ───────────────               │   (선택한 슬롯 상세)    │
│ ┌────┐ ┌────┐                        │      큰 스프라이트       │
│ │🐹×3│ │🌱×1│                        │   No.003 두더지   COMMON │
│ └────┘ └────┘                        │   보유 3마리 · 최고 Lv.7 │
│ RARE ─────────────────               │   진화  ● ● ○           │
│ ┌────┐ ┌────┐                        │   첫 만남 2026.09.28     │
│ │🦓×1│ │ ▓▓ │  ← 실루엣              │                        │
│ └────┘ └────┘                        │   [펫룸에서 보기]        │
│ EPIC ─────────────────               │                        │
│ ┌────┐ ┌────┐                        │                        │
│ │ ▓▓ │ │⭐×0│  ← 발견했으나 0마리     │                        │
│ └────┘ └────┘                        │                        │
└──────────────────────────────────────┴────────────────────────┘
```

- **헤더**: 화면 제목, 전체 수집 진행도(`발견 종 / 등록 종`)와 퍼센트 진행 막대(XP 막대 스타일).
- **등급 탭**: `전체 · COMMON · RARE · EPIC`. 각 탭에 등급별 `발견/전체`를 표시한다. 기본은 `전체`.
- **그리드**: 등급 구역(COMMON → RARE → EPIC) 안에서 `speciesId` 오름차순으로, 같은 크기의 정사각 슬롯을 12px 간격으로 배치한다. 종이 늘어나면 그리드 영역만 세로 스크롤한다.
- **상세 패널**: 오른쪽 양피지 패널. 처음 열면 첫 슬롯을 선택한다.

### 3. 슬롯 상태

| 상태 | 조건 | 슬롯 표현 | 상세 패널 |
| --- | --- | --- | --- |
| 미발견 | 한 번도 획득한 적 없음 | 1단계 idle 스프라이트를 `#2C2438` 단색으로 채운 **실루엣**, 낮은 대비의 빈 슬롯 배경, 번호 `No.006`, 등급 안쪽 테두리 | 실루엣, 이름 `???`, 등급 배지, **획득 경로 힌트**, `✨ 펫 뽑기로 가기` 버튼 |
| 발견·보유 | 현재 1마리 이상 보유 | 컬러 1단계 스프라이트, 오른쪽 아래 `×N` 보유 수 배지, 등급 테두리·배지 | 아래 "발견 펫 상세" |
| 발견·미보유 | 획득한 적은 있으나 합성 재료로 써서 현재 0마리 | 컬러 스프라이트를 유지하되 채도를 낮추고 `×0` 표시 | 발견 펫 상세 + "지금은 함께하는 펫이 없어요" |
| NEW | 발견했지만 도감에서 아직 열어 보지 않음 | 슬롯 왼쪽 위 금색 `NEW` 표식 | 상세를 열면 확인 처리되어 표식이 사라진다 |

- 선택 슬롯은 디자인 가이드대로 2px 금색 점선 바깥 테두리로 표시한다.
- 상태는 색에만 기대지 않는다. 실루엣·`???`·`×N`·`NEW` 텍스트를 함께 쓴다.

### 4. 발견 펫 상세

- 큰 스프라이트(정수 배율, idle 모션 1회 재생 후 정지).
- `No.003 두더지` + 등급 배지.
- **보유 마릿수**, 보유 개체 중 **최고 레벨**.
- **진화 도감**: 1·2·3단계 썸네일. 보유 개체가 도달한 적 있는 가장 높은 단계까지 컬러로, 그 위 단계는 실루엣으로 보여 준다(현재 보유 기준).
- **첫 만남 날짜**.
- **획득 경로**: 뽑기 등급 확률과, RARE·EPIC이면 합성 경로(`COMMON 10마리 합성` / `RARE 10마리 합성`).
- 보유 중이면 `펫룸에서 보기` 버튼: 펫룸으로 돌아가 해당 종의 첫 개체 상세를 연다.

### 5. 획득 경로 힌트 문구 (미발견 상세)

- 공통: `✨ 펫 뽑기에서 만날 수 있어요 · {등급} {등급 확률}%`
- RARE: `🔮 COMMON 펫 10마리를 합성해도 만날 수 있어요`
- EPIC: `🔮 RARE 펫 10마리를 합성해도 만날 수 있어요`
- 확률은 뽑기 기능이 공개하는 값(현재 COMMON 80% · RARE 17% · EPIC 3%)을 읽어 쓰며 화면에 상수로 적지 않는다.

## Non-goals

- 도감 완성 보상 지급. 수집 보상은 기존 업적(`collection.dex_5`, `dex_15`, `dex_complete`)이 담당한다.
- 펫 설명(flavor text). 종 데이터에 설명 필드가 없으므로 다음 단계로 미룬다.
- 뽑기·합성 결과 화면의 `NEW! 도감 등록` 연출. 도감 저장소가 생긴 뒤 별도 작업으로 붙인다.
- 정렬·검색·즐겨찾기, 도감에서 직접 활성 펫 바꾸기.
- 정보 화면(meta)의 `도감 보유/전체` 계산 방식 변경. 아래 Open questions 참고.
- 오버레이 팻말 메뉴의 도감 진입점.

## Domain rules

- 도감 진행도는 마리 수가 아니라 **종** 수로 센다(펫룸 기획과 같은 규칙).
- **발견은 영구 기록이다.** 펫을 처음 얻는 순간(뽑기 `createOwnedPets`, 합성 결과 `replaceOwnedPets`) 그 종의 발견 기록을 남기고, 이후 합성으로 0마리가 되어도 지우지 않는다. 현재 보유 수로는 이 사실을 되살릴 수 없으므로 펫 도메인이 저장해야 한다(feature-contracts "한 순간에만 존재하는 사실").
- 발견 기록과 펫 생성은 같은 트랜잭션에서 저장한다. 펫은 생겼는데 발견이 빠지는 상태가 생기지 않는다.
- 진행도 분모는 **DB에 등록된 종 수**(`countSpecies`)다. 새 종이 배포되면 자동으로 미발견 실루엣 슬롯이 늘어난다.
- 보유 마릿수·최고 레벨·진화 단계는 **현재 보유 기준**이다.
- NEW는 "발견했지만 도감 상세를 연 적 없음"이다. 기능 도입 전에 이미 보유하던 종은 확인한 것으로 간주해 NEW를 붙이지 않는다.

## Edge and error cases

- **보유 펫 0마리·발견 0종**: 모든 슬롯이 실루엣이고 상세 패널에 "아직 만난 펫이 없어요. ✨ 펫 뽑기로 첫 친구를 만나 보세요."를 보인다.
- **도감 조회 실패**: 진행도를 `0/6`으로 그리지 않는다. 그리드 자리에 오류 패널과 다시 시도 버튼을 보인다.
- **NEW 확인 저장 실패**: 화면은 그대로 두고 NEW 표식도 유지한다. 다음에 열면 다시 시도한다.
- **스프라이트 에셋 누락**: 해당 슬롯에만 `?` 대체 아이콘을 보이고 다른 슬롯은 정상 표시한다.
- **도감을 연 채로 다른 창에서 뽑기**: 도감에 다시 진입할 때 최신 상태로 다시 읽는다(실시간 갱신은 범위 밖).
- **`prefers-reduced-motion`**: 상세 스프라이트 재생과 NEW 표식 팝 효과를 끈다.

## API and data impact

소유자는 펫 도메인이다. 도감 화면은 `PetClient`만 호출한다.

- **마이그레이션 `pet` v2**: `pet_discoveries(species_id PK → pet_species, discovered_at, seen_at NULL)`.
  기존 `owned_pets`의 종을 `discovered_at = seen_at = 마이그레이션 시각`으로 채운다.
- **`PetClient` 추가 메서드(안)**
  - `listDexEntries(): DexEntry[]` — 등록 종마다 `{ species, discoveredAt | null, ownedCount, highestLevel, highestStage, isNew }`.
  - `markDexSeen(speciesId): void`
- `createOwnedPets`·`replaceOwnedPets`가 같은 트랜잭션에서 발견 기록을 `INSERT OR IGNORE`한다. 기존 시그니처는 바뀌지 않는다.
- 도감 UI는 새 기능 패키지 `packages/pet-dex`(`@pet/dex`)가 소유하고, 뽑기·합성처럼 펫룸 창을 대신하는 640×420 창으로 연다.
- 실루엣은 기존 stage1 idle PNG를 Canvas `source-in` 합성으로 단색 처리한다. **새 에셋은 필요 없다.**
- 뽑기 확률은 `@pet/gacha`가 공개하는 값을 읽는다.

## Decisions (2026-10-05 요청자 확인)

1. 합성으로 0마리가 된 종은 **발견을 유지하고 `×0`**으로 표시한다.
2. 미발견 슬롯에도 **등급 테두리·배지를 공개**한다.
3. 진입점은 **펫룸 이동 버튼 하나**다. 오버레이 팻말 메뉴에는 넣지 않는다.

## Open questions

1. 정보 화면의 `도감 보유/전체`는 지금 `현재 보유 종 / 20칸`이고, 도감 화면은 `발견 종 / 등록 종`을 쓴다. 정보 화면을 도감 기준으로 맞출지는 meta 소유자와 별도 작업으로 정한다. 이번 범위에서는 정보 화면을 바꾸지 않는다.

## Design prompt

디자이너 역할(또는 UI를 만드는 에이전트)에게 그대로 넘기는 지시문이다. `design.md`가 정본이고, 아래는 도감에 적용한 값이다.

```text
petto-petto 의 "펫 도감" 화면을 만든다. design.md 를 먼저 끝까지 읽고 그 토큰·규칙만 쓴다.

[캔버스]
- 640×420 프레임 없는 창. 배경은 깊은 숲 #10231A 단색 + 아주 옅은 잎 패턴(선택). 장식이 슬롯과 경쟁하면 뺀다.
- 화면 가장자리 패딩 18px(space-7). border-radius·blur·glass 금지. 그림자는 2px 2px 0 rgba(0,0,0,.35)만.

[레이아웃]
- 헤더(높이 40px): 왼쪽 `← 펫룸` 나무 버튼, 이어서 제목 "펫 도감"(16px/700). 오른쪽에 `수집 4 / 6` (12px) + 진행 막대 120×10px(테두리 2px, 채움은 #8FD68A→#3C7A4A→#1C4A34 세로 그라데이션) + `66%`(10px).
- 탭 줄(높이 28px, 헤더 아래 8px): `전체` `COMMON 2/2` `RARE 1/2` `EPIC 1/2`. 나무 버튼 모양, 선택 탭은 금색 #FFD166 2px 아래 테두리 + 밝은 나무색. 등급명은 영문 대문자 그대로.
- 본문: 왼쪽 그리드 영역(가로 약 370px, 세로 스크롤) + 오른쪽 상세 패널(가로 약 216px). 사이 간격 12px.

[그리드]
- 등급 구역 제목: `COMMON` 등 13px/700, 등급 밝은색 글자 + 오른쪽으로 1px 점선 구분선. 구역 사이 10px.

- 스프라이트는 정수 배율(슬롯 안 48px 기준)로 중앙 배치, image-rendering: pixelated.
- 왼쪽 아래 번호 `No.003` 10px, 오른쪽 아래 보유 배지 `×3` 11px/700 (#F5ECD8 글자, #3A2A1C 바탕 2px 박스).

[슬롯 상태]
- 미발견: 바닥을 낮은 대비 #2B3A30 로 바꾸고, 스프라이트를 #2C2438 단색 실루엣으로. 등급 링은 유지하되 50% 밝기. 번호만 보이고 보유 배지는 없음. 슬롯 중앙 아래 `?` 10px.
- 발견·보유: 컬러 스프라이트 + `×N`.
- 발견·0마리: 컬러 스프라이트에 filter: grayscale(.6) brightness(.85), 배지 `×0`은 비활성 회색 #999999.
- NEW: 슬롯 왼쪽 위 바깥으로 2px 걸친 금색 #FFD166 바탕 `NEW` 10px/700, 글자 #3B2A1A. 등장 시 1회 2px 팝(reduced-motion 이면 없음).
- 선택: 슬롯 바깥 2px 금색 점선. 키보드 포커스: 2px 금색 외곽선 + 1px #2C2438 보조 링.
- hover: 슬롯을 translate(0,-2px) (애니메이션 80ms, reduced-motion 이면 없음).
```
