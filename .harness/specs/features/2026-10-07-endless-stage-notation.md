# Feature specification: 누적 진행을 유지하는 전투 스테이지 표기

## Status

Approved

## Owner

요청자

## Problem and user outcome

무한에 가까운 전투 진행에서 색·크기 순환 때문에 `8-3` 다음 표시가 `1-1`로 돌아간다.
플레이어는 적 외형이 반복되어도 계속 전진하고 있음을 스테이지 번호로 읽을 수 있어야 한다.

## Scope

`STAGE {누적 구간}-{전투}` 표기를 제안한다. 첫 구간은 1-1, 각 구간은 세 전투이며
8-3 이후 9-1, 16-3 이후 17-1로 진행한다.

## Non-goals

전투 난이도·보상·진행 상한·성장·저장 형식 변경, 환생·회차 시스템, 새로운 맵이나 적,
진행 번호 세 계층 도입.

## Domain rules

- 누적 진행 번호는 적의 색·크기와 독립적이다.
- 기존 첫 24전투의 표기를 유지하며 이후 앞 번호가 계속 증가한다.
- 현재 적이 처치·대기 상태일 때 그 적의 번호를 유지하고 다음 적 등장 시 다음 번호를 보여 준다.
- 미리보기의 적 색·크기는 실제 진행 번호를 변경하지 않는다.
- 저장된 기존 펫별 stage로 새 번호를 계산하며 회차·구간을 별도로 저장하지 않는다.
- 활성 펫이 없으면 기존처럼 스테이지 표기를 숨긴다.
- 번호가 길어도 주변 HUD를 덮지 않으며 생략 시 전체 번호를 확인할 수 있다.

## Acceptance criteria

- 누적 stage 24는 8-3, 25는 9-1, 48은 16-3, 49는 17-1로 보인다.
- 기존 1~24 번호 및 색·크기 순환을 유지한다.
- 처치→대기→등장에서 표시가 실제 적과 맞으며 번호가 조기에 넘어가지 않는다.
- 미리보기, 저장 복구, 펫 변경 시 정확한 실제 진행을 표시한다.
- 최소 창과 큰 구간 번호에서 HP 바·버튼을 가리지 않는다.

## Edge and error cases

활성 펫 없음은 표기 숨김으로 처리한다. 큰 stage는 정확한 번호를 유지하고 축약 단위를
사용하지 않는다. 입력 stage 유효성 및 상한은 기존 엔진 계약을 따른다.

## API and data impact

저장 형식과 외부 Port 변경 없이 기존 stage를 사용한다.

## Open questions

표기는 요청자가 승인했다. XP 요구량 증가 정책은 이번 범위 밖이며 기존 규칙을 유지한다.
