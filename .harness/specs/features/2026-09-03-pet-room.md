# Feature specification: 펫룸(Pet Room)

This specification owns the product what and why. The related implementation
plan owns the technical how.

## Status

Approved (요청자 승인, 2026-09-03 — 세션 중 계획 제시 후 3개 결정 승인)

## Owner

소원 (요청자)

## Problem and user outcome

배경 에셋(960×360 레이어 배경 2종)과 배경 생성 스킬은 끝나 있는데 **그것을 소비하는 화면이
없다.** 오버레이 창은 펫 한 마리만 띄우고, 보유 펫이 여럿이라는 사실이 사용자에게 어디에도
드러나지 않는다.

동시에 `@pet/meta`가 프로덕션에서 **테스트 대역(`InMemoryCollection`)을 그대로 쓰고 있다**
(`packages/pet-meta/src/app/state.ts`). 오버레이 펫이 star_wizard Lv.21로 고정이고, 보유 펫
수는 상수 3, 도감 진행도는 3/24로 박혀 있다. 정보 화면의 숫자가 전부 가짜다.

사용자(이 앱의 사용자, 그리고 이어받을 스터디 팀원)가 얻는 것:

1. 보유 펫 전원이 숲 배경 위를 돌아다니는 **살아 있는 화면**. 시각에 따라 낮/밤 배경이
   바뀌고 반딧불이가 움직인다.
2. 펫을 눌러 등급·레벨을 확인하고 **오버레이에 띄울 펫을 고르는** 경로.
3. 정보·업적 화면의 보유 펫 수와 도감 진행도가 **실제 데이터**가 된다.

## Scope

- 펫룸 창 — 배경 레이어 합성, 보유 펫 전원 배회, 반딧불이 애니메이션
- 시각 기반 낮/밤 배경 선택과 실행 중 자동 전환
- 펫 클릭 → 클릭 반응 재생 + 상세 패널(등급 배지 · 레벨 · 단계 · XP바 · 오버레이 지정)
- 활성 펫 지정과 오버레이 창의 **재시작 없는** 스프라이트 교체
- 보유 펫 명부의 영속(앱 재시작 후 유지)
- `CollectionPort`의 실제 구현으로 테스트 대역 교체
- 진입점 — **앱 메뉴 `펫 > 펫룸`(⌘1)**, 트레이 메뉴, 오버레이 우클릭 메뉴
- 펫 에셋 6종 수록(기존 1종 + 레퍼런스 프로젝트에서 5종), Galmuri 도트 폰트 번들

## Non-goals

- **펫 도감(Pet Dex) 화면** — 진행도 숫자는 제공하지만 도감 화면 자체는 이번 범위 밖
- 가챠·합성 등 펫 **획득** 로직 (명부는 고정 시드)
- 실제 XP 적립과 레벨업 (XP바는 레벨에서 만든 표시값)
- 신규 walk 애니메이션 제작
- 카메라 스크롤과 `parallax` 활용
- 앱 패키징 (리포에 아직 빌드 설정 없음)

## Domain rules

| 규칙 | 근거 |
|---|---|
| 로컬 06:00–17:59는 낮(`bg_002`), 18:00–05:59는 밤(`bg_003`) | 요청자 지정 |
| 활성 펫은 **항상 정확히 하나**. 명부 밖 id는 지정 불가 | 오버레이에 뜨는 펫이 곧 프로필 펫(기획서 5.1) |
| 배회는 idle을 유지한 채 **위치만** 슬라이드 | walk 모션이 에셋에 없음(에셋 가이드 §8) |
| 스프라이트 **좌우 반전 금지** | 광원 좌상단 고정(에셋 가이드 §7) |
| 프레임 크기·개수·fps는 **항상 옆 json에서** 읽는다 | EPIC stage3만 48px — 32 하드코딩 시 그 종만 잘림(가이드 §5) |
| 클릭은 `click`/`click2` 중 랜덤 1종을 1회 재생 후 idle 복귀 | 한 종만 쓰면 반복 클릭이 죽어 보임(가이드 §8) |
| 확대는 정수 배율 nearest-neighbor만 | design.md §4 |
| 도감 진행도는 마리 수가 아니라 **종** 수 | 가이드 §9 |
| 펫은 배경 전 레이어 **위**에 그리고, 배회 범위는 전경 기둥을 피한다 | `near` 레이어가 지면과 전경 기둥을 한 장에 담고 있음 — 아래 API 항목 참조 |
| 활성 펫 표시는 **오직 push 구독에서만** 갱신. 발신 창도 예외 없음 | 창이 여럿이라 진실의 원천이 하나여야 함 |

## Acceptance criteria

| 기준 | 확인 방법 |
|---|---|
| 시드된 보유 펫 6마리가 각자 idle을 재생하며 지면을 서서히 배회한다 | 앱 실행 캡처 + `배회하는 펫은 어떤 프레임에서도 영역을 벗어나지 않는다` 테스트 |
| 배회 중인 펫이 배경 밖이나 전경 나무 기둥과 겹치지 않는다 | `배회 영역은 지면 위에 있고 전경 나무 기둥을 피한다` 테스트 |
| 반딧불이가 12프레임을 6fps로 순환한다 | 실행 중 표시 프레임 관측(12종 전부) |
| 사용자 로컬 시각이 낮이면 bg_002, 밤이면 bg_003이 뜬다 | 경계값 단위 테스트 + 실행 중 push 전환 캡처 |
| 펫을 클릭하면 클릭 반응 후 상세 패널이 뜬다 | 실제 클릭 후 패널 상태 조회 |
| 상세 패널이 등급 배지·레벨·단계·XP바를 보여준다 | 캡처 |
| 활성 펫을 바꾸면 오버레이 창 스프라이트가 **재시작 없이** 즉시 바뀐다 | 지정 후 오버레이 캡처 + 오버레이 로그 |
| 상세 패널이 펫 활동 영역을 가리지 않는다 | 캡처 (design.md §7) |
| 앱을 재시작해도 활성 펫 지정이 유지된다 | 연속 실행에서 직전 활성 펫으로 시작 |
| 정보 화면의 보유 펫 수·도감 진행도가 실제 명부에서 나온다 | `CollectionPort` 구현 교체 |
| 앱을 켜면 펫룸으로 들어가는 길이 **눈에 보인다** | 앱 메뉴 항목·단축키 실행 확인, 트레이 아이콘이 비어 있지 않음 확인 |

## Edge and error cases

- **저장 파일 손상 / 모르는 종 / 빈 명부** → 시드로 되돌아가고 앱은 뜬다. 던지지 않는다.
- **활성 펫이 명부에서 사라짐** → 첫 마리로 되돌린다. 활성이 없는 상태는 존재하지 않는다.
- **스프라이트 한 종을 못 읽음** → 그 펫만 빠지고 나머지는 나온다. 오류를 화면에 표시한다.
- **click/click2가 없는 종** → idle만 재생한다.
- **창이 백그라운드에 있다 돌아옴** → `dt`를 한 프레임분으로 제한해 펫이 순간이동하지 않는다.
- **`prefers-reduced-motion: reduce`** → 반딧불이는 첫 프레임 고정, 배회 정지. idle은 유지한다
  (펫이 살아 있다는 표시이지 장식용 반복이 아니다).

## API and data impact

**신규 패키지** `@pet/room` — 보유 펫 명부, 장면 규칙, 스프라이트 규칙, 저장 형식.
Electron·DOM을 의존하지 않아 창 없이 `node --test`로 검증된다.

**신규 저장 파일** `room-state.json` (`version: 1`). meta의 `meta-state.json`과 분리한다 —
저장 주기와 스키마 변경 이유가 다르다. 기존 파일은 건드리지 않으므로 마이그레이션 없음.

**신규 IPC** `room:scene` · `room:open` · `room:setActivePet`(invoke),
`room:activePetChanged` · `room:backgroundChanged`(push, 전 창 브로드캐스트).

**변경된 인터페이스** `MetaAppState` 생성자가 `CollectionPort`를 주입받는다. 호출처는
`apps/desktop/src/main/main.ts` 한 곳이며 기존 계약 테스트는 영향받지 않는다.

### 배경 계약(`bg_00X.json`)에서 발견된 결함 — 배경 소유자 확인 필요

이 화면이 배경 계약의 최초 소비자다. 붙여 본 결과:

1. **펫의 z 순서가 계약에 없다.** `near` 레이어가 지면(y≥282 불투명)과 전경 나무 기둥
   (x 0–59, 876–942)을 한 장에 담고 있다. 펫은 지면 위에 서야 하므로 near보다 앞이어야 하고,
   그러면 기둥보다도 앞이 된다. 한 레이어에 z가 하나라 둘 다 만족시킬 수 없다. `petAnchor.y`
   (186)가 `groundTop`(282)보다 위라 계약만 읽으면 "mid와 near 사이"로 읽히는데, 그렇게 넣으면
   펫이 지면에 완전히 가려진다. → `near`를 지면/전경으로 분리하거나 레이어에
   `"foreground": true|false`를 넣어 달라.
2. **배회 가능 영역이 없다.** `petAnchor`는 점 하나인데 여러 마리가 도는 방에는 영역이 필요하다.
   지금은 `groundTop`·`height`와 **PNG에서 직접 잰 기둥 폭**으로 유도한다. →
   `"walkArea": { "x": 96, "y": 292, "w": 744, "h": 56 }`를 발 좌표 기준으로 넣어 달라
   (`walkAreaOf`가 이미 이 필드를 우선 사용하므로, 넣으면 렌더러 변경 없이 유도가 꺼진다).
3. **`petAnchor` 규약이 안 적혀 있다.** `y + h == groundTop`(앵커 밑변이 지면에 닿음)이 성립하는데
   문서에 없어 추측해야 한다. 한 줄 명시해 달라.

참고(막지는 않음):

- `parallax`는 현재 에셋에서 쓸 수 없다. `seamless: false`이고 레이어 폭이 창과 같아 어느
  레이어든 밀면 빈 가장자리가 드러난다. 값이 죽은 메타데이터로 남는다.
- `animation.frames`가 12장 × 960×360 풀 PNG(384KB)인데 프레임 간 실제 차이는 ~145픽셀이고
  변화 영역이 bbox `(64,100)-(819,278)` 하나로 묶인다. dirty-rect 크롭이나 반딧불이 좌표
  리스트로 바꾸면 훨씬 가벼워진다.

### 진입점 결함 (2026-09-03 수정)

첫 구현에서 펫룸에 들어갈 수가 없었다. 원인은 **트레이 아이콘이 `nativeImage.createEmpty()`**
였던 것이다. 트레이 항목은 폭 16px로 존재하지만 아무것도 그려지지 않아 메뉴 바에서 보이지
않는다(`tray.getBounds()`로 실측). 남은 진입점인 오버레이 우클릭은 **펫을 찾아 우클릭해야
한다는 것을 알아야만** 쓸 수 있어 발견 가능한 길이 사실상 0이었다.

조치 두 가지:

1. `tools/tray-icon.py`로 실제 트레이 아이콘을 그려 넣었다(macOS `Template` 규칙 — 알파만
   읽혀 메뉴 바 색에 자동으로 맞춰진다).
2. **앱 메뉴 `펫`** 을 추가했다 — `펫룸`(⌘1) · `정보`(⌘2) · `설정`(⌘3) · `업적`(⌘4).
   트레이가 붐벼 가려지거나 오버레이를 못 찾아도 항상 같은 자리에 있고 단축키가 붙는다.

미해결: 오버레이 펫에 실제 우클릭이 전달되는지는 확인하지 못했다. `#sprite`에 걸린
`-webkit-app-region: drag`가 마우스 이벤트를 삼킬 가능성이 있는데, 실제 OS 입력 주입이
접근성 권한 때문에 앱에 닿지 않아 실험이 결론에 이르지 못했다. 합성 이벤트로는 메뉴가 정상
동작한다. 아래 Open questions 참조.

## Open questions

- 배경 계약 결함 1·2·3의 수정 여부와 시점 — 배경 소유자 결정 대기. 수정 전까지는 렌더러가
  실측 상수로 유도한다.
- 오버레이 펫에 **실제 우클릭이 전달되는가.** `#sprite`의 `-webkit-app-region: drag`가 마우스
  이벤트를 삼키면 우클릭 메뉴도 좌클릭 반응도 동작하지 않는다(이 경우 펫룸 이전부터 있던
  결함이다). 실제 입력 주입에 접근성 권한이 필요해 확인하지 못했다. 사용자가 오버레이 펫을
  우클릭했을 때 메뉴가 뜨는지 알려 주면 확정된다.
- `@pet/room`이 들고 있는 보유 펫 명부의 최종 소유 도메인. `collection` 담당자가 오면 그쪽으로
  옮긴다(이름 선점을 피하려고 `@pet/room`에 임시로 두었다).
