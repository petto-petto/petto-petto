# Feature specification: meta 업적 줄 — 티어 제거 · 배지 · 달성 시각 · 보상 직접 받기

This specification owns the product what and why. The related implementation
plan owns the technical how.

## Status

Approved (요청자 지시와 선택, 2026-10-05)

## Owner

성훈 (`meta` 도메인 담당, 요청자)

## Problem and user outcome

업적 화면의 한 줄에 읽을 것이 많고, 정작 업적마다의 개성과 달성 기록은 없다.

- 이름 옆의 `브론즈 · 실버 · 골드` 티어가 복잡하다. 단계는 이름의 Ⅰ·Ⅱ·Ⅲ 과 목표값이 이미
  말해 준다.
- 줄 맨 앞은 모든 업적이 같은 자물쇠나 메달이다. 어떤 업적인지는 글을 읽어야 안다.
- 달성한 업적에 `달성`이라고만 적혀 있어 언제 달성했는지 알 수 없다.
- 보상 칩이 달성 조건과 진행률 사이에 끼어 있어 "무엇을 얼마나 했나"가 끊겨 읽힌다.
- 보상이 달성하는 순간 저절로 들어와서, 사용자는 무엇을 받았는지 모르고 지나간다.

사용자는 목록을 훑으며 그림으로 업적을 구분하고, 달성한 업적에서는 달성한 때를 보고, 보상은
그 업적 칸에서 직접 받는다.

## Scope

- 업적의 티어를 없앤다. 정의와 화면 어디에도 남기지 않는다.
- 업적 22개 각각에 고유한 16×16 픽셀 배지를 두고, 줄 맨 앞(예전 자물쇠 자리)에 2배로 그린다.
  요청자가 "22개 전부", "픽셀 아이콘"을 골랐다.
- 달성한 업적 줄에 달성 시각을 표시한다.
- 진행률의 큰 수는 자릿수를 끊어 적는다(`800,000 / 1,000,000`).
- 잠긴 업적의 배지도 자기 색으로 그린다. 요청자가 "전부 갈색이라 단조롭다"고 했다.
- 보상을 줄의 오른쪽 위로 옮긴다. 왼쪽은 이름 → 조건 → 진행률이 끊기지 않고 이어진다.
  (처음에는 줄의 맨 아래로 옮겼다가 요청자 의견으로 오른쪽 위가 됐다.)
- 분류와 보상의 모양을 서로 다르게 한다. 요청자가 "전부 같은 사각형이라 구분이 안 된다"고
  했다.
- 보상은 달성해도 자동으로 지급하지 않는다. 사용자가 그 업적 칸의 `보상 받기` 버튼을 눌러
  받는다(요청자 지시, 2026-10-05). 제품 기획서 7.5의 자동 지급을 대체한다.

## Non-goals

- 칭호 자체의 그림. 칭호는 지금처럼 글자다.
- 프로필 카드나 펫룸에 배지를 보여 주는 일.
- 배지 애니메이션, 달성 순간의 연출.
- 업적 이름의 Ⅰ·Ⅱ·Ⅲ 과 목표값, 보상의 변경.

## Domain rules

1. 업적마다 배지가 하나 있고 서로 다른 그림이다. 업적 정의와 배지는 일대일이다.
2. 배지가 아직 없는 업적(새로 추가한 정의)은 기본 배지로 보인다. 화면이 깨지지 않는다.
3. 달성한 업적의 배지는 색 그대로이고 칸에 금색 띠를 두른다. 잠긴 업적의 배지는 자기 색을
   절반 농도로 흐리게 그린다.
4. 달성 전의 히든 업적은 자기 배지 대신 물음표 배지를 보여 준다. 그림이 조건을 미리 알려
   주면 안 된다. 달성하면 자기 배지가 나온다.
5. 달성 시각은 사용자의 로컬 시간 `YYYY-MM-DD HH:MM` 이다. 달성하지 않은 업적에는 없다.
6. 배지의 색은 디자인 가이드의 토큰만 쓴다. 에픽 보라는 에픽 등급을 뜻하는 배지에만 쓴다.
7. 상태(달성 · 잠김 · 히든)는 색에만 기대지 않고 글자(달성 시각, 진행률, 칸의 설명)로도
   구분된다.
8. 판정은 보상을 지급하지 않는다. 달성하면 받을 보상이 생기고, 재화 · 칭호 · 트로피는
   사용자가 `보상 받기`를 누른 때에 들어온다.
9. 받지 않은 보상은 사라지지 않는다. 앱을 다시 켜도 받을 수 있다.
10. 같은 업적의 보상은 몇 번을 눌러도 한 번만 들어온다.
11. 받다가 실패한 보상은 받을 보상으로 남고, 줄에 까닭을 보여 주며, 다시 누르면 지급된다.
    실패해도 달성은 취소되지 않는다.
12. 달성하지 않은 업적과 없는 업적의 보상은 받을 수 없다.
13. 첫 칭호의 자동 장착은 칭호를 받는 때에 일어난다.
14. 업적 화면은 받을 보상이 남은 업적 수를 필터와 무관하게 전체 기준으로 보여 준다.
15. 달성 말풍선은 무엇을 받았는지가 아니라 받으러 오라고 말한다(`첫 만남 달성! 보상을 받아 가!`).
16. 받은 업적 보상은 받은 뒤의 판정부터 누적 토큰에 들어간다. 받지 않은 보상은 누적 토큰과
    토큰 마일스톤에 들어가지 않는다.
17. 분류는 상자 없는 작은 글자다. 보상은 종류마다 모양이 다르다 — 토큰은 동전 아이콘과 굵은
    숫자, 칭호는 리본 아이콘과 리본 띠, 트로피는 잔 아이콘과 글자.
18. 보상의 눈에 보이는 글자는 값만 적는다(`100,000`, `초보 조련사`). 종류는 아이콘이 말하고,
    온전한 문구(`토큰 100,000`, `칭호 초보 조련사`)는 툴팁과 접근성 이름에 둔다.
19. 가려진 히든 줄의 보상은 종류도 알려 주지 않고 `? ? ?` 만 보인다.
20. 달성한 줄은 진행 막대 대신 `✓ 달성 YYYY-MM-DD HH:MM` 을 적는다.
21. 보상 받기 버튼과 받았다는 표시는 보상 바로 아래에 있다.

## Acceptance criteria

- 업적 정의와 화면 모델에 티어가 없다. — 계약 테스트
- 22개 업적 id 가 배지 목록과 일치하고, 모든 배지가 16×16 이며 팔레트 안의 글자만 쓰고 서로
  다르다. — 계약 테스트
- 가려진 히든 업적의 줄은 물음표 배지를, 달성한 뒤에는 자기 배지를 싣는다. — 계약 테스트
- 배지를 그리지 않은 새 정의는 기본 배지로 나온다. — 계약 테스트
- 달성한 업적의 줄에 달성 시각이 있고 달성하지 않은 줄에는 없다. — 계약 테스트
- 실제 패널 화면에서 배지가 선명한 픽셀로 보이고 달성 줄에 `달성 YYYY-MM-DD HH:MM` 이
  보인다. — 임시 Electron 창으로 업적 화면을 캡처해 확인
- 달성만 한 상태에서는 재화 · 칭호 · 트로피가 들어오지 않는다. 받기를 누르면 들어오고, 다시
  눌러도 한 번뿐이다. — 계약 테스트
- 받기가 실패하면 줄이 받을 수 있는 상태로 남고 까닭이 보이며, 다시 누르면 지급된다. — 계약
  테스트
- 받지 않은 보상은 재실행 뒤에도 받을 수 있고, 받은 보상은 재실행 뒤에 다시 지급되지 않는다.
  — 계약 테스트
- 보상 받기 채널이 문자열이 아닌 값을 거절하고, 달성하지 않은 업적에는 까닭을 돌려준다. —
  계약 테스트
- 실제 패널에서 `보상 받기`를 누르면 잔액이 오르고 줄이 `✓ 받음`으로 바뀌며 받을 보상 수가
  하나 준다. — 임시 Electron 창에서 버튼을 눌러 확인
- 화면 모델의 보상이 종류 · 보이는 글자 · 설명을 싣고, 종류마다 8×8 아이콘이 있으며 서로
  다르다. — 계약 테스트
- 실제 패널에서 보상이 줄의 오른쪽 위에 종류별 모양으로 보이고 분류가 상자 없이 보인다. —
  임시 Electron 창 캡처

## Edge and error cases

- 캔버스를 쓸 수 없는 환경에서는 배지 칸이 비고 나머지 줄은 그대로 보인다.
- 저장된 달성 시각이 없는 줄은 달성하지 않은 줄이다. 시각을 지어내지 않는다.

## API and data impact

- 업적 정의(`achievements.json`)와 `AchievementDefinition` 에서 `tier` 를 없앤다. 저장되는
  값이 아니라 저장 형식은 그대로다.
- 업적 화면 모델의 줄에서 `tier` 가 빠지고 `badge` · `unlockedAtLabel` 이 생긴다. 화면
  모델에 배지 팔레트가 실린다.
- 판정 함수가 보상을 지급하지 않게 되고, 업적 하나의 보상을 받는 함수가 따로 생긴다. 판정
  결과의 `pendingRewards` 는 `claimableRewards` 가 된다.
- 화면 모델의 `rewardPending` 이 `rewardState`(잠김 · 받을 수 있음 · 받음)와 `rewardError`,
  화면 전체의 `claimableCount` 로 바뀐다.
- 화면 모델의 보상이 문자열에서 `{ 종류, 보이는 글자, 설명 }` 으로 바뀌고, 보상 종류 아이콘이
  실린다.
- IPC 채널 `achievements:claim` 과 preload 의 `claimAchievement` 가 생긴다.
- 저장 형식은 그대로다. 받지 않은 보상은 이미 있던 "지급 대기" 기록으로 남는다. 예전
  버전에서 지급에 실패해 대기 중이던 보상은 받을 보상으로 보인다.
- 테이블 변경은 없다. 달성 시각은 이미 저장하고 있던 값이다.
