# Skill and Harness Authoring

Before creating or changing a Skill or harness document, read `.harness/references/writing-great-skills/SKILL.md` and `.harness/references/writing-great-skills/GLOSSARY.md` in full.

Keep every instruction and Skill body in its canonical location. Prefer progressive disclosure, one source for each meaning, and remove duplication, stale sediment, and no-op guidance before adding material.

For every Skill change, record a baseline scenario, add a failing contract or behavior check, make the smallest Skill-body change, and rerun the check successfully. Use descriptions with explicit triggers and leading words; each procedure must have observable completion criteria.

Changes to shared harness behavior require fresh evidence, contract verification, and a `CHANGELOG.md` update.
