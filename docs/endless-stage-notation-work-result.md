# 누적 스테이지 표기 작업 결과

## Track and Seed

Standard. 2026-10-07 요청자가 `8-3 → 9-1` 표기를 승인했다.
Seed: [승인 명세](../.harness/specs/features/2026-10-07-endless-stage-notation.md).
성공 기준은 첫 24전투의 표기를 유지하면서 누적 구간을 표시하고, 전환 시 실제 적과
번호를 맞추며, 적 미리보기와 실제 진행 번호를 분리하는 것이다.
XP 곡선, 전투 규칙, 아트 순환, 저장 형식 변경은 범위 밖이다.

## Explorer

HUD는 적의 색·크기를 번호로 사용해 24전투마다 1-1로 돌아갔다.
엔진 stage는 계속 증가하며 `visibleEnemyStage`가 처치·대기·등장의 시점을 이미 구분한다.
변경 범위는 scene의 라벨 함수, HUD 연결, 긴 번호의 CSS와 집중 테스트다.

## Planner

1. 누적 번호·전환·미리보기 분리의 실패 테스트를 작성한다.
2. 화면에 보이는 stage를 세 전투씩 묶어 누적 구간과 구간 내 번호를 계산한다.
3. HUD에 연결하고 긴 번호를 말줄임 처리하며 전체 번호를 title과 접근성 이름에 제공한다.
4. 집중 테스트, UI 빌드 및 공유 Electron gate를 실행하고 diff를 리뷰한다.

## Implementer

기존 색·크기 기반 동작에서 새 행동 테스트 세 개가 실패하는 것을 확인했다.
라벨은 `visibleEnemyStage`에서 계산하고 구간 번호에 쉼표를 적용했다.
XP와 성장 계산은 변경하지 않았다.

## XP 확인

실제 앱은 50개의 레벨 비용을 제공하며 비용은 `10 + floor(level / 2)`다.
전투는 각 구간에서 2·2·3레벨 비용을 합산한다.
비용표 이후에는 마지막 35 XP를 계속 사용하므로 8구간 이후 비용은 70·70·105로 반복한다.
진행 함수를 실행해 8-1부터 10-3까지의 실제 요구량을 확인했다.
스테이지 번호 변경만으로는 후반 XP 증가가 새로 생기지 않는다.

## Verifier

집중 테스트는 1·3·4·24·25·48·49·300·3,000·엔진 상한,
첫 24전투 호환, 처치·대기·등장의 경계, 미리보기 분리를 확인한다.
실행 명령은 `node --experimental-strip-types --test packages/pet-battle/test/battle-scene.contract.test.ts`,
`npm run build:ui --workspace @pet/battle`, `bash .harness/scripts/verify-electron.sh`다.
최종 실행 결과는 작업 응답의 최신 출력에 기록한다.
실제 창에서 긴 번호의 시각 확인은 수행하지 않았으며 그 항목은 검증 공백으로 남는다.

## Reviewer

별도 리뷰 단계에서 계산식, 경계 테스트, 기존 아트 선택과의 분리를 확인했다.
기존 색·크기 필드는 다른 화면 동작에 사용되므로 유지했다.
저장 상태를 추가하지 않아 기존 진행 복구와 펫 교체가 같은 stage 계약을 따른다.
코드 지적 없음. 시각 검증 공백은 위에 명시한다.

## Evolve

None. Harness 변경 없음.
