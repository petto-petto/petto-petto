# 무한 진행 스테이지 표기 조사 및 설계

조사일: 2026-10-07. 상태: 제안. 이번 작업은 자료조사와 설계이며 앱 구현은 별도다.

## 결론

현재 두 자리 구조를 유지하면서 앞 번호를 계속 올리는 `STAGE 9-1`을 권장한다.

```text
STAGE 8-1 → STAGE 8-2 → STAGE 8-3 → STAGE 9-1 → STAGE 9-2
```

앞 숫자는 누적 진행 구간, 뒤 숫자는 그 구간의 세 전투다.
적의 색과 배경이 반복되어도 구간 번호는 계속 증가한다.
새로운 구간은 새로운 아트나 맵을 뜻하지 않는다.
첫 24전투의 기존 번호는 유지하면서 문제의 경계만 자연스럽게 확장한다.

## 권장안의 화면 규칙

- 기존 HUD 위치에서 `STAGE {누적 구간}-{전투}`만 표시한다.
- 1구간 = 세 전투이며 뒤 번호는 `1 → 2 → 3`이다.
- 앞 번호는 `1 → 2 → … → 8 → 9 → …`로 증가한다.
- 기존 색별 소·중·대 순서와 24전투마다의 아트 반복은 유지한다.
- 두 번째 색 순환의 첫 빨간 소형 적은 `STAGE 9-1`이다.
- 회차 배지, 새 보상, 새 난이도, 추가 알림은 도입하지 않는다.
- Isamanru 및 기존 글자 크기·색·픽셀 디자인을 유지한다.
- 쉼표는 구간 번호에만 사용한다. 예: `STAGE 1,000-3`.
- `K`, `M`, 지수 표기로 번호를 줄이지 않는다. 인접 구간을 구별해야 한다.
- 긴 번호에서도 HP 바와 버튼을 가리지 않도록 번호 영역의 최대 폭을 제한한다.
  공간 부족 시 말줄임을 허용하되 title과 접근성 이름에는 전체 번호를 제공한다.
  실제 구현에서 최소 창·큰 번호를 확인하며 글자 크기를 임의로 줄이지 않는다.

## 기존 코드에서 확인한 상태

- `packages/pet-battle/src/ui/battle-overlay.ts`는 `enemyColorStage`와
  `enemySizeStage`를 합쳐 현재 라벨을 만든다. 표시가 적의 외형에 묶여 있는 원인이다.
- `packages/pet-battle/src/view/scene.ts`는 색을 여덟 가지로, 크기를 세 가지로 순환한다.
- 엔진의 `pet.stage`는 정복 후 계속 증가하며 현재 상한은 `0xffff_ffff`다.
  따라서 현재 현상은 24마다 진행 데이터가 초기화되는 문제가 아니다.
- `visibleEnemyStage`는 처치·대기 때 처치한 stage, 등장 때 다음 stage를 반환한다.
  라벨도 화면의 실제 적과 같은 시점의 번호를 사용해야 한다.
- 엔진이 전투 중 미리보기의 색·크기를 변경해도 실제 누적 번호는 바뀌지 않아야 한다.
- 현재 상한은 구현상 유한하다. 이번 표기 설계에서 저장 타입과 상한 정책은 확장하지 않는다.

## 구현 시 사용할 매핑

저장된 누적 전투 번호 `s`를 그대로 사용한다. 별도 회차나 구간 상태는 저장하지 않는다.

```text
누적 구간 = floor((s - 1) / 3) + 1
전투 번호 = ((s - 1) % 3) + 1
```

| 누적 전투 s | 기존 표기 | 제안 표기 | 적 외형             |
| ----------- | --------- | --------- | ------------------- |
| 1           | 1-1       | 1-1       | 첫 색 · 소형        |
| 3           | 1-3       | 1-3       | 첫 색 · 대형        |
| 4           | 2-1       | 2-1       | 두 번째 색 · 소형   |
| 24          | 8-3       | 8-3       | 여덟 번째 색 · 대형 |
| 25          | 1-1       | 9-1       | 첫 색 · 소형        |
| 48          | 8-3       | 16-3      | 여덟 번째 색 · 대형 |
| 49          | 1-1       | 17-1      | 첫 색 · 소형        |
| 300         | 4-3       | 100-3     | 네 번째 색 · 대형   |

새 번호는 기존 `stage`에서 계산하므로 데이터 이전 없이 이미 진행한 위치를 바로 복구한다.
예를 들어 누적 49전투에 있는 펫은 업데이트 후 `17-1`로 보인다.
펫별 진행 저장과 펫 교체 규칙은 그대로 따른다.

## 검증 설계

구현 승인 후 다음을 확인한다.

1. 1·3·4·24·25·48·49·300 및 엔진 상한의 매핑.
2. 첫 24전투의 기존 표시 유지 및 24→25에서 8-3→9-1 전환.
3. 처치·대기 중 8-3 유지, 다음 적 등장부터 9-1 표시.
4. 색·크기 미리보기로 스테이지 번호가 바뀌지 않음.
5. 높은 stage의 저장·재시작·펫 교체에서도 정확한 표시 복구.
6. 최소·기본 창에서 STAGE 9-1, 100-3, 1,000-3, 상한 번호의 HUD 배치.
7. 기존 무작위 응원, 아트 순환, 성장 및 정복 동작의 회귀 검증.

승인할 제품 결정은 권장안 `STAGE 8-3 → 9-1` 채택이다.
승인 명세를 Seed로 한 구현 단계는 그 승인 이후에 시작한다.
