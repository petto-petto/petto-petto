## Independent Review

같은 세션에서 Reviewer 계약으로 diff를 다시 읽었다. 구현자와 다른 사람(또는 별도 리뷰 에이전트)의 검토는 PR에서 받는다. 반영한 지적:

- preload 가 `shell`도 노출하자 앱 테스트 하네스가 마지막으로 노출된 객체를 화면 bridge 로 잡았다 → 이름으로 골라 잡는다.
- 상단 바 빨간 점 색을 새로 만들지 않고 `design.md` 오류 색(`#F08A8A`)을 `--petto-alert`로 썼다.

## 남은 일과 후속 후보

- `@pet/core`의 머리말은 공용 어휘 추가에 팀 합의를 요구한다. 그래서 축약 함수와 틀은 core 가 아니라 새 패키지 `@pet/shell`에 두었다. 패키지를 둘지는 PR에서 팀이 정한다.
- 상단 바 높이 32px는 앱(`SHELL_BAR_HEIGHT`)과 CSS(`--petto-bar-height`) 두 곳에 있다. 둘이 어긋나면 화면 아래가 잘린다. 주석으로 묶어 두었다.

## Evolve

새 반복 마찰 없음. 1·2단계에 기록한 가짜 DOM 하네스 후보가 다시 한 번 나왔다(preload 가 객체를 하나 더 노출하자 하네스가 틀린 객체를 잡음). 세 번째 발생이라 `$harness-improve` 제안 근거가 충분하다. 하네스 변경은 승인이 필요하므로 PR 설명에 후보로 적는다.
