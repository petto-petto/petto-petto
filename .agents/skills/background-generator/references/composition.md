# 구도 규칙

캔버스 크기는 요청마다 받는다(기본 280x120). 아래 수치는 **기준 높이 120px**
기준이고, 실제로는 `bgcore.geom()`이 전부 높이 비례로 계산한다 — 손으로 고칠
때도 절대 px이 아니라 "높이의 몇 %"로 생각한다.

**카메라는 사이드뷰 + 바닥 깊이로 고정이다.** 소실점 투시(3/4 탑다운, 1점 투시)로
그리지 않는다 — 펫이 32x32 정면 스프라이트라 카메라가 안 맞는다. 대신 지면은
위로 갈수록 멀어지는 면으로 다루고, 깊이는 `quality.md` §4의 여섯 단서로 만든다.

280x120은 넓고 낮다(가로세로 2.33:1). 세로가 120px뿐이라 **수평 띠 배분이
구도의 전부**다. 펫은 32x32니까 화면 높이의 27%를 차지한다 — 배경이 조금만
번잡해도 펫이 사라진다.

## 1. 세로 배분 (야외 기준)

```
y   0 ─────────────────────────────  상단 여백/캐노피   0~12
       하늘·안개                      12~46
y  46 ─── far 능선 ────────────────   원경              46~76
y  76 ─── mid 수목선 ──────────────   중경              76~94
y  94 ═══ groundTop ═══════════════   지면 밴드          94~120
y 120 ─────────────────────────────
```

- **지면 밴드는 14px 이상.** 그보다 얇으면 펫이 선이 아니라 모서리에 선다.
- **펫 박스는 지면 위 32px** — 위 그림에서 y 62~94. 이 구간의 배경은
  `mid` 색이어야 한다. 지면 밴드(가장 어두움)가 펫 뒤로 올라오면
  `#2C2438` 외곽선과 명암비가 3.0 아래로 떨어진다.
- 상단 12px은 오버레이 UI(체력바 등)가 걸치기 쉬우니 정보가 없는 영역으로 둔다.

**밝은 프리셋(`sky`)은 예외다.** 펫 뒤를 열린 하늘로 두는 게 정답이라
수목선을 펫 박스 아래(`groundTop-8`)로 내린다. 이때 백드롭이 단색 하늘이라
국소대비·명암비가 둘 다 여유 있게 통과한다.

## 2. 실내 배분

```
y   0 ─────────────────  벽(어두움)         0~54
y  54 ─── 징두리 상단 ──  wainscot(밝음)     54~88
y  88 ═══ groundTop ═══  마루               88~120
```

실내에는 공기원근이 없다. 깊이는 **가림 순서**(벽 → 벽걸이 → 가구 → 전경 소품)와
**레이어 간 명도차**로만 만든다. 그리고 실내에서 게이트가 걸리는 지점은 거의
항상 하나다 — **펫 뒤가 어두운 벽**. 펫 높이 구간에는 반드시 밝은 징두리를 깐다
(`wood.3`~`wood.4`). 어두운 벽 그대로 두면 명암비 1.4:1이 나온다.

## 3. 가로 배분

- **펫 박스(기본 x 124~156)에는 아무것도 놓지 않는다.** 스탬프·실루엣 경계선이
  이 구간을 지나가면 국소대비 게이트에서 걸린다.
- 좌우 대칭을 피한다. 큰 요소는 한쪽에 몰고 반대쪽은 작은 것 여럿으로 받는다.
- 화면 밖으로 잘리는 요소를 최소 하나 둔다(프레이밍 거목, 잘린 구름). 280px
  안에 모든 게 온전히 들어오면 "세트장"처럼 읽힌다.

## 4. 레이어에 무엇을 넣나

| 레이어 | parallax | 넣는 것 | 색 |
| --- | --- | --- | --- |
| `sky` | 0.0 | 그라데이션, 구름, 광선, (실내)벽·마루 | `sky` 램프 전체 |
| `far` | 0.25 | 능선·캐노피, 뒤쪽 나무, (실내)벽걸이 | `far` 램프 1~2단만 |
| `mid` | 0.55 | 수목선, 중경 나무·덤불, (실내)가구 | `mid` 램프 1~2단 |
| `near` | 1.0 | 지면 밴드, 풀·꽃·바위, 프레이밍 기둥, 비네트 | `near`+`leaf` |

**뒤 레이어일수록 색을 적게 쓴다.** far가 near보다 색이 많으면 원경이 앞으로
튀어나온다. 램프 인덱스도 뒤로 갈수록 좁게 쓴다(far는 2단, near는 4단).

## 5. 게이트가 걸릴 때 실제 해법

| FAIL | 원인 | 고치는 법 |
| --- | --- | --- |
| `{layer}: 뒤와 명도차` | 앞뒤 레이어가 같은 명도 | 앞 레이어 램프 인덱스를 ±2. 밝은 하늘 프리셋에서 `far.1`은 하늘과 겹친다 → `far.0`. 중앙값 기준이라 소품 하나만 바꿔도 잘 움직인다 |
| 하늘색과의 거리 증가 | 근경이 원경보다 하늘색에 가깝다 | 근경을 어둡게/채도 높게. 지면 재질을 바꿨다면 램프를 `wood`→`near`로 |
| 레이어 색 상한 | 스탬프를 너무 많이 얹음 | 스탬프 하나를 빼거나 `shade`를 맞춰 색을 재사용. 바위(wood 3색)가 제일 비싸다 |
| 총 색 **하한** | 램프 단계를 안 씀 | `foliage`/`ground_plane`의 톤 범위를 넓힌다. 색을 늘리는 게 아니라 **단계를 쓴다** |
| 램프 N단 이상 | 한 램프를 1~2단만 씀 | 그 램프로 칠한 것에 3톤을 넣는다. 프레이밍 기둥에 반사광 한 줄만 넣어도 통과 |
| 구조적 엣지 <15% | 큰 면이 단색 | `band`→`ground_plane`, `fringe`→`foliage`, 평면 벽→`panel` |
| top1 / 최대 블롭 | 하늘·지면·벽이 통짜 | 그라데이션 단 수를 늘리거나 `panel`의 `boardH`·`jointEvery`를 줄인다 |
| 명도 구간 <7 | 밝은 쪽 또는 어두운 쪽이 통째로 빔 | 밝은 요소(창·빛 웅덩이) 또는 어두운 요소(그림자 띠·수목 그늘)를 **면적을 갖게** 넣는다 |
| 매스 3톤 <80% | 단색 덩어리 존재 | `--verbose`로 어느 매스인지 본다. 대개 스탬프 프레임이나 그라데이션 띠 |
| 광원 일관성 <75% | 아래가 더 밝은 덩어리 | 그 덩어리의 톤을 뒤집는다. 배경면은 검사에서 빠지므로 지면은 해당 없음 |
| 깊이 단서 부족 | 겹침·명도계단만 있음 | `scatter_depth`의 scale 범위, `ground_plane`, `contact_shadow`를 추가 |
| 지면 압축 | 부등호가 반대로 나옴 | `ground_plane`의 `cell`을 [작은값, 큰값] 순서로 — 먼 쪽이 촘촘해야 한다 |
| 고립픽셀 ≤6% | speckle 밀도 과다 | `speckle.density`를 0.03 이하로. 그라데이션 bayer 디더는 여기 안 걸린다 |
| near가 펫박스 비움 | 전경 요소가 중앙에 있음 | 그 스탬프를 x 124~156 밖으로 |

## 6. 명암 — 모든 덩어리는 3톤이다

광원은 좌상단 고정(캐릭터 스킬과 동일). 200px 이상 덩어리는 예외 없이 세 단을
쓴다: **베이스 / 우하단 그림자 / 좌상단 하이라이트.** 단색 덩어리 하나가
"평평하다"는 인상의 절반을 만든다.

- 큰 매스(잎더미·수목선)는 `foliage`가 로브마다 자동으로 3톤을 넣는다.
- `rect`/`fill`/`fringe`로 만든 밋밋한 매스는 레이어 마지막에 `autoshade`.
- 스탬프는 legend 자체를 3톤으로 만든다(`stamps.md` 참고).
- 바닥에 닿는 것에는 `contact_shadow`. 이게 없으면 물체가 떠 보인다.
- 화면을 가로지르는 면(지면·벽·하늘)은 형태가 아니라 배경면이라 광원 검사에서
  빠진다. 대신 **먼 쪽이 밝아야** 한다(깊이).

## 7. 캐릭터 자리 — 기준은 `quality.md` §6 하나뿐이다

**여기에 규칙을 적지 않는다.** 예전에 이 문서는 "펫 박스를 비워라"라고 하고
`quality.md`는 "그 게이트를 없앴다"라고 해서 서로 충돌했고, 실제로 그걸 따른
결과 화면 중앙에 구멍이 뚫렸다. 기준이 두 곳에 있으면 반드시 갈라진다.

현재 기준: **배경은 캐릭터 자리를 비워 주지 않는다.** 가독성은 게임 쪽 발광
이펙트가 맡는다. `petAnchor`는 좌표 정보로만 쓰인다. 되돌려야 할 상황과 그때
필요한 수치는 `quality.md` §6에 있다.

시각 검수에서는 다른 것을 본다 — "캐릭터가 설 위치와 발판이 한눈에 읽히는가"
(`visual_review` 항목). 비우라는 뜻이 아니라 **어디에 서는지 보이라**는 뜻이다.

## 8. 자주 하는 실수

1. **스탬프를 뒤 레이어에 놓고 앞 레이어 채우기로 덮어버린다.** far의 나무는
   mid 수목선보다 위(작은 y)에 서야 보인다. `y = mid_base + 6` 정도.
2. **나무 색이 그 레이어 배경색과 같다.** `leaf.2`와 `mid.1`이 같은 값인
   프리셋이 있다. mid 레이어의 나무에는 `shade: 1`을 준다.
3. **짧은 주기의 사인으로 잎을 그린다.** 픽셀 단위에서 톱니가 된다. 가까운
   잎더미는 `hills`가 아니라 `fringe`(겹친 반원 로브)로 그린다.
4. **지면 speckle을 뿌려 "질감"을 낸다.** 1px 난수는 질감이 아니라 노이즈고
   고립픽셀 게이트에 걸린다. 구조가 필요하면 `ground_plane`·`panel`·`foliage`를
   쓴다. `texture`는 density 0.03 이하의 보조용이다.
5. **지면을 단색 밴드로 둔다.** 개선 전 산출물의 지면 구간 엣지 밀도가 4~7%였다
   — 화면 1/4이 통짜 슬래브였다는 뜻이다. 지면은 `band`가 아니라 `ground_plane`.
6. **깊이를 레이어 순서만으로 낸다.** 겹침 하나로는 깊이 단서 1개다. 크기
   기울기(`scatter_depth`의 scale 범위)와 지면 압축을 같이 넣어야 4개를 넘긴다.
