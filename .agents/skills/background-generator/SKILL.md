# Background Generator

배경 한 장을 `sky / far / mid / near` 4레이어로 굽는다. 그림은 손으로 찍지 않는다 —
`scene.json`(프리미티브 + 스탬프)을 쓰고 Pillow가 렌더한다. 색은 항상 프리셋 램프
참조(`mid.2`)로 쓴다. 프리셋만 바꾸면 같은 구도가 다른 분위기로 다시 구워진다.

## Pillow dependency gate

이 스킬의 모든 절차보다 먼저 다음을 실행한다.

```bash
python3 -c 'import PIL'
```

실패하면 즉시 중단한다. **Pillow is required. Do not run any script, render, verify, or install Pillow.** Pillow가 준비되기 전에는 이 스킬을 사용할 수 없다고 보고한다.

**카메라는 사이드뷰 + 바닥 깊이로 고정이다.** 소실점은 없다. 깊이는 크기 기울기·
겹침·명도 계단·대기 원근·지면 압축·접지 그림자 여섯 단서로 만들고, `bg_check.py`가
실측한다 — 야외 4개, 실내 3개가 하한이다.

**성공 기준은 전부 숫자다.** 지표·기준값·출처는 `references/quality.md`. 그리기 전에
한 번 읽는다.

**그림의 좋고 나쁨은 사용자가 판단한다.** 게이트가 PASS여도 완성이 아니고, 자체
판단으로 미학적 재작업을 반복하지 않는다 — §5-A.

**캔버스 크기는 고정이 아니다.** 기본 280x120, `--size WxH`로 받는다. 구도 상수와
절대 px 게이트는 높이에 비례해 스케일된다. 권장 높이 80~360px, 최소 96x64
(`quality.md` §5).

**펫 가독성은 게이트가 아니다.** 펫 주변 발광 이펙트를 게임 쪽에서 넣는다.
`petAnchor`는 좌표 정보로만 메타에 남는다.

캐릭터 스킬(`pixel-pet-creator`)과 공유하는 전제:
- 광원은 **좌상단** 고정. 모든 상단 엣지가 밝고 아랫면이 어둡다.
- `#2C2438`은 **캐릭터 외곽선 전용 예약색**이다. 배경에서 3%를 넘기지 않는다.
- 펫 캔버스는 32x32 고정. 배경의 `petAnchor`도 32x32다.

## 0. 먼저 인터뷰 — 모호도 20% 이하까지 (건너뛰지 않는다)

다섯 글자짜리 요청("서재 같은 분위기")에서 소파·난로·담요·사슴뿔을 지어내지 않는다.
그리기 전에 구체성을 **수치로** 재고, 부족하면 묻는다.

```bash
python3 scripts/bg_interview.py template > /tmp/spec.json
# 사용자 요청에서 읽어낸 것을 채운다 (추측한 건 assumed에)
python3 scripts/bg_interview.py score /tmp/spec.json   # 모호도 %
python3 scripts/bg_interview.py next  /tmp/spec.json   # 다음에 물을 것
```

- **모호도 > 20%면 그리지 않는다.**
- 한 번에 **3~4개까지**, 가중치 큰 것부터 묻는다.
- **선택지를 준다.** 공간 종류를 알면 그 공간에 있을 법한 것들을 먼저 제안한다.
- **추론할 수 있는 건 묻지 않는다.** "실내 서재"면 구조는 실내 정면이다.
- 20% 이하가 되면 `bg_interview.py brief`로 장면 브리프를 만들어 **그리기 전에
  한 번 보여주고** 시작한다.
- 물을 수 없으면(무인 실행) 기본값으로 채우고 `assumed`에 적어 결과 보고에 밝힌다.

슬롯표·가중치·질문하는 법은 `references/interview.md`.

## 0-A. 레퍼런스가 있으면 — 먼저 분석한다 (건너뛰지 않는다)

레퍼런스 이미지를 받았거나 프로젝트에 있으면 **실제로 열어 보고** 다섯 축을
정리한다. 표면만 따라가면(“숲이니까 나무”) 공간 구조가 통째로 빠진다.

1. **공간 구조** — 가로형 / 세로형 / 다층형. 지평선 유무, 층 개수
2. **주 피사체와 개수** — 예: 거대 고목 5~6, 이끼 발판 4~5층, 로프 다리 4, 사다리 1
3. **전경·중경·원경** — 각 층에 무엇이 있고 어떻게 구분되나
4. **조명과 색감** — 광원 위치, 밝은 영역, 안개, 그림자의 색조, 주요 색 계열
5. **플레이 여백** — 캐릭터가 설 자리, 발판 가독성, 열린 시야 구간

결과를 `elements.json`으로 남긴다(형식 `references/reference_analysis.md`, 실물
`references/example_elements.json`). **핵심 요소는 5개 이상 뽑는다** — 4개 이하만
반영되면 재생성 트리거다.

**레퍼런스는 참고 대상이지 복제 대상이 아니다.** 공간 구조·요소 종류·조명 방향·
색 계열은 가져오되, 개별 오브젝트의 형태와 배치는 새로 구성한다.

## 0-B. 분위기 확인 — 인터뷰의 일부다

분위기·장소는 §0 슬롯의 '공간 종류'와 '색·톤 방향'이다. 비어 있으면 여기부터
채운다.

> 어떤 분위기로 만들어드릴까요?
> - **숲(forest)** — 안개 낀 정글, 깊은 녹색, 늘어진 덩굴
> - **하늘(sky)** — 맑은 시안 하늘, 밝은 초원, 떠 있는 발판
> - **실내(interior)** — 따뜻한 목재 방, 붉은 벽, 램프 불빛
> 아니면 참고할 이미지가 있으면 주세요. 시간대(낮/노을/밤)나 "○○ 게임 같은"
> 도 괜찮습니다.

**"~~같은 분위기로"가 이미 있으면 묻지 말고 진행한다.** 그 말이 가리키는 프리셋을
`mood` 키워드로 고르고(§1), 무엇으로 해석했는지 결과 보고에 한 줄 적는다.
되물을 수 없으면 `forest`를 쓰고 가정했음을 명시한다.

같이 정할 것:
- **id / slug** — `bg_004` 같은 3자리. "다음 번호로"면:
  `ls apps/desktop/renderer/assets/backgrounds 2>/dev/null | grep -o 'bg_[0-9]\{3\}' | sort -u | tail -1`
- **캔버스 크기**(`--size WxH`) — 추측하지 않는다. 기본은 280x120.
- **좌우 타일링**(`--seamless`) — 가로로 스크롤시킬 배경인지.
- **펫이 설 위치** — 기본은 가로 중앙. 오버레이 UI가 한쪽을 가리면 옮긴다.

## 1. 프리셋을 고른다

```bash
python3 scripts/bg_palette.py list
python3 scripts/bg_palette.py show --preset forest
```

| 프리셋 | layout | 분위기 키워드 | 구조 |
| --- | --- | --- | --- |
| `jungle` | **canopy** | 정글·숲·판타지·이끼·덩굴·고목·다층·탐험 | 다층 수직. 고목·이끼 발판·로프 다리·역광 안개 |
| `forest` | ground | 숲·안개·고요한·습한·수평·산책 | 수평. 잎 벽 + 흙 지면 |
| `sky` | ground | 하늘·맑은·낮·초원·밝은·평화로운 | 수평. 열린 하늘 + 사암 지면 |
| `interior` | interior | 실내·방·아늑한·따뜻한·밤·집·카페 | 정면 벽 + 마루 |
| `cozy_study` | interior | 서재·아늑한·cozy·벽난로·겨울·눈·책 | 정면 벽 + 마루. **`accent`만 한색** |

**`layout`이 구도를 정한다.** `ground`는 지평선과 지면 밴드가 있는 수평 구도,
`canopy`는 지평선이 없는 다층 수직 구도다. 레퍼런스가 세로형/다층형인데 `ground`를
고르면 재생성 트리거 2번에 걸린다.

램프는 `sky far mid near wood leaf accent light` 8종, 각 5단(0=어두움 → 4=밝음).
역할명이 프리셋 공통이라 스탬프가 프리셋을 가리지 않는다.

**따뜻한 실내 vs 차가운 창밖처럼 한 장면 안에서 온도를 대비시킬 때는 `accent`
램프 하나만 반대 온도로 잡는다.** 나머지 7램프를 한 온도로 통일하면 대비를 주는
오브젝트(창·얼음·촛불)만 화면에서 뜬다. `cozy_study`가 이 구조다.

### 맞는 프리셋이 없으면 — 지어내지 말고 만든다

hex 40개를 손으로 쓰지 않는다. 램프 간 중복과 명도 역전이 생긴다.

```bash
python3 scripts/bg_preset_new.py --name snowy_pines \
    --mood "눈,설원,침엽수림,겨울,차가운" --label "눈 덮인 침엽수림" --write
```

키워드에서 지형·시간대·온도를 판정해 8램프 x 5단을 만들고 색상 채점을 미리
계산한다. 예측이 FAIL이면 `--anchors '하늘,원경,중경,전경'`이나 `--terrain`으로
다시 뽑는다.

명도는 주제가 아니라 **구조**가 정한다 — 앵커 명도를 0.84/0.63/0.44/0.20 사다리로
강제하고, 지면(wood) 램프를 가장 어두운 층에 둔다. 레이어 분리와 대기 원근을
동시에 만족시키려면 이 배치가 필요하다.

스캐폴드가 `terrain`에 맞춰 소품을 바꾼다(설원=침엽수, 사막=선인장·바위, 동굴·
화산=첨탑·바위). **중경 잎덩어리는 지형과 무관하게 깔리므로, 동굴·화산이면 그
매스를 암벽으로 바꾸는 손질을 따로 한다** — 스킬의 알려진 한계다.

레퍼런스 이미지가 있으면 이미지에서 뽑는다:

```bash
python3 scripts/bg_palette.py from-image ~/ref/night_town.jpg --k 12 --name night_town
```

**역할 배정(무엇이 sky이고 무엇이 near인지)은 사람이 확인한다.** 확인 후
`references/presets.json`에 붙이고 `kind`를 채운다.

## 2. scene.json 초안을 받는다

```bash
python3 scripts/bg_scaffold.py --preset forest --id bg_004 --slug misty_grove \
    --name "안개 숲" --size 280x120 --root <프로젝트루트> > /tmp/bg_004.json
```

빈 파일에서 시작하지 않는다. `--size`를 바꾸면 수평선·수목선·기둥 폭·스탬프 배율·
뿌리는 개수가 전부 따라 움직인다. **큰 캔버스에 스탬프를 원래 크기로 두지 않는다** —
구조적 엣지가 절반으로 떨어진다(`quality.md` §5).

stderr로 저장 경로와 다음 명령이 나온다. 이 초안을 **고쳐서** 요청에 맞춘다.

## 3. scene.json을 요청에 맞게 고친다

```json
{
  "id": "bg_004", "name": "안개 숲", "preset": "forest",
  "canvas": [280, 120], "seamless": false,
  "horizon": 54, "groundTop": 94,
  "petAnchor": {"x": 124, "y": 62, "w": 32, "h": 32},
  "layers": [
    {"name": "sky",  "z": 0, "parallax": 0.0,  "ops": [...]},
    {"name": "far",  "z": 1, "parallax": 0.25, "ops": [...]},
    {"name": "mid",  "z": 2, "parallax": 0.55, "ops": [...]},
    {"name": "near", "z": 3, "parallax": 1.0,  "ops": [...]}
  ]
}
```

- **정량 성공 기준과 출처 → `references/quality.md`** (먼저 읽는다)
- **게이트끼리 충돌할 때의 구현 규칙 → `references/gate_conflicts.md`**
- **인터뷰 슬롯과 질문법 → `references/interview.md`**
- **레퍼런스 분석과 elements.json → `references/reference_analysis.md`**
- **색상·명도 지침 → `references/color.md`**
- **증상 → 원인 → 처방 → `references/troubleshooting.md`**
- **시각 검수 채점표 → `references/visual_review.md`**
- 구도·레이어 배분·펫 자리 규칙 → `references/composition.md`
- op 목록과 인자 → `references/ops.md`
- 스탬프 목록과 새로 만드는 법 → `references/stamps.md`
- 레이어 메타·패럴랙스 소비 규약 → `references/layers.md`

ops는 **레이어 안에서 쓴 순서대로** 덮인다. 레이어는 z 순서대로 합성된다.

## 4. 렌더한다

```bash
python3 scripts/bg_render.py /tmp/bg_004.json \
    --out-dir <프로젝트루트>/apps/desktop/renderer/assets/backgrounds/bg_004_misty_grove \
    --preview /tmp/bg_004_prev.png --scale 3
```

`--preview`는 검수용이다. 확대본을 에셋으로 저장하지 않는다 — 최종 에셋은 언제나
1배다.

## 5. 검증 게이트 — PASS 전에는 완성이 아니다

```bash
python3 scripts/bg_check.py <out-dir>
python3 scripts/bg_check.py <out-dir> --verbose   # 어긋난 매스까지
```

기준값과 출처는 `references/quality.md`. 아래는 요약이다.

**평탄함**

| 지표 | 기준 | 레퍼런스 실측 |
| --- | --- | --- |
| 총 색 수 | **24~48** (하한도 게이트다) | 24 |
| 레이어당 색 수 | 야외 6~21 / 실내 6~22 | |
| 램프 단계 사용 | 면적 3% 이상 램프는 **3단 이상 실사용** | |
| top1 색 점유 | **≤ 25%** | 8~19% |
| 최대 단색 연결영역 | **≤ 16%** | 1.7~16.8% |
| 구조적 엣지 밀도 | **≥ 15%** | 34~42% |
| 세로 4구간 분포 | 수평선 아래 각각 ≥ 평균×0.45 / 하늘 ≥2% | |
| 가로 4구간 | 각각 ≥ 평균×0.55 | |

**명암**

| 지표 | 기준 |
| --- | --- |
| 명도 10구간 사용 | **≥ 7구간** (각 2% 이상) |
| 매스 3톤 사용 | 200px 이상 매스의 **≥80%** 가 3단 이상 |
| 광원 좌상단 일관성 | 매스의 **≥75%** 가 윗면 > 아랫면 밝기 |

**투시 — 깊이 단서 6종 중 야외 4 / 실내 3**

명도 계단 · 겹침 · 대기원근(야외) · 크기 기울기 · 지면 압축 · 접지 그림자
(`quality.md` §4).

**구조 · 위생**

| 지표 | 기준 |
| --- | --- |
| petAnchor | 좌표가 캔버스 안 |
| 캔버스·레이어 | scene 선언값과 일치, 합성본 알파 255, 3~5장, parallax 단조 증가 |
| 레이어 분리 | 각 레이어가 바로 뒤와 **명도차 중앙값 ≥0.10** |
| 지면 | groundTop 78~106 · 밴드 높이 ≥14px (둘 다 높이 비례) |
| 예약색 | `#2C2438` ≤3% |
| 노이즈 | 고립 픽셀(8이웃) ≤6% |

**FAIL이 나오면 scene.json을 고치고 다시 렌더한다.** `LIMITS` 숫자를 낮춰서
통과시키지 않는다.

- 지표 하나가 걸렸을 때의 처방 → `references/composition.md` §5
- **두 지표가 서로 반대로 움직일 때(near 명도차↔지면 압축, 매스 3톤↔near 명도차,
  명도 10구간↔어두운 실내 톤, 광원 일관성↔반복 면) → `references/gate_conflicts.md`**
- 기준을 정말 바꿔야 하면 `quality.md` §0의 방법으로 실측을 다시 하고 그 문서를
  함께 고친다.

`clearing` op(펫 자리 저대비 구역)은 기본 초안에서 쓰지 않는다. 발광 없는 화면이
생기면 그때 쓴다(`quality.md` §6).

`elements.json`을 out-dir에 그냥 두지 않는다 — `bg_check.py`가 메타 json으로 잘못
잡는다. `<out-dir>/refs/elements.json`에 넣는다.

## 5-A. 사용자 확인 루프 — 미학 판단은 사용자가 한다

**첫 렌더가 나오면 즉시 합성본을 사용자에게 보여주고 판단을 받는다.** 자체 판단으로
"더 예뻐 보이게" 고치는 바퀴를 돌지 않는다. 취향 판단을 대신하면 시간만 늘고
결과는 사용자 기준과 멀어진다.

**내가 고치는 것(결함)** — 사용자에게 묻지 않고 바로 고친다.

- `bg_check.py` FAIL 항목
- `bg_score.py` 80점 미만 또는 재생성 트리거
- `references/troubleshooting.md`에 **이름이 있는 증상**(전봇대·막대사탕·슬래브·
  창백한 화면·파란 열매 등)

**사용자가 정하는 것(취향)** — 반드시 물어본다.

- 밝기·채도·전체 온도가 원하는 "느낌"인가
- 오브젝트의 크기·개수·배치가 적당한가
- 특정 요소(가구·장식·창밖 풍경)의 모양이 의도대로 읽히는가
- 무엇을 더 넣고 무엇을 뺄지

보여주는 시점은 두 곳뿐이다.

```
scene.json -> bg_render -> bg_check/bg_score -> 결함 수정 -> 게이트 PASS
   -> [1] 사용자에게 확대본 제시 + 지적 요청
   -> 지적받은 것만 수정 -> 다시 렌더
   -> [2] 사용자에게 다시 제시
```

제시할 때는 세 줄로 쓴다: **무엇을 넣었는지 / 게이트 결과 / 어디가 마음에 안 드는지
물어보기.** 스스로 고칠지 말지 애매한 것은 고치지 말고 그 줄에 적어 함께 묻는다.

무인 실행이라 물을 수 없을 때만 §5-C의 자기 채점으로 대체한다.

## 5-B. 최종 품질 채점 (100점) — 80점 미만은 통과가 아니다

`bg_check.py`는 "망치지 않았는가", `bg_score.py`는 **"요구한 것을 실제로 만들었는가"**
를 본다. 둘 다 통과해야 한다.

```bash
python3 scripts/bg_elements.py template --structure vertical > /tmp/elements.json
python3 scripts/bg_elements.py ops                       # 쓸 수 있는 op과 용도
python3 scripts/bg_score.py <out-dir> --elements /tmp/elements.json [--prev <이전>]
```

**레퍼런스가 없는 요청에도 `elements.json`을 쓴다.** 사용자가 말한 것을 요소로 옮겨
적으면 된다 — "눈 덮인 침엽수림"이면 침엽수, 눈 쌓인 지면, 원경 산 실루엣, 흩날리는
눈. 그래야 "말한 걸 실제로 만들었는가"를 셀 수 있다.

| 항목 | 배점 | 무엇을 보나 |
| --- | --- | --- |
| 도트 표현 일관성 | **25** | 팔레트 제한(램프 밖 색 ≤0.5%) 10 · 색 수 24~48 8 · 안티앨리어싱 없음 7 |
| 레퍼런스 구도 반영 | **30** | `elements.json`의 핵심 요소가 씬에 실제로 몇 개 있나 |
| 공간감과 레이어 | **20** | 레이어 분리 12 · 3장 이상 4 · 커버리지 4 |
| 색상 및 조명 | **15** | 5항목 각 3점 — `references/color.md` |
| 게임 배경 활용성 | **10** | 전경이 캐릭터 자리를 비움 4 · 발판/경로 3 · 중앙 시야 개방 3 |

### 재생성 트리거 — 하나라도 걸리면 부분 수정 금지

공간 구조부터 새로 구성한다. `bg_score.py`가 자동 판정한다.

1. 핵심 요소가 **4개 이하**만 반영
2. 다층/세로형 레퍼런스인데 **평평한 가로 풍경**으로 생성 (`layout` 불일치)
3. 이전 결과와 구도·주 피사체·색감이 **대부분 동일** (`--prev`로 동일 화소 ≥60%)
4. 도트가 아니라 **매끄러운 디지털 페인팅**처럼 보임 (중간톤 화소 과다)
5. **레이어 구분이 약해** 공간감이 없음 (명도차 0.10 이상 쌍이 2개 미만)

## 5-C. 시각 검수 — 사용자에게 물을 수 없을 때만

무인 실행에서 §5-A를 대신한다. **사용자가 있으면 자기 채점 대신 §5-A로 보여준다.**

```bash
python3 scripts/bg_visual.py sheet <out-dir> --out /tmp/sheet.png --scale 2 [--pet pet.png]
python3 scripts/bg_visual.py form > /tmp/visual.json
# 시트를 실제로 열어 보고 채운다 — 게이트 결과를 근거로 옮겨 적지 않는다
python3 scripts/bg_visual.py verify /tmp/visual.json
```

7개 항목 100점: 레퍼런스 공간 구조 20 · 전경중경원경 분리 15 · 캐릭터/발판 가독성
15 · 색의 선명함 15 · 톤 차이로 생긴 깊이감 15 · 형태와 색의 변화 10 · 도트 표현
충실도 10. 기준은 `references/visual_review.md`.

## 5-D. 최종 통과 판정 — 다섯 조건을 모두 만족해야 완성이다

```bash
python3 scripts/bg_final.py <out-dir> --elements elements.json --visual visual.json \
    [--mode edit] [--prev <이전 out-dir>]
```

| # | 조건 |
| --- | --- |
| 1 | **기술 검사** `bg_check.py` PASS |
| 2 | **시각 품질** 사용자 확인(§5-A) 또는 무인 실행 시 80/100 이상 |
| 3 | **핵심 요소** 이미지에서 육안으로 5개 이상 확인 |
| 4 | **팔레트/톤 요구사항** 사용자가 지정한 색·톤 요구 충족 |
| 5 | **검수 결과 첨부** 실제 합성 PNG를 붙인 검수가 존재 |

**기술 검사만 통과하고 시각 품질이 미달이면 "PASS"로 끝내지 않는다.** 결과 보고에
부족한 영역과 재생성 프롬프트를 함께 낸다.

`--mode edit`은 "구도는 그대로 두고 고쳐 달라"는 요청에 쓴다. '이전과 유사' 재생성
트리거를 끈다.

## 6. 저장 경로

**Electron 런타임 에셋은 반드시 `apps/desktop/renderer/assets/backgrounds/`에 저장한다.**
프로젝트 루트의 `assets/backgrounds/`는 출력 경로로 쓰지 않는다.

```
apps/desktop/renderer/assets/backgrounds/{id}_{slug}/
  scene.json              # 소스 스펙 — 나중 수정은 여기서 시작한다
  refs/elements.json      # 요소 목록 (out-dir 최상단에 두지 않는다)
  {id}.json               # 런타임 메타(레이어·parallax·petAnchor·팔레트)
  {id}_composite.png      # 합성본
  {id}_sky.png  {id}_far.png  {id}_mid.png  {id}_near.png
```

`bg_render.py --out-dir`을 이 Electron 런타임 경로로 주면 별도 export 단계가 없다.
**`scene.json`을 반드시 함께 남긴다.**

## 7. 이미 있는 배경을 고칠 때

PNG를 건드리지 않는다. `scene.json`을 고치고 같은 `--out-dir`로 다시 렌더한다.
색만 바꾸는 요청이면 `preset` 한 줄만 바꾼다. 프리셋 교체 후에는 램프 인덱스가 새
팔레트에서도 분리되는지 `bg_check.py`로 확인한다 — 밝은 프리셋에서 `far.1`은 하늘과
명도가 겹친다.

## 8. 결과 보고 — 항상 네 부분을 포함한다

```
0) 장면 브리프 (인터뷰 결과)
   모호도 6% — 진행 가능
   공간 서재(실내) / 구조 실내 정면 / 크기 560x240
   오브젝트 소파·러그·담요·난로·액자·사슴뿔 장식·창
   조명 난롯불 주광원 / 톤 따듯한 색조
   대비 창밖은 눈 내리는 추위, 방 안은 안락
   (추측으로 채운 것: 캐릭터 자리 = 중앙 바닥)

1) 레퍼런스 분석 요약
   공간 구조 / 주 피사체 / 레이어 / 조명·색감 / 플레이 여백 다섯 줄

2) 실제 생성 프롬프트
   (씬을 어떤 지시로 구성했는지. 핵심 요소를 5개 이상 명시)

3) 품질 검사 점수와 판정
   bg_check.py  PASS (0 failed)
   bg_score.py  100/100  PASS
     도트 25/25 · 구도 30/30 · 공간감 20/20 · 색상 15/15 · 활용성 10/10
   재생성 트리거 0건

3-B) 시각 확인 (합성 PNG 첨부)
   사용자 확인 요청 — 마음에 안 드는 곳을 지적해 주세요
   (무인 실행이면: bg_visual 점수와 항목별 내역)

4) 미달 시 개선 또는 재생성 프롬프트
   ("수치는 통과했지만 그림이 미달"인 경우를 PASS로 보고하지 않는다.)
```

분위기나 크기를 스스로 해석했으면 그 줄을 반드시 넣는다.

## 안 하는 것

- 펫(캐릭터) 스프라이트 생성·수정 — `pixel-pet-creator` / `pixel-pet-editor`.
- **미학 판단을 혼자 하기.** 게이트 PASS 이후의 "더 예쁘게"는 사용자에게 묻는다 — §5-A.
- **사용자에게 안 보여주고 세 바퀴 넘게 고치기.** 결함 수정이 끝나면 바로 제시한다.
- 확대본을 에셋으로 저장하기(`--preview`는 검수용이다).
- 96x64 미만 캔버스 — 4레이어와 지면 밴드가 안 들어간다.
- `#2C2438`을 배경 외곽선으로 쓰기.
- `bg_check.py`의 `LIMITS` 숫자를 통과시키려고 낮추기.
- **서로 충돌하는 두 게이트를 번갈아 땜질하기** — `gate_conflicts.md`의 규칙으로 푼다.
- 모호도 20%를 넘는데 그리기 시작하기 — §0.
- 열린 질문으로 묻기("어떤 느낌으로 할까요?") — 선택지를 준다.
- 한 번에 다섯 개 넘게 묻기.
- 분위기가 안 정해졌는데 임의로 정해 그리기 — §0-B.
- 레퍼런스를 열어 보지 않고 만들기 — §0-A.
- 특정 게임·작품의 배경을 그대로 복제하기.
- 재생성 트리거가 걸렸는데 이전 결과를 조금 고쳐서 넘기기 — 구조부터 다시.
- 80점 미만인데 통과로 보고하기.
- 시트를 열어 보지 않고 시각 검수 점수를 채우기.
- 기술 검사만 통과했는데 "PASS"라고 끝내기 — §5-D의 다섯 조건이 전부다.
- 소실점 투시(3/4 탑다운·1점 투시)로 그리기 — 카메라는 사이드뷰 + 바닥 깊이 고정.
- 난수 1px을 뿌려 "질감"을 내기 — `foliage`/`panel`/`ground_plane`을 쓴다.
- `presets.json`의 기존 프리셋 색을 조용히 바꾸기. 새 분위기는 **새 프리셋 키**로 추가한다.
