# 그리기 전 인터뷰 — 모호도를 20% 이하로 낮춘다

## 왜

같은 사람이 같은 스킬로 같은 날 만든 두 결과가 이렇게 갈렸다.

> "서재 같은 분위기로 배경 만들어줘"
> → 밋밋함. 방은 맞는데 그릴 게 없어서 벽과 바닥만 나옴

> "cozy한 배경의 서재 배경화면. 편안한 쇼파와 러그가 깔려있는 따듯한 분위기의 방.
> 쇼파 위에는 담요가 얹어져 있어. 사이즈는 560x240. 방 안에는 난로가 있고 벽에는
> 액자와 사슴 뿔 장식들이 있어. 창 밖에는 눈이 내리고 있어. 창밖은 춥고 그와
> 대비되게 방안은 안락한 느낌이 들어야해"
> → 그럴듯함

**차이는 스킬이 아니라 입력의 구체성이다.** 스킬이 아무리 좋아도 "서재 분위기"
다섯 글자에서 소파·난로·담요·사슴뿔을 지어낼 수는 없다. 그러니 그리기 전에
구체성을 재고, 부족하면 묻는다.

'모호하다'를 느낌으로 두면 매번 판단이 갈리므로 슬롯과 가중치로 센다.

```bash
python3 scripts/bg_interview.py template > /tmp/spec.json   # 빈 명세
# 사용자 요청에서 읽어낸 것을 채운다 (추측한 건 assumed에)
python3 scripts/bg_interview.py score /tmp/spec.json         # 모호도
python3 scripts/bg_interview.py next  /tmp/spec.json         # 다음에 물을 것
python3 scripts/bg_interview.py brief /tmp/spec.json         # 확인용 브리프
```

위 두 요청을 이 표로 채점하면 **88%** 와 **6%** 가 나온다. 체감과 맞는다.

## 슬롯과 가중치

| 슬롯 | 가중치 | 왜 이 무게인가 |
| --- | --- | --- |
| 주요 오브젝트 (3개 이상) | 14 | 화면을 채우는 건 분위기 형용사가 아니라 물건이다 |
| 공간 종류 | 10 | 없으면 시작 자체가 안 된다 |
| 공간 구조 | 10 | 레이아웃을 정한다. 나중에 바꾸면 전부 다시 그린다 |
| 캔버스 크기 | 8 | 구도 상수가 전부 여기 비례한다 |
| 배치와 관계 | 8 | 목록만 있고 배치가 없으면 나열이 된다 |
| 조명과 광원 | 8 | 명암 설계의 근거. 없으면 평평해진다 |
| 색·톤 방향 | 8 | 팔레트 선택 / 새 프리셋 생성의 입력 |
| **움직이는 요소** | **8** | **차단.** 기본 산출물은 정지 한 장이다 |
| 대비 구조 | 6 | 좋은 배경은 대개 대비 하나를 축으로 삼는다 |
| **변형 개수** | **6** | **차단.** 2본 이상이면 프리셋을 파생시켜야 한다 |
| **노출·톤 강도** | **6** | **차단.** 색이 아니라 밝기다 |
| 캐릭터 자리 | 5 | petAnchor 위치 |
| 시간대·날씨 | 3 | 없어도 기본값으로 진행 가능 |

## 차단 슬롯 — 모호도가 통과해도 진행하지 않는다

굵게 표시한 셋은 **그림의 디테일이 아니라 무엇을 굽는지**를 정한다. 나머지 슬롯은
비어 있어도 그림 한 구석이 덜 구체적일 뿐이지만, 이 셋이 뒤집히면 산출물 전체를
다시 굽는다 — 프레임 시퀀스, 프리셋 파생, 팔레트 명도 재배치.

실제로 그렇게 됐다(2026-09-03 펫룸 배경). 모호도 0%로 진행했는데 사용자가
"화면이 움직이면 좋겠다", "낮·밤 두 본", "너무 밝아서 날아간다"를 차례로 요구했고,
그때마다 배경 두 장과 프레임 24장을 다시 구웠다. 그 명세를 지금 슬롯표로 다시
채점하면 정확히 이 셋이 비어 있다.

**그래서 모호도가 20% 이하라도 이 셋이 비어 있으면 `판정: 아직 묻는다`가 나온다.**
`bg_interview.py next` 가 다른 무엇보다 먼저 이 셋을 내놓는다.

기본값 자체는 싸다(움직임 없음 / 1본 / 중간). 비싼 건 나중에 뒤집히는 것이므로,
물을 수 없으면 **기본값을 골라 `assumed` 에 적는다** — 그러면 차단이 풀린다.

## 어떻게 묻나

**한 번에 3~4개까지, 가중치 큰 것부터.** 열 개를 한꺼번에 물으면 취조가 된다.
`bg_interview.py next`가 순서를 정해 준다.

**선택지를 준다.** "어떤 오브젝트를 넣을까요?"라고 열린 질문을 던지면 사용자가
다시 모호하게 답한다. 공간 종류를 알면 그 공간에 있을 법한 것들을 **먼저 제안**한다.

> 서재라면 — 소파·안락의자 / 책장·책상 / 난로·양탄자 / 창과 커튼
> 중 무엇을 넣을까요? (복수 선택, 없는 건 직접 적어 주셔도 됩니다)

**추론할 수 있는 건 묻지 않는다.** "실내 서재"라고 했으면 공간 구조는 '실내 정면'
이고, 크기는 이 프로젝트 기본값(560x240)을 제안하면 된다. 이미 답한 걸 다시 묻지
않는다.

**이미 20% 이하면 묻지 않고 그린다.** 인터뷰는 목적이 아니라 수단이다.

## 브리프로 확인받는다

슬롯이 차면 `bg_interview.py brief`로 문장을 만들어 **그리기 전에 한 번 보여준다.**
사용자가 쓴 좋은 프롬프트가 사실 이 브리프와 같은 형태다 — 인터뷰의 결과물은
질문 목록이 아니라 **그 좋은 프롬프트를 대신 써 주는 것**이다.

## 물을 수 없을 때

무인 실행이거나 사용자가 "알아서 해줘"라고 하면 기본값으로 채우되,
**채운 것을 `assumed`에 적고 결과 보고에 밝힌다.** 조용히 정하면 나중에
"내가 원한 게 아니다"가 되고, 그때는 이미 다 그린 뒤다.

기본값: 크기 560x240 / 캐릭터 자리 중앙 바닥 / 시간대 낮 / 대비는 공간 종류에서
자연스러운 축(실내면 안팎, 야외면 원경-전경) / 움직임 없음 / 1본 / 노출 중간.

차단 슬롯(움직임·변형·노출)은 기본값으로 채우더라도 **반드시 `assumed` 에 적는다.**
적지 않으면 `score` 가 계속 차단한다 — 조용히 정해 놓고 나중에 뒤집히는 것이 이
셋에서는 가장 비싸기 때문이다.
