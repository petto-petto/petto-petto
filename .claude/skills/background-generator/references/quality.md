# 배경 정량 성공 기준

"더 분위기 있게", "투시를 넣어서", "명암을 줘서"는 지침이 아니다. 실제로 실패하는
지점은 넷이고, 넷 다 숫자로 잡힌다. 이 문서는 그 숫자와 **숫자의 출처**를 적는다.

기준을 낮춰서 통과시키지 않는다. 낮추는 순간 이 표 전체가 장식이 된다.
기준을 바꿔야 한다고 판단되면 **왜 그 값이어야 하는지 실측을 다시 하고**
이 문서를 함께 고친다.

## 0. 캘리브레이션 방법

`background_image_reference/` 3장을 이렇게 처리해 실측했다.

```
280x120 축소(LANCZOS) -> 24색 medianCut 양자화 -> 3x3 최빈값 필터 2회
```

마지막 최빈값 필터가 핵심이다. 이걸 안 하면 축소 과정에서 생긴 1px 노이즈가
엣지로 잡혀 레퍼런스가 79%까지 나온다. 두 번 돌리면 디더/노이즈가 뭉개지고
**구조적인 엣지**(형태의 경계)만 남는다. 산출물도 같은 처리를 거쳐 비교한다.

## 1. 실측표

| 지표 | 레퍼런스 3장 | 개선 전 산출물 | 개선 후 산출물 | 채택 기준 |
| --- | --- | --- | --- | --- |
| 총 색 수 | 24(양자화 고정) | 21 / 21 / 23 | 30 / 30 / 33 | **24~48** |
| top1 색 점유 | 8.3 / 19.4 / 8.9% | 23.4 / 32.0 / 28.8% | 16.2 / 21.6 / 17.0% | **<= 25%** |
| 최대 단색 연결영역 | 1.7 / 16.8 / 5.5% | 19.3 / 20.7 / 4.1% | 13.7 / 14.9 / 12.8% | **<= 16%** |
| 구조적 엣지 밀도 | 42.4 / 36.2 / 33.7% | 10.0 / 9.5 / 16.8% | 31.0 / 24.6 / 21.5% | **>= 15%** |
| 명도 10구간 사용 | 10 / 9 / 7 | 7 / 5 / 4 | 9 / 8 / 7 | **>= 7** |

산출물 열은 forest / sky / interior 순, 280x120 기준이다. 다른 크기에서의
동작은 §5.

개선 전 산출물이 "평평하다"는 인상의 정체가 이 표다. 구조적 엣지 10%는
레퍼런스의 1/4이고, 지면 구간만 보면 4~7%로 사실상 단색 슬래브였다.

**엣지 하한을 레퍼런스(34~42%)가 아니라 15%로 잡은 이유**: 레퍼런스는 축소된
회화/스크린샷이라 손으로 찍은 도트보다 구조적 밀도가 원래 높다. 도달 불가능한
값을 하한으로 두면 게이트가 아니라 벽이 된다. 15%는 "지면이 단색 슬래브면
반드시 걸리고, 성실히 그리면 통과하는" 지점으로 잡았다(실측 산출물 21~31%).

## 2. 평탄함 — 4개 축

| 게이트 | 기준 | 무엇을 막나 |
| --- | --- | --- |
| 총 색 수 | 24~48 | **하한도 게이트다.** 20색 이하는 예외 없이 평평했다 |
| 레이어당 색 수 | 야외 6~16 / 실내 6~22 | 한 레이어가 전부를 짊어지는 것 |
| top1 색 점유 | <= 25% | 한 색이 화면 1/4을 넘으면 평평하게 읽힌다 |
| 최대 단색 연결영역 | <= 16% | 하늘·지면이 통짜 한 덩어리인 것 |
| 구조적 엣지 밀도 | >= 15% | 형태 경계 자체가 없는 것 |
| 세로 4구간 분포 | 수평선 아래는 각각 >= 전체평균 x0.45 | 디테일이 한 띠에만 몰리는 것 |
| 하늘 구간 | >= 2% | 완전히 빈 하늘(구름·광선 하나는 있어야) |
| 가로 4구간 | 각각 >= 전체평균 x0.55 | 좌우 한쪽만 그리는 것 |

**색 수 하한만으로는 부족하다** — 안 쓰이는 색을 1픽셀씩 뿌려도 통과하기 때문에
`램프 단계 사용` 게이트를 같이 둔다: 면적 3% 이상 쓰는 램프는 **실제로 3단 이상**
써야 한다.

## 3. 명암 — 3톤 + 광원 일관성

| 게이트 | 기준 | 근거 |
| --- | --- | --- |
| 명도 10구간 사용 | >= 7구간(각 2% 이상) | 레퍼런스 7~10. 히스토그램이 뭉치면 안개 낀 사진처럼 읽힌다 |
| 매스 3톤 사용 | 200px 이상 매스의 **80% 이상**이 3단 이상 | 덩어리가 단색이면 형태가 안 선다 |
| 광원 좌상단 일관성 | 매스의 **75% 이상**이 윗면 > 아랫면 밝기 | 캐릭터 스킬과 같은 광원 규칙 |

**'매스'의 정의**: 합성본에서 **같은 램프에 속하는 픽셀들의 4-이웃 연결 성분**.
색이 아니라 램프로 묶기 때문에, 3톤으로 칠해진 나무 한 그루가 3개 매스로
쪼개지지 않고 하나로 잡힌다.

**광원 검사를 '윗면 vs 아랫면 밝기'로 재는 이유** (중요):
- 무게중심(밝은 픽셀 중심 vs 어두운 픽셀 중심)으로 재면 **잎덩어리에서 항상 0**이
  나온다. 로브가 반복되면 좌상단 하이라이트와 우하단 그림자가 서로 상쇄된다.
- 대각 비대칭(p vs p+(1,1))으로 재도 **겹친 로브에서 무너진다**. 앞 로브의
  하이라이트가 뒤 로브의 그림자 바로 옆에 붙어 국소적으로 뒤집힌 쌍을 만든다.
- 실루엣의 위/아래 경계만 보면 이 상쇄가 일어나지 않는다. 실제로 눈이 읽는 것도
  덩어리의 윗면/아랫면 밝기다.

**배경면은 광원 검사에서 제외한다.** 화면 좌우 끝에 모두 닿는 매스(지면·벽·하늘)는
'형태'가 아니라 면이다. 이런 면의 명도 기울기는 광원이 아니라 **깊이**를 뜻하고
(먼 쪽이 밝다), 그림자 띠가 얹히면 위가 어두운 게 정상이다. 이 면의 원근은
`지면 압축` 게이트가 따로 본다.

## 4. 투시 — 깊이 단서 6종

카메라는 **사이드뷰 + 바닥 깊이**다. 소실점은 없다. 깊이는 여섯 가지 단서로
만들고, **야외는 6종 중 4개, 실내는 (대기원근이 없어) 5종 중 3개** 이상을
실측으로 만족해야 한다.

| # | 단서 | 어떻게 재나 | 어떻게 만드나 |
| --- | --- | --- | --- |
| 1 | 명도 계단 | 각 레이어가 바로 뒤와 평균 명도차 >= 0.08 | 레이어마다 램프 인덱스를 벌린다 |
| 2 | 겹침(occlusion) | 앞 레이어가 뒤 레이어 위에 5% 이상 겹침 | `scatter_depth`가 y 순으로 그린다 |
| 3 | 대기 원근(야외) | 뒤 레이어일수록 하늘색과 가깝다 | 뒤로 갈수록 램프를 하늘 쪽으로 |
| 4 | 크기 기울기 | `scatter_depth`의 scale 범위 또는 stamp scale 2종 이상 | 뒤 요소를 작게, 앞 요소를 크게 |
| 5 | 지면 압축 | 지면 밴드 **위쪽 1/3 엣지 밀도 > 아래쪽 1/3 x1.15** | `ground_plane`이 셀·결 간격을 위로 갈수록 좁힌다 |
| 6 | 접지 그림자 | 지면 상단에서 지면 평균보다 0.10 어두운 픽셀 >= 5% | `contact_shadow` + 수목 그림자 띠 |

**5번 방향에 주의**: 멀수록 같은 픽셀 수에 더 많은 것이 들어가므로 **먼 쪽(위)
엣지 밀도가 더 높다.** 반대로 나오면 지면이 아래로 갈수록 잘게 쪼개진 것이라
원근이 뒤집힌 것이다. (구현 중 이 부호를 반대로 뒀다가 실측에서 잡혔다.)

**3번은 '하늘색과의 거리'로 잰다.** 채도·명도 단조성으로 재면 지면 재질이 바뀌는
순간(초록 -> 모래) 정상 배경이 FAIL 난다 — `sky` 프리셋에서 실제로 오탐이 났다.

## 5. 캔버스 크기 — 고정이 아니다

크기는 요청마다 받는다(`bg_scaffold.py --size WxH`, 기본 280x120). 기준값은
**기준 높이 120px에서 캘리브레이션**했고, 실제 캔버스에서는 이렇게 다룬다.

| 종류 | 처리 |
| --- | --- |
| 비율 지표(top1, 최대블롭, 색 수, 명도구간, 구조엣지, 깊이단서) | 그대로 쓴다 — 크기와 무관 |
| 절대 px(groundTop 범위, 지면 밴드 높이, 접지 그림자 표본 창) | 높이 비례로 스케일 |
| 주요 매스 하한(200px) | 면적이므로 **높이 비율의 제곱**으로 스케일 |
| 구도 상수(수평선·수목선·기둥 폭·셀 폭) | `bgcore.geom()`이 전부 비례 계산 |
| 스탬프 | **정수배 확대만** (도트가 깨진다). 애매한 배율의 오차는 뿌리는 개수로 메운다 |

### 왜 "요소를 같이 키우는가"가 전부인가 (실측)

같은 그림을 확대하면 구조적 엣지가 이렇게 움직인다.

| | 구조적 엣지 |
| --- | --- |
| 원본 280x120 | 23.6% |
| 2배 확대 560x240 | 22.3% |
| 3배 확대 840x360 | 18.4% |
| **요소 크기 그대로, 캔버스만 2배** | **12.2% (하한 미달)** |

확대는 완만히 떨어져 하한을 지키지만, **큰 캔버스에 원래 크기의 요소를 그대로
심으면 절반으로 떨어져 바로 걸린다.** 큰 배경을 만들 때 스탬프 `scale`을 올리지
않거나 뿌리는 개수를 안 늘리면 이 실패가 난다.

### 검증한 구간

3프리셋 전부 게이트 통과를 확인한 크기다.

```
160x72  200x86  280x120  360x160  420x180  480x120
560x240  700x300  840x360  200x200  240x240  320x320
```

종횡비 1:1(정사각)부터 4:1(480x120)까지 포함한다. `bgcore.SAFE_H`가 정의하는
**권장 높이는 80~360px**이고, 그 밖이면 `bg_scaffold.py`가 경고를 찍고 진행한다
(1024x440에서는 지면 압축 1개가 걸렸다 — 게이트가 못 미더운 게 아니라
그 크기에서 초안 파라미터가 안 맞는 것이니 눈으로 확인하고 손보면 된다).
**96x64 미만은 거부한다** — 4레이어와 지면 밴드가 물리적으로 안 들어간다.

## 6. 펫 가독성은 게이트가 아니다 (2026-08-29 제거)

한동안 펫 박스의 국소대비·색 수·`#2C2438` 대비 명암비를 게이트로 뒀고, 그걸
통과시키려고 펫 자리에 빈터(`clearing`)를 까는 게 기본 초안이었다.

**게임 쪽에서 펫 주변에 발광 이펙트를 넣기로 하면서 전부 뺐다.** 배경이 캐릭터
가독성을 책임질 이유가 없어졌고, 빈터를 빼면서 배경이 더 채워졌다. `petAnchor`는
좌표 정보로 메타에 남는다 — 런타임이 펫과 발광을 어디에 놓을지 알아야 한다.

되돌릴 일이 생기면(발광 없는 화면이 생기면) 필요한 건 셋이다: 펫 박스
국소대비 std(L) <= 0.10, 색 <= 6, WCAG 명암비 >= 3.0:1. 그리고 `clearing` op은
지우지 않고 남겨 뒀다.

## 6-B. 레이아웃별 게이트 차이

| 게이트 | ground | canopy |
| --- | --- | --- |
| 지면 압축 · 지면 밴드 높이 · groundTop 범위 | 적용 | `groundTop`은 '펫이 서는 발판'을 가리킨다 |
| 크기 기울기 | 스탬프 scale 2종 또는 scatter_depth scale 범위 | **레이어별 줄기 폭 증가**로도 성립 |
| 광원 일관성 | 8x8 창의 좌상단/우하단 비교 | 동일. 세로 관통 매스도 같은 식으로 잡힌다 |

## 7. 이 기준을 만들면서 실제로 잡힌 결함

게이트가 장식이 아니라는 증거이자, 같은 실수를 반복하지 않기 위한 기록이다.

1. **`interior` 프리셋의 `near.4`와 `far.2`가 같은 `#7C4327`이었다.** 색 -> 램프
   역맵이 엉켜 far 매스가 단색으로 잡혔다. 지금은 `bgcore.validate_preset`이
   프리셋 로드 시점에 램프 간 중복 hex를 막는다.
2. **지면 압축 게이트의 부등호 방향이 반대였다.** 원근을 제대로 그린 산출물이
   FAIL 났다.
3. **광원 검사를 무게중심으로 재서 잎덩어리가 전부 0%로 나왔다.** 위 §3 참고.
4. **밝은 하늘 프리셋에서 `far.1`이 하늘과 명도가 같아 원경 실루엣이 사라졌다.**
   `레이어 뒤와 명도차` 게이트가 dL=0.000으로 잡았다.
5. **고립픽셀을 4-이웃으로 재서 정상 bayer 디더가 19.8%로 잡혔다.** 8-이웃으로
   바꾸면 체커는 대각 이웃이 같아 빠진다. 그래도 1px 그라데이션 디더가 6%를
   넘어서, `vgradient`에 2x2 블록 디더(`block`)를 넣었다.
