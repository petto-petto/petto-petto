# 게이트가 서로 충돌할 때

`bg_check.py`의 지표 몇 쌍은 반대 방향으로 당긴다. 한쪽을 올리면 다른 쪽이
떨어지므로, 아래 규칙대로 구현한다. **기준값을 낮춰서 푸는 것은 금지다.**

| 충돌하는 쌍 | 구현 규칙 |
| --- | --- |
| `near 명도차` ↔ `지면 압축` | near는 전면 폭 띠가 아니라 **전경 오브젝트**로 채운다 |
| `매스 3톤` ↔ `near 명도차` | 3톤은 **스탬프 legend 안에서** 만든다 |
| `명도 10구간` ↔ 어두운 실내 톤 | 밝은 **목재 몰딩**으로 중간 밝기 면적을 확보한다 |
| `광원 일관성` ↔ 반복 면(벽돌·유리·널판) | 면은 **켜(course)** 로 쌓는다 |
| `구조 엣지` ↔ `지면 압축` | 엣지는 지면 **위쪽 1/3**에 몰아 둔다 |
| `원경 잎덩어리 윗변` ↔ `하늘의 광원 판정` | 원경에는 `crest`를 주지 않는다 — 6번 |

## 1. near 레이어는 전경 오브젝트로 채운다

- 실내 near에 **가구 하나를 올린다.** 쇼파·안락의자·테이블 중 하나면 된다.
- 그 가구의 x를 `petAnchor` 밖 **그리고** 중앙 세로 띠(x 38~62%) 밖에 둔다.
  이러면 활용성 10점(전경이 캐릭터 자리를 비움 / 중앙 시야 개방)이 유지된다.
- 천장·바닥 그늘 띠는 보조로만 쓴다. **띠만으로 채우면 명도차 중앙값이 0.08
  아래로 내려간다.**
- 띠는 **밝은 면 위에만** 깐다(마루·징두리). 어두운 벽 위의 띠는 near.0을 써도
  차가 0.076밖에 안 난다.

## 2. 3톤은 스탬프 legend 안에서 만든다

- 테두리형 스탬프(프레임·상자·책장·가구)는 legend에 세 단을 직접 넣는다:
  좌상단 밝은 단 / 본체 / 우하단 어두운 단.
- **레이어에 중간 톤을 넓게 깔아서 3톤을 맞추지 않는다.** near.2를 면으로 깔면
  그 면적이 명도차 중앙값을 끌어내려 `near 명도차`가 깨진다.
- 화면 좌우 끝에 모두 닿는 매스는 '배경면'으로 분류돼 3톤·광원 검사에서 빠진다.
  전면 폭 띠로는 3톤 비율을 올릴 수 없다.

## 3. 지면 아래 1/3을 비운다

- 가구·소품의 접지 y를 **지면 밴드의 위 2/3 안**에 둔다. `contact_shadow`도 같이.
- `ground_plane`은 `cell: [4, 28]`, `furrow0: 1`로 위쪽을 촘촘하게 만든다.
- 아래쪽 그늘 띠가 필요하면 `rect`(단색)로 만든다. **`vgradient` 디더는 엣지
  밀도를 크게 올려 압축 판정을 뒤집는다.**
- 560x240 실측: 접지 y를 210~220으로 올리고 아래 12행을 비우면 먼쪽 30.4% /
  가까운쪽 14.5%로 통과한다.

## 4. 반복 면은 켜로 쌓는다

벽돌·널판·창유리처럼 같은 무늬가 반복되는 면은 한 켜를 이 순서로 만든다.

```
줄눈 / 이음매  (어두운 단)
윗면          (밝은 단)     <- 바로 아래 행
본체          (기본 단)
```

`panel` op이 이 구조다. 손으로 만드는 스탬프도 같게 맞춘다. 광원 검사는 매스
안 8x8 창에서 좌상단이 밝은지를 보므로, 창을 어디에 놓아도 같은 결과가 나온다.
창밖 풍경처럼 아래가 밝을 수밖에 없는 매스는 1~2개까지 비율로 흡수된다.

## 5. 중간 밝기는 목재 몰딩으로 확보한다

어두운 난색 실내는 명도 히스토그램이 아래 4구간에 뭉쳐 `명도 10구간 >= 7`에
걸린다. 다음 두 줄로 해결한다.

```json
{"op": "rect", "x": 0, "y": <레일 y>,   "w": W, "h": 4, "color": "wood.3"}
{"op": "rect", "x": 0, "y": <걸레받이 y>, "w": W, "h": 6, "color": "wood.2"}
```

레일(chair rail) 3~4px + 걸레받이 5~6px이면 L 0.4~0.6 구간이 채워진다.
징두리를 어둡게 잡을 때는 이 두 줄을 반드시 같이 넣는다.


## 6. 원경 잎덩어리의 윗변은 하늘의 아랫경계다

전경 오브젝트가 화면 좌우 끝을 막으면 하늘은 '배경면'(좌우 끝에 모두 닿는 면)으로
분류되지 못해 **광원 검사 대상이 된다.** 그런데 안개 낀 하늘은 세로 그라데이션뿐이라
좌우 방향이 없다. 창 하나 안에서 명도차가 0에 가까우면 판정이 디더 패턴에 좌우돼
28~57% 사이를 요동한다.

하늘이 **한 덩어리**로 남아 있으면 대개 균일 구간으로 잡혀 판정에서 빠진다. 조각나는
순간 각 조각이 따로 측정된다. 그 조각 모양을 정하는 것이 원경 잎덩어리의 윗변이다.

- **원경 `foliage`에는 `crest`를 주지 않는다.** 중경부터 켠다 — 화면에서 실제로 크게
  보이는 것도 중경 잎벽이다.
- 하늘에 `glow`를 얹어 방향을 만들려 하지 않는다. 램프가 달라 밝은 부분이 하늘 매스에서
  빠져나가 판정이 오히려 뒤집힌다(실측 13%).
- 하늘 그라데이션을 세우지도 않는다. 균일해서 빠지던 조각이 판정 대상이 된다(실측 28%).

**opt-in 파라미터를 새로 만들 때는 꺼진 경로가 난수를 한 번도 더 쓰지 않게 한다.**
소비 순서가 달라지면 같은 seed로도 배치가 통째로 바뀌어, 안 건드린 레이어까지 움직인다.
