# 레퍼런스 분석 — 그리기 전에 반드시 하는 단계

레퍼런스를 "숲", "도트 스타일"처럼 표면적으로만 받으면 **공간 구조가 통째로
빠진다.** 실제로 그렇게 만들었다가 반려됐다: 다층 수직 정글 레퍼런스를 받고
평평한 가로 숲을 만들었고, 채점해 보니 핵심 요소 1/7 · 71점이었다.

그래서 생성 전에 다섯 축을 **눈으로 보고** 짧게 정리한다. 추측하지 않는다 —
이미지를 실제로 열어서 본다.

## 다섯 축

| 축 | 무엇을 적나 | 왜 |
| --- | --- | --- |
| **1. 공간 구조** | 가로형 / 세로형 / 다층형. 지평선이 있나, 층이 몇 개인가 | 이걸 놓치면 나머지를 다 맞춰도 다른 그림이 된다 |
| **2. 주 피사체와 개수** | 예: 거대 고목 5~6, 이끼 발판 4~5층, 로프 다리 4, 사다리 1 | 개수까지 적어야 "몇 개 반영했나"를 셀 수 있다 |
| **3. 전경·중경·원경** | 각 층에 무엇이 있고 어떻게 구분되나 | 레이어 배정의 근거 |
| **4. 조명과 색감** | 광원 위치, 밝은 영역, 안개, 그림자의 색조, 주요 색 계열 | 팔레트와 glow 배치의 근거 |
| **5. 플레이 여백** | 캐릭터가 설 자리, 발판 가독성, 열린 시야 구간 | 게임 배경이라 반드시 본다 |

## 재해석 원칙

레퍼런스는 **분위기와 공간 구성**을 참고하는 대상이지 베끼는 대상이 아니다.
특정 게임이나 작품의 배경을 그대로 복제하지 않는다. 구체적으로:

- 공간 구조·요소 종류·조명 방향·색 계열은 가져온다.
- 개별 오브젝트의 형태, 배치 좌표, 실루엣은 새로 구성한다.
- 원작을 알아볼 수 있는 고유 형상(특정 캐릭터, 로고, 특정 건축물)은 넣지 않는다.

## 산출물 — `elements.json`

분석 결과를 기계가 셀 수 있는 형태로 남긴다. `bg_score.py`가 이걸로
"핵심 요소가 실제로 씬에 있는가"를 검증한다.

```json
{
  "reference": "background_image_reference/xxxx.jpg",
  "structure": "vertical",
  "elements": [
    {"name": "화면을 세로로 관통하는 거대 고목", "op": "tree_column", "min": 6},
    {"name": "이끼 낀 나뭇가지 발판(다층)",     "op": "branch_platform", "min": 4},
    {"name": "로프 다리",                      "op": "rope_bridge", "min": 2},
    {"name": "사다리",                         "op": "ladder", "min": 1},
    {"name": "역광 안개 개방부",               "op": "glow", "min": 2},
    {"name": "늘어진 덩굴",                    "op": "stamp:vine", "min": 3},
    {"name": "잎 덩어리 군락",                 "op": "foliage", "min": 6}
  ]
}
```

`structure`는 `vertical` / `layered` / `horizontal`. 앞의 둘인데 `ground`
레이아웃으로 만들면 재생성 트리거 2번에 걸린다.

**요소는 5개 이상 뽑는다.** 4개 이하만 반영되면 트리거 1번이다.

`references/example_elements.json`이 실제 예시다(정글 캐노피 레퍼런스 분석 결과).
