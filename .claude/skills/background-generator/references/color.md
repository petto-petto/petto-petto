# 색상 및 명도 지침

게임 배경은 뮤트하거나 회색기 많은 팔레트보다 **생동감 있고 선명한 트루컬러**를
우선한다. 다만 화면 전체가 같은 강도로 쨍하면 플레이 요소가 묻히므로 레이어별로
강도를 나눈다.

## 레이어별 강도

| 레이어 | 채도 | 명암 대비 | 디테일 |
| --- | --- | --- | --- |
| 전경 | 가장 높게 | 가장 강하게 | 형태가 선명하게 |
| 중경 | 한 단 낮게 | 중간 | 한 단 낮게 |
| 원경 | 낮게 | 낮게 (안개색) | 실루엣 위주 |

## 규칙

- **단일 초록 금지.** 주요 녹색 계열은 황록·청록·짙은 녹색 등 여러 색조로 구성한다.
  `jungle` 프리셋이 그 예다 — `mid`는 올리브~황록, `leaf`는 선명한 초록,
  `near`는 짙은 녹색이다.
- **`accent`는 화면을 채우는 색의 보색 자리다.** 위의 '여러 색조'는 초록 안에서의
  변주이고, 그것만으로는 화면이 단색 인상을 벗지 못한다. 초록 숲이면 accent는
  초록이면 안 된다.
- **그림자는 검정이 아니라 색조 있는 짙은 색.** 램프의 0단이 그 역할을 한다.
  램프를 새로 만들 때 0단을 회색이나 검정으로 두지 않는다.
- **빛이 닿는 영역에는 밝은 하이라이트 색.** `light` 램프와 `glow` op.
- **중앙 플레이 영역**(캐릭터·적·아이템·UI가 놓일 자리)은 배경보다 명도·채도
  대비가 지나치게 높지 않게 조절한다. 채점의 '중앙 대비 std ≤ 0.20'이 이 기준이다.

## 채점 (15점)

`bg_score.py`가 다섯 항목을 각 3점으로 본다. 모두 충족해야 만점이다.

| 항목 | 기준 |
| --- | --- |
| 뮤트/무채색 아님 | 화면 평균 채도 ≥ 30% |
| 레이어 간 차이 | 레이어 평균 명도 또는 채도의 최대-최소 ≥ 0.15 |
| 하이라이트·그림자 구분 | L ≥ 0.75 영역 ≥ 2% **그리고** L ≤ 0.25 영역 ≥ 2% |
| 색조 다양성 | 채도 15% 이상 화소의 색상환 20도 구간이 3개 이상(각 1% 이상) |
| 과대비/형광 아님 | 채도 90% 이상 화소 ≤ 15%, 중앙 플레이 영역 명도 std ≤ 0.20 |


## accent 대비 — 프리셋을 고를 때 확인한다

```bash
python3 scripts/bg_palette.py show --preset <이름>   # 'accent 대비' 줄을 본다
```

매스 램프(`mid`·`leaf`·`near`)의 평균 색상과 `accent` 평균 색상의 원형 거리다.
**60도 미만이면 그 팔레트로는 색조 대비를 만들 수 없다.**

실측(2026-09-03):

| 프리셋 | 거리 | |
| --- | --- | --- |
| `forest` | 32도 | 대비 불가 |
| `sky` | 43도 | 대비 불가 |
| `interior` | 8도 | 대비 불가 |
| `jungle` | 60도 | 경계 |
| `cozy_study` | 173도 | OK |

**초기 프리셋 다섯 중 셋이 accent로 대비를 만들지 못한다.** 이 셋을 쓸 때는 색조가
아니라 **톤·명암**으로 대비 축을 잡거나, accent 램프를 다시 잡은 새 프리셋을 만든다.
`jungle`으로 숲을 그렸을 때 "전부 초록으로 보인다"는 지적이 나온 원인이 이것이다 —
8램프 중 6이 초록 계열이고 대비를 담당할 accent마저 청록이었다.

### accent는 색상이 흐르는 램프로 써도 된다

한 색의 명암 5단으로 두면 그 램프를 쓰는 오브젝트가 전부 같은 색이 된다. **명도
사다리만 지키면 단마다 색상을 달리 걸 수 있다** — 보라 → 자홍 → 진홍 → 주홍 → 호박.
`scatter_depth`의 `shade`가 깊이에 따라 단을 밀어 주므로 같은 스탬프를 뿌려도 무리가
저절로 여러 색으로 섞인다. `petroom_grove`의 버섯이 이 방식이다.

## 프리셋 파생 — 기존 팔레트를 태운다

```bash
python3 scripts/bg_preset_new.py --name petroom_grove --from jungle --burn 0.7 \
    --label "펫룸 깊은 숲" --write
```

같은 색상 계열을 유지한 채 명도만 눌러 새 프리셋을 만든다. **기존 프리셋 색은
건드리지 않는다** — 다른 배경들이 쓰고 있다.

`--burn` 은 0(원본 그대로) ~ 1(가장 많이 탄다). 실측으로 `jungle` 기준 **0.5~0.7이
안전 구간**이고, 0.9는 레이어 분리가 깨진다. 도구가 쓰기 전에 예측해 알려 준다.

### 손으로 하면 반드시 밟는 함정 셋

이 셋 때문에 도구가 필요하다. 세 번 다 겪었다.

1. **HLS의 L만 내리면 옅은 색이 쨍해진다.** 채도가 그대로 남기 때문이다 — 안개
   하늘이 형광 초록이 된다. RGB를 통째로 곱해야 R:G:B 비가 유지된다.
2. **무채색은 명도를 내려도 회색이다.** `#FFFFFF` 는 채도가 0이라 물려받을 색이
   없다. 색이 실제로 있는 가장 가까운 단에서 색상을 가져오되, **L이 1.0이면
   재구성이 다시 흰색**이므로 천장 아래로 먼저 내려야 한다.
3. **균일하게 누르면 레이어 분리가 무너진다.** 명도차가 같은 비율로 줄어들어
   `bg_check` 의 '뒤와 명도차 0.10' 이 깨진다. 그렇다고 감마를 낮춰 그림자를
   벌리면 이번엔 최하 명도 구간이 비어 '명도 10구간' 이 깨진다 — **두 게이트가
   반대로 당긴다.** 램프마다 명도 밴드를 따로 잡고 깊이 사다리를 강제해야 둘 다
   만족한다.

## 하이라이트는 절대 밝기가 아니라 **동적 범위**로 본다

의도적으로 어둡게 태운 화면에 "L>=0.75 면적 2% 이상"을 요구하면 정상 결과가
감점된다. 실측에서 레퍼런스 3장이 4.1~34.9%로 제각각이었고, 승인된 어두운 배경
둘은 1.0%·1.3%였다 — 절대값은 주제에 따라 달라져 기준이 될 수 없다.

`bg_score.py`는 **상위 2% 밝기 - 하위 2% 밝기 >= 0.55**를 본다. "명암이 살아
있는가"를 재는 것이라 밝은 화면과 태운 화면에 같은 잣대가 된다. 실측: 레퍼런스
0.744 / 0.815 / 0.835, 승인된 배경 0.63 / 0.68.

## 채도가 낮은 게 정상인 주제 — `paletteMode: cool`

눈·동굴·석조 유적에 "뮤트 금지, 평균 채도 30%"를 그대로 들이대면 **정상 팔레트가
실패한다.** 설원을 형광 초록으로 칠할 수는 없다.

프리셋이 `"paletteMode": "cool"`을 선언하면 채도 하한이 18%로 내려간다. 대신
그런 화면은 채도가 아니라 **명도와 색조**로 살아나야 하므로 색조 계열 요구가
3 → 4개로 올라간다. 무채색으로 뭉개서 빠져나갈 수는 없다는 뜻이다.

`bg_preset_new.py`가 지형을 보고 자동으로 붙인다(snow/cave/ruins). 직접 만든
프리셋이라면 presets.json에 손으로 넣는다.
