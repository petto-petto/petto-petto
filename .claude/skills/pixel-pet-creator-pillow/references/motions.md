# 모션 스프라이트 (idle / click / attack)

스펙 §3-3이 정의하는 **단계당 필요 에셋**은 네 가지다.

| 항목 | 용도 | 규격 |
| --- | --- | --- |
| 정지 이미지 | 도감 카드·뽑기 연출 | 1장 (`_card.png`) |
| 대기(idle) 모션 | 오버레이·펫룸 상시 재생 | **4프레임** 루프 |
| 클릭 반응 모션 | 오버레이 클릭 시 랜덤 액션 | **2종** (`_click`, `_click2`) 각 4프레임 |
| 전투 모션 | 전투 화면 | 공격 1종 (`_attack`) **6프레임** |

프레임 수와 클릭 종수는 **등급과 무관하게 위 표대로** 고정이다. 등급 차이는
프레임 수가 아니라 정렬 후 차이 하한·이펙트·지연 부위 수로 낸다(`budget.py`).

## 물량 절감안 C (스펙 §3-6 권장안)

한 종의 세 단계를 모두 풀세트로 만들면 1종당 27프레임이 되어 MVP 20종 기준
과부하다. 스펙이 권장하는 절감안은 이렇다.

- **단계마다 새로 만드는 것**: 정지 이미지 + idle
- **최종 단계(Stage 3) 것을 공유하는 것**: click, attack

즉 Stage 1·2 폴더에는 `_card.png` / `_idle.png` / `_idle.json`만 두고, click·attack은
Stage 3 폴더의 것을 런타임이 참조한다. 사용자가 "전 단계 풀세트"를 명시하지
않았다면 이 방식을 제안하고 확인받는다. 무엇을 만들고 무엇을 공유했는지는
결과 보고에 반드시 적는다 — 나중에 "왜 stage1에 attack이 없지?"가 되지 않도록.

## 정렬 후 차이 — 프레임 수만 늘리면 걸린다

`motion_check.py`는 프레임을 최적 오프셋으로 **정렬한 뒤** 남는 차이만 센다. 스프라이트를
통째로 1px 민 프레임은 정렬하면 0%가 되므로, 프레임 수만 등급대로 채우고 내용은
전부 shift인 모션은 반드시 FAIL이 난다. (초기 3종 실측: EPIC·RARE의 idle이 정렬 후
0~2%였다. 프레임은 4장·3장이었는데 내용은 같은 그림을 민 것뿐이었다.)

| 정렬 후 최대 차이 | COMMON | RARE | EPIC |
| --- | --- | --- | --- |
| idle | 8% | 15% | 22% |
| click / attack | 10% | 18% | 25% |

올리는 방법은 **부위마다 다르게 움직이는 것** 하나뿐이다.

- 눈 감기 (2x3 눈 → 가로선 1줄): 32x32에서 약 1~2%
- 귀·뿔·꼬리를 몸통과 반대로 1px: 부위 크기만큼
- 액센트 픽셀(보석·발광) 위치 이동 + 밝기 톤 교체
- 입 벌리기, 갈기 끝 흔들기, 다리 교차
- 몸통을 1px 내리면서 **귀·꼬리 끝은 고정** — 눌리는 느낌이 나면서 정렬로 상쇄되지 않는다

마지막 항목이 요령이다. 전체를 같이 밀면 0%, 몸통만 밀고 끝을 고정하면 그 경계
픽셀이 전부 차이로 잡힌다. 같은 작업량으로 지표와 보기 좋음을 동시에 얻는다.

## 원칙 — 옮기지 말고 찌그러뜨린다

앞의 표(정렬 후 차이)가 무엇을 요구하는지 풀어 쓰면 이렇다. **스프라이트를 통째로
옮기기만 하면 정렬 후 차이가 0에 수렴한다.** 눈도 똑같이 읽는다 — 평행이동한 그림은
"그림이 움직였다"이지 "생물이 움직였다"가 아니다. 실제로 살아 있어 보이게 만드는
건 세 가지다.

1. **접지면을 고정한다.** 발이 닿는 아래 2~3행은 절대 움직이지 않는다. 발까지
   같이 움직이면 스스로 움직이는 게 아니라 누가 들었다 놨다 하는 것처럼 보인다.
   **이 하나가 나머지 둘을 합친 것보다 체감이 크다.**
2. **실루엣 크기를 바꾼다(스쿼시 & 스트레치).** 내려앉을 때 세로 1px 줄고 가로
   1px 늘어난다. 솟을 때 반대. 32px에서 1px는 3%라 충분히 읽히고, 정렬 후 차이가
   실제로 올라가는 것도 이 항목이다.
3. **부위를 한 박자 늦춘다(오버래핑 액션).** 꼬리·귀·날개는 몸통보다 1프레임 늦게
   따라오고, 몸이 멈춘 뒤에도 한 프레임 더 흔들린다. 꼬리가 큰 캐릭터일수록 여기서
   얻는 게 크다.

## scripts/motion_make.py 로 뽑는다

세 가지 역학은 캐릭터가 달라도 같아서, 프레임마다 손으로 그리지 않고 스크립트가
계산한다. 완성된 **카드 그리드 한 장**에서 파생시킨다.

```bash
python3 scripts/motion_make.py --grid /tmp/pet_012_s3.txt --motion attack \
  --anchor 3 --lag 24-30 --effect-at 8,26 --out-prefix /tmp/pet_012_s3_attack
```

| 인자 | 캐릭터마다 판단해서 넣는 값 |
| --- | --- |
| `--anchor N` | 아래 몇 행이 땅에 닿는 발인가 (보통 2~3) |
| `--lag X0-X1` | 한 박자 늦게 따라올 부위의 열 범위. 꼬리·귀·날개. 여러 번 지정 |
| `--effect-at X,Y` | 이펙트 기준점 — attack이면 발밑, click이면 머리 위 |

이펙트는 그리드에 이미 있는 색만 쓰므로 팔레트 예산이 흔들리지 않는다.
변형 뒤 외곽선이 벌어질 수 있어 자동으로 재봉합하지만, 결과가 어색하면 `--anchor`
를 바꾸거나 해당 프레임 그리드를 직접 손본다.

**만들고(make) 검사한다(check).** 뽑은 뒤 반드시 `motion_check.py` 로 정렬 후 차이가
등급 하한을 넘는지 확인한다. 스크립트가 "실루엣 변형" 표시를 한 번도 안 냈다면
그 애니메이션은 아직 평행이동이고, 검사에서 걸린다.

## 모션별 프레임 구성

등급과 무관하게 동일하다. 등급 차이는 프레임 수가 아니라 **정렬 후 차이 하한 +
이펙트 + 지연 부위 수**로 낸다(`budget.py`).

### idle — 4프레임 루프, fps 4~6

```
f0 중립 → f1 스쿼시(내려앉음) → f2 중립 → f3 스트레치(들림) + 눈 감기
```

숨 쉬는 리듬이다. 크게 움직이면 오버레이에서 산만하다.

### click — 4프레임, 1회 재생, fps 8~10, **전 등급 2종**

```
f0 중립 → f1 스트레치 + 눈 크게(움찔) → f2 스쿼시 + 이펙트 → f3 중립
```

2종은 **다른 감정**으로 만든다(놀람 / 기뻐서 폴짝). 같은 동작의 미세 변형 2종은
랜덤 재생에서 차이가 안 느껴져 만든 의미가 없다. 유저가 반복해서 누르는 자리라,
여기가 지루하면 펫 전체가 죽은 것으로 느껴진다.

### attack — 6프레임, 1회 재생, fps 10~12

```
f0 중립 → f1 예비(스쿼시) + 먼지 → f2 타격(스트레치) → f3 타격 유지 →
f4 착지(스쿼시) → f5 중립
```

**f2와 f3이 같은 포즈인 것은 의도**다. 타격 프레임을 두 장 연속으로 두면 그 순간이
두 배로 길어져 무게가 실린다(히트스톱). 메타에 프레임별 길이가 없어 프레임 복제로
흉내낸다. `motion_check.py` 에서 그 구간만 차이 1~2%로 찍히는 것도 정상이다.

예비동작(f1)이 없으면 타격이 안 읽힌다. 3박자를 지킨다.

### 마지막 프레임은 반드시 f0 과 같아야 한다

click·attack 은 1회 재생이고 끝나면 idle 로 돌아간다. 마지막 프레임이 다른 포즈면
재생이 끝나는 순간 툭 튄다. `audit.py` 가 잡는다.

## export

```
piskel export_sprite_sheet  projectId=<id>  columns=<프레임수>  scale=1
  outputPath=<stage 폴더>/pet_{petId}_s{stage}_{motion}.png
```

`columns`를 프레임 수와 같게 두면 가로 1행 시트가 나온다. 런타임 슬라이싱이
`frameIndex * frameWidth` 하나로 끝난다. **scale은 반드시 1** — 확대는 렌더러가
정수 배율 nearest-neighbor로 처리한다(스펙 §3-7).

## .json 메타

스펙 §3-7이 시트와 같은 경로의 JSON 메타를 요구한다. 시트만 내보내고 메타를
빠뜨리면 런타임이 프레임을 자를 수 없다.

`pet_{petId}_s{stage}_{motion}.json`:

```json
{
  "frameWidth": 32,
  "frameHeight": 32,
  "frameCount": 4,
  "columns": 4,
  "fps": 6,
  "loop": true
}
```

- `loop`: idle은 `true`, click/attack은 `false`
- `frameCount`는 실제 export한 프레임 수와 반드시 일치 — 어긋나면 마지막에 빈 칸이 재생된다
- **EPIC Stage 3는 `frameWidth`/`frameHeight`가 48**이다. 캔버스가 48이면 여기도 48로 쓸 것

## 카드 이미지

모션을 만들었더라도 카드는 별도로 내보낸다. 도감 카드는 정지 이미지 1장이다.

```
piskel export_png  projectId=<id>  frameIndex=0  scale=1
  outputPath=<stage 폴더>/pet_{petId}_s{stage}_card.png
```
